# NEW-PSI 21차 — PDF 저장 직전 이중 무결성 검증 및 실제 PDF 브라우저 회귀 (2026-11-01)

## 기준선
- 20차 PR #196, `main` `4ee383fb`: 원본과 출력 사본의 페이지별 대조 후 로컬 저장.
- 20차까지의 Vercel 운영 배포 확인 결과: Production READY 커밋은 17차 `090f5ddb`이고 18~20차는 빌드 빈도 제한으로 운영 미반영. 21차도 운영 배포는 별도 판정한다.

## 21차 수정
- `verifyPsiPreparedPdfIntegrity(prepared, originalFile)`: 최종 다운로드 직전에 **원본 File 바이트**와 **이미 검토·생성한 PDF Blob 바이트**를 다시 읽고 SHA-256을 산출한다.
- 두 바이트의 SHA-256이 검토 manifest에 기록된 원본 및 결과 해시와 모두 일치해야 한다. 원본·사본 해시가 같거나 필수 manifest 상태, 페이지 요약, PDF 크기/형식 또는 미승인 상태가 유효하지 않으면 저장을 차단한다.
- 두 파일이 검증에 실패하면 **PDF도 JSON도 저장하지 않는다**. 성공하면 원본 파일을 수정하지 않고, 생성한 동일한 최종 PDF Blob과 로컬 검토 JSON을 요청한다.
- 최종 비교 UI는 재렌더링 오류가 남아 있거나 페이지 표시가 완료되지 않은 상태에서 저장 버튼을 활성화하지 않는다.

## 자동 회귀
1. Vitest: 출력 PDF/원본 변경, 검토 누락, 악의적으로 '승인' 설정된 manifest, 일치하지 않는 해시 및 잘못된 페이지 요약이 저장을 차단하는지 검사한다. 성공 시 별도의 PDF와 JSON 저장 요청을 확인한다.
2. Chromium Playwright: Vite 로컬 페이지에서 **실제 구조(xref 및 trailer)를 가진 합성 PDF**를 동적으로 생성하고, PDF.js로 10페이지 파일 로드, 11페이지 거부, 렌더·불투명 검정 마스크, 좌표 정규화, 생성된 검정 사각형 PDF의 픽셀 검사 통과, 검은 영역이 없는 PDF 차단, 추출 텍스트 PDF 차단을 확인한다.
3. 1280×800 데스크톱 Chromium과 390×844 터치 Chromium 컨텍스트를 모두 실행한다. 이는 **실제 Android 기기 테스트가 아니라 모바일 크기의 Chromium 합성 시험**이다.
4. `.github/workflows/psi-company-wide.yml`에서 PR 자동 브라우저 검증에 해당 스크립트와 JSON 증빙 산출물을 포함한다.

## 보안 범위
- 다운로드 직전 SHA-256 일치는 파일이 검토 때와 동일한 바이트라는 확인일 뿐, 원본 법적 진정성, 작성시간, 가림 밖의 개인정보 제거를 보증하지 않는다.
- 합성 PDF의 개인정보 문자열은 가상 문구뿐이다. 실제 작업자 파일을 CI로 업로드하거나 GitHub에 저장하지 않는다.
- 로컬 확인은 독립된 관리자 승인, 원본 보존 서버, 외부 수신자 반출 이력, RLS 마이그레이션이 아니다.
- **운영 완료**는 `main` SHA와 Vercel Production READY SHA 일치 및 실기기 Android·PC의 개별 검증 후 별도 판정한다.
