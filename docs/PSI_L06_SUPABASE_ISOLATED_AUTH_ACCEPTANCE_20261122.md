# L06 — 승인된 독립 Supabase 환경의 실제 Auth/RLS·관리자 원문 조회 인수 시험표

> 문서 상태: **TEST PLAN ONLY / NOT EXECUTED** (2026-11-22). NEW-PSI PR #237 개발 브랜치 전용.
> 사용자 승인 전 운영 `PSI-Database`, 목적 미확인 `TELLOWSS's Project` 어느 쪽에도 아래 시나리오를 실행하지 않는다.

## 0. 시험 시작 조건 — 모두 충족해야 한다

1. 사용자가 **L06 전용**으로 승인한 별도 Supabase 테스트 프로젝트 ID, 데이터 삭제 범위, 비용 한도, 담당자·승인자·회수 기한을 기록한다. 기존 두 연결 프로젝트 중 하나를 임의로 선택하지 않는다.
2. 프로젝트가 기존 NEW-PSI 운영 인증/데이터·Vercel Production 키·Storage/브라우저 세션과 **논리적으로 완전히 분리**되었음을 확인한다. 실제 근로자 이름/사진/안전기록/연락처/공유토큰은 복사하지 않는다.
3. `supabase/proposals/` 세 개의 L06 SQL과 종속 P05 tenant/site 테이블의 **적용 순서 및 현재 마이그레이션**을 격리 DB에서 확인한다. Auth 스키마를 자의적으로 생성·수정·삭제하지 않는다.
4. 시험용 가상기업 A/B, 현장 A1/A2/B1, 사용자(근로자 A·B, 관리자 A1/A2·B1, 일반 구성원, 배정해제 관리자)를 **임의 계정과 테스트 메일**로 만든다. 서버에서 발급된 정상 Supabase 로그인 JWT만 사용한다.
5. 시험 시작·중지·정리 승인 및 증빙 저장 위치를 명확히 정한다. 서명된 JWT, Refresh Token, service-role 키, 개인정보를 CI artifact·PR·로그에 출력하지 않는다.
6. `pg_get_functiondef`, `information_schema`, GRANT/RLS 정책 및 실제 `auth.sessions` 컬럼의 구조를 **읽기 전용으로 먼저 확인**한다. 미지원 필드·공유 서비스 동작이 다르면 가설을 수정하고 시작을 보류한다.

## 2. 실제 검증과 기존 합성시험의 차이

- PGlite 45개 목표 등 코드 단위 테스트의 `auth.sessions`/JWT는 **가상 최소 구조**이다. `auth.jwt()`를 모사한 것이며 Auth 서버의 JWT 검증, 실제 로그인·로그아웃, HTTP 권한, PostgreSQL 복수 커넥션의 잠금 경합을 검증하지 않는다.
- Supabase `auth.sessions` 행이 있다고 해서 **발급된 액세스 토큰이 유효한지 모든 방식으로 증명하는 것은 아니다**. 실험에서는 JWT 만료·user ban·계정 soft-delete·signOut 동작을 각각 분리하여 검사한다.
- PostgreSQL의 `FOR SHARE` 잠금은 해당 RPC 트랜잭션 종료 시 해제된다. 이미 반환한 응답을 추후 권한철회로 되돌릴 수 없으며, 조회가 종료된 이후 새 요청은 인증·권한을 처음부터 검증해야 한다.
- `service_role`을 브라우저 또는 일반 관리자 액세스 경로에 넣지 않는다. 승인된 관리자 읽기 RPC 자체의 독립적인 테넌트·현장 인가가 반드시 필요하다.
- 가짜 작업완료일/실제 위험 제거 시각을 만들지 않으며, `approved`는 **평가자료 검토 승인**, 근로자 작업허가·TBM 수료·안전조치 완료와 무관하다.

## 3. 증빙·종료 기준

- 각 A01~A23을 `PASS / FAIL / BLOCKED / NOT RUN` 중 하나로 기록한다. SQLSTATE/HTTP 코드/응답필드·요청 전후 시각·사용 권한·DB/앱 커밋 SHA만 보존한다. JWT·키·개인 이름·사진은 저장하지 않는다.
- A02/A03/A04/A08~A16/A19~A23 중 하나라도 실패하거나, 가상 테스트와 실제 Auth 동작이 다르면 **운영 연결 금지**. 재현·원인·시정·재검증 결과가 필요하다.
- 테스트 프로젝트 검증 성공도 L18의 법정 문서/개인정보 처리·보관/삭제, 현장 관리자 인수, Android 실기기, 다국어 원어민 검토와 사용자 최종 승인을 **대체하지 않는다**.

**현재:** A01~A23 전부 `NOT RUN`. 해당 문서는 가이드/허용 범위를 명시할 뿐 DB에 접속하거나 테스트 계정을 생성하지 않는다.
