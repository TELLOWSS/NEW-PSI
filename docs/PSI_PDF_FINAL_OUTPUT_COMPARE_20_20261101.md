# NEW-PSI 20차 · 실제 출력 PDF 원본 대조 및 검토 기록 (2026-11-01)

## 기준
- 19차 PR #195, `main` `f32e12bf`: 10페이지 PDF, 터치 화면 이동/가림 모드, 가림 내부 픽셀 검사.
- 20차는 로컬 PDF의 **검토** 절차 개선이다. 기업·현장별 서버 권한/RLS, 증빙 반출 승인, 관리자 서명 및 수신 기록을 추가하지 않는다.
- Vercel Production이 코드와 동일한 커밋에서 READY인지 별도 확인하기 전까지 운영 완료라고 표시하지 않는다.

## 구현한 2단계
1. **기존 편집 단계**: PDF 파일 로딩, 페이지별 가림 지정, 확대, 이동, 모든 페이지 수동 확인 후 '실제 PDF 생성 후 최종 비교' 선택.
2. **완성 출력물 확인 단계**: `buildPsiRasterPdfReview()`로 PDF.js 원본 렌더 → 검정 픽셀 가림 → 이미지 PDF 생성 → *출력 PDF 자체* 재렌더링 검사, 추출 텍스트/주석/첨부/폼 필드 부재 검사 실행. 이 과정은 외부 전송 없이 로컬 브라우저에서 일어난다.
3. 실제로 만들어진 **동일한 Blob**을 다시 열고, 원본 파일과 최종 출력 PDF를 페이지별 비교 캔버스에서 나란히 표시한다(PC 2열, 모바일 1열).
4. 각 페이지가 실제로 화면에 로드된 후에만 해당 페이지 비교 확인을 체크할 수 있다. 전 페이지(1~10) 비교 확인이 누적되기 전에는 파일을 저장할 수 없다.
5. 비교 중 누락을 발견하면 '가림 영역 다시 수정'을 선택한다. 이전 출력 Blob은 폐기하고 편집으로 되돌아가며, 다시 만들기 전에는 저장할 수 없다.
6. 전 페이지 비교 확인이 완료되면 원래 빌드한 동일 Blob과 별도 JSON 검토기록을 로컬 다운로드한다. 검토기록에는 출력물 SHA-256, 원본 SHA-256, 페이지, 수동 비교 여부 및 미승인 상태를 구분하여 기록한다.

## 안전 및 개인정보 경계
- 비교 UI는 원본 개인정보를 화면 안에 표시한다. 화면공유·캡처·화면 녹화·주변인 열람에 주의해야 한다.
- 비교 결과는 인간의 확인 체크일 뿐이며 모든 개인정보 완전 삭제, 독립된 안전관리자 승인, 외부 제출 적법성, 최초 원본 파일 진정성을 증명하지 않는다.
- PDF.js/파일 저장은 기기/브라우저의 메모리·권한 제한을 받는다. 10페이지 파일을 실제 Android(세로·가로), 태블릿, PC에서 가져오기·가림·확대·이동·원본/출력본 대조·다운로드·다시 열기·텍스트 추출 검증까지 수행해야 한다.
- 기존 원본은 로컬 파일로 남으며, PDF 자체와 JSON은 별도 로컬 파일로 저장한다. 서버 원장/승인 로그나 PSI 증빙 ZIP에 자동 등록하지 않는다.
- 19차 가림 출력 검증은 영역 내부 픽셀 검사이며, 검은 사각형 경계의 렌더링 보간 영역과 **마스크 바깥** 개인정보까지 자동 검출하는 절차가 아니다.

## 검증 기준
- TypeScript, Vitest, 릴리스 빌드, 7개 제품 브라우저 검증.
- 비교 미완료·중복·범위 밖 페이지는 저장 전에 차단되는 단위 테스트.
- 페이지별 수동 검토와 출력물-원본 비교가 기록되더라도 JSON은 **외부 승인 기록이 아닌 로컬 확인 기록**이라는 점을 UI·스키마에 명시한다.
- 실제 기기 기능 검증, 운영 DB 마이그레이션·승인/반출 권한, Vercel 프로덕션 배포는 별도 완료 판정.
