# ATLAS · PSI Inspector 회신·재점검 UX 통합 (2026-10-26)

## 현행 확인
- `InspectorQuickWorkspace`는 조치 우선순위 레이더의 **‘회신 기록 확인’**과 별도 **‘받은 회신 모아보기’**를 동시에 노출한다. 둘 다 동일 `setInboxRequest`를 호출하는 실제 중복이다.
- `InspectorReplyInbox`의 ‘지금 확인’ 필터는 개선사진·조치 어려움만 포함하고, **조치 예정 회신을 누락**한다. 예정 답변도 임시 보호조치와 실제 예정일을 관리자에게 확인해야 하므로 조치 검토 목록에 포함해야 한다.
- `replyInbox`에서 photo=`responses.find`와 last=`responses.at(-1)`는 수신 순서와 시간 순서가 다르면 **오래된 사진이나 상태를 우선 표시할 수 있다**. 원본 배열을 수정하지 않고 실제 submittedAt를 기준으로 선택한다.
- 회신의 수령은 조치 승인·법규 확정·작업재개 승인·사진 검증을 뜻하지 않는다. 링크 생성은 전달 성공을 증명하지 않는다.

## 구현
1. **레이더의 회신함 CTA 하나만 유지**. 별도 동일 목적 배너 제거. 행동은 동일하며 수신함 진입 경로 보존.
2. **‘지금 확인’에 planned 추가**. `inboxRequiresReview`를 유일 기준으로 사용하여 UI 필터와 단위 테스트가 동기화된다.
3. `inboxNextStep` 표시: 협의 필요→장애·대체·임시 보호 확인 / 개선사진→현장 전후 사진 대조·재점검 / 조치 예정→기한 및 임시 보호조치 / 무회신→실제 송수신 단정 금지 / 반영됨→현장 재점검 별도.
4. **타임스탬프 기반 최신 회신 선택**. 사진은 photo 중 최신, 나머지 상태는 전체 회신 중 최신. 비정상 수신 배열에서도 원본을 변경하지 않는다. 회신 링크 URL/토큰은 목록 자료에 포함하지 않는다.
5. Vitest: 상태별 확인 대상, 시간순 역전, 중복 CTA, 민감 토큰 배제. 기존 Inspector 모바일 합성 QA와 전체 7업무 CI 유지.

## 제품 경계
관리자/안전관리자용 인스펙터 전체 프로그램과 기존 제한적인 현장 회신 링크는 서로 다르다. 근로자에게 전체 PSI 프로그램 접근을 공유하지 않는다. 협력사 안전관리비·안전시설·신호수 인건비는 별도 앱, SMART TBM 및 ZERO DAY 별도. API/DB 스키마/저장자료/메시지 자동 발송/자동 승인 변경 없음.

## 출시 증빙 기준
GitHub 릴리즈 CI와 전제품 합성 7업무 PASS → 동일 SHA Vercel Preview READY → main 병합 → Production READY + 실제 별칭 SHA 대조. 실제 카카오톡 전달, Android 단말, 현장 사진 재점검은 자동 QA 대상이 아니다.
