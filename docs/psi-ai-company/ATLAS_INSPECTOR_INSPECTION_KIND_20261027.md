# ATLAS Inspector 고도화 — 점검 유형과 기한부 시정조치의 명확한 분리 (2026-10-27)

## 배경 및 기존 코드 확인
사용자가 강조한 정기점검·컨설팅점검 등은 모든 조치를 당장 완료하는 업무가 아니다. 협력사와 시정기한을 정하고 기한 내 진행, 오늘 마감, 기한 초과, 개선사진 제출·재점검, 권한자 확인을 분리해야 한다.

기존 PR #97(main 병합)에는 당일·1·2·3·7일/날짜 직접입력, 최초 기한 설정 근거, 연장 사유 및 기한별 상태 구분이 이미 구현돼 있다. PR #98(main 병합)에는 20건 점검씩 서버에서 읽는 관리자용 여러 점검 통합 조치대장이 구현돼 있다. **이번 PR은 이를 다시 만들지 않는다.**

기존 결손: InspectionDocument에는 title/urgent만 있고 명시적 정기점검·컨설팅점검 구분이 없어서 저장본, 보고서, 여러 점검의 조치대장에서 그 성격을 제목으로 추측해야 했다.

## 실제 수정
1. InspectionDocument에 선택형 inspectionKind: spot(수시)/regular(정기)/consulting(컨설팅)/other(기타) 메타정보 추가. 구버전 문서에는 유형 미지정 상태를 보존하고 이름을 보고 자동 추론하지 않음.
2. 관리자 간편 점검의 사진 입력 화면 위에 점검 유형 선택 제공. 새 점검은 첫 사진 저장과 함께 종류가 저장되며, 저장된 점검은 사용자가 종류를 바꾸면 기존 revision 충돌보호와 동일한 API의 문서 저장 절차를 거침.
3. 종류 변경 중에는 새 사진/미저장 입력/조치 편집과 충돌하지 않도록 입력을 제한하고, 실패 시 이전 저장종류를 유지. 서버 validateDocument 화이트리스트와 4개 값만 허용하는 입력 검증 추가. DB 테이블/마이그레이션 없음.
4. 관리자 통합 조치대장에 점검 종류 노출·검색·CSV 열 추가. 보고서 메타정보 및 카톡/공유용 복사 요약에 점검 종류 명시. 구버전 보고서도 '유형 미지정' 보존.
5. 기존 약정기한 D-n/오늘/초과/재점검/재점검 확인, 긴급 위험 경고는 종류와 독립. 유형만으로 즉시 작업중지·재개 승인, 법적 정기점검 완료를 결정하지 않는다.
6. 기존 자원/비용 준수: API 3개 유지, cron 0, 무료 Hobby, AI 호출·사진 업로드·DB 조회 자동 증가 없음.
