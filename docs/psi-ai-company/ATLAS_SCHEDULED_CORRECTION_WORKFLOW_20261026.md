# ATLAS — 인스펙터 컨설팅·정기점검 기한부 조치 (2026-10-26)

## 사용자 업무를 반영한 구분
인스펙터는 즉시 시정용 앱에 한정되지 않는다. 컨설팅 점검/정기점검/일상점검에서 작업자·협력사와 현실적인 조치기한을 지정할 수 있다. 당일·1일·2일·3일·7일 또는 지정일을 **달력일 기준**으로 선택하며, 주말/휴무일 자동 제외 없음. 기한은 관리자가 승인/재협의할 업무 기록이며, 위험이 안전해졌다거나 작업 계속 수행을 자동 승인하는 값이 아니다. 중대·급박한 위험이면 기한부 개선 여부와 관계없이 현장 접근통제/작업중지 필요성을 우선 전문가가 판단해야 한다.

## 실제 구현
- action draft/기한 변경에 2일·7일 단축 선택 추가; 기존 당일·1일·3일·지정일 유지.
- 신규 조치에 **최초 기한 설정 이유·현장 여건** 선택 입력(최대 300자) 및 본 조치 JSON의 optional `scheduleContext` 로 저장. 기존 조치에는 필드 없음 허용. 기한 변경 시 기존 사유 변경 없이 append-only `note` 이력에 사유 남김.
- `validateDocument` 엄격 허용키 및 300자 제한, `sameAction` 불변성 비교에 최초 사유 포함. 새로운 DB 테이블/마이그레이션 없음. 백엔드 JSON 문서 보관 그대로.
- 저장한 조치 목록에서는 날짜/상태와 독립된 ① 기한 내 진행(D-n) ② 오늘 약정기한 ③ 기한 초과 ④ 개선사진 접수·재점검 대기 ⑤ 관리자 확인 완료를 명시. 새 위험이 안전해졌다고 단정하거나 즉시조치 명령을 자동 내리지 않음.
- 조치 우선 레이더에 '기한 내 진행' 개수 추가, 기한 내 모든 조치에 즉시조치 경보를 주지 않음. 응급 통제 지표/긴급 검토는 기존 별도 흐름 유지.
- 현장 조치 요청문, 인스펙터 스냅샷 보고서, 교육/차기 위험성평가 검토용 초안에 최초 기한 근거를 포함. 보고서 스냅샷은 과거 그대로, 최신 기록 적용 시 새 보고서 생성.
- 위 상태 분류는 **한 점검의 저장된 action metadata만** 사용. 현장 승인, 근로자 열람, 실제 회신 발송, 임시 보호조치 현장 이행 여부 자동 확인 아님.

## QA·보안·업무 경계
달력/윤년/연말, 기한 내/오늘/초과/재점검/확정, 오래된 문서 optional 호환, 사유 길이, 수정 이력 보존, 익명 현장 초안 및 출력 점검. Github 전체 verify:ci + Inspector 모바일 카메라/공유/회신 Playwright + 전체 7업무 합성 브라우저 + 같은 HEAD의 Vercel Preview READY 후 main 병합/Production READY+alias 대조.
근로자에게 전체 NEW-PSI/Inspector 앱 접근을 공유하지 않음; 제한 회신은 별도 공개 경로. 협력사 안전관리비/안전시설비/신호수 인건비 원장, SMART TBM, PSI ZERO DAY 독립 유지. 기한만으로 현장 위험·법령 위반·작업재개 승인 결정 금지.
