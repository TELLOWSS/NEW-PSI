# ATLAS 10차: 검수표 파일 교체 전 비교 및 작업 보호 — 2026-10-26

## 발견된 고위험 사용자 경험
기존 '기존 검수표 다시 열기' 버튼은 파일 형식 검증만 끝나면 현재 브라우저의 132건 검수표를 즉시 교체했다. 검수 중인 현재 문장이 저장되지 않았거나, 과거에 저장한 다른 파일을 선택한 경우 검수 진행정보를 잃을 수 있었다. 일반 사용자에게 예상하기 어려운 데이터 손실이므로 우선 수정했다.

## 사용자 동선
1. `기존 검수표 다시 열기`로 파일을 선택하더라도 **현재 132건 검수표는 즉시 바뀌지 않는다**.
2. 가져올 파일을 원래 v2 기준 스키마로 검증한 뒤 132개 ID마다 문장, 상태, 검수코드, 검수일시를 비교해 **차이 있는 언어/문장수, 검수 기록 증가/감소, 검수 완료 내용 변경**을 확인한다.
3. 현재 미저장 변경이 있으면 '검수표·이어하기 저장' 버튼으로 JSON 다운로드를 요청하고, 실제 파일을 확인해 '다운로드 파일 확인 완료'를 누르기 전에는 **기존 검수표 교체 버튼 사용 불가**.
4. 교체로 이전의 검수 완료 기록이 없어지거나 다른 값으로 덮일 수 있으면 **명시적 위험 확인 체크**를 해야 교체 가능.
5. 사용자가 `확인 후 이 파일로 교체`를 눌렀을 때만 검수표와 마지막 언어/문장 위치를 교체한다. `취소 · 기존 자료 유지`는 기존 작성내용을 바꾸지 않는다.
6. 불량한 파일(JSON/크기 초과/스키마/문장 수/위조된 레이블)은 적용되지 않는다. 다른 모델 결과 파일 로드는 기존 검수본 일치 검증을 그대로 유지한다.

## 자동시험
- 새 10개 단위 테스트. 120건 기존 검수 완료를 과거 미검수 파일로 덮으려 할 때의 손실 개수, 상이한 검수자·시각 변경, 132건 개별 위치 검사, 1,000회 결정적 무작위 대조, 누락/중복/위조 데이터 차단, 132건 원본 불변성.
- UI 코드 정적검사: 검수표 적용 함수가 별도로 존재하고 `needsSave`와 덮어쓰기 위험 확인 없이 상태 교체 불가.
- 전체 `verify:ci` + 7개 제품 브라우저 회귀 + 정확한 PR SHA의 Vercel Preview READY 통과 후 main 병합.
- 최종 병합 커밋의 Vercel Production READY·운영 도메인 같은 SHA 확인.

## 비용/안전/제약
- Vercel Hobby 설정·기존 3개 함수·cron 0·DB 스키마 유지. 클라이언트 비교만 하며 추가 유료 모델 호출 없음.
- JSON의 검수자 코드와 타임스탬프는 본인/전문성 인증 자료가 아니다. '검수 완료 기록'은 번역의 의미 정확성을 자동 증명하지 않는다.
- 실제 Laya 11언어 실험, Android 실기기 화면 조작성, Vercel 계정 Usage 잔여량 별도 확인 필요.
- 이 검수판은 개발자용 연구 기능으로 PSI 위험등급·작업중지·근로자 교육 합격을 직접 변경하지 않는다.
