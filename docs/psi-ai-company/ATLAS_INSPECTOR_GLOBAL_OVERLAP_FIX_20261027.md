# ATLAS Inspector · 여러 점검 통합 조치대장의 이중 상태 정확도 (2026-10-27)

## 오류와 업무 영향
기존 한 점검 일정표(PR #115)는 기한 경과와 재점검 대기를 별개의 축으로 보고 있었지만, 여러 점검 관리자용 통합 조치대장은 `actionDeadlinePhase`의 단일 상태만 사용했다. 약정기한이 지난 조치가 개선사진/완료 검토 요청 상태(`review-requested`)이면 기한 초과 수치·필터에서 누락되던 문제를 확인했다.

## 구현
- `globalActionDimensions`: 저장된 조치 기록의 기한·완료 검토 요청을 각각 독립적으로 계산한다. `verified`는 미결/기한 초과에서 제외. 후속 증빙 제출 시점이나 실제 현장 조치 완료를 추정하지 않음.
- 기한 초과 필터와 재점검 대기 필터에 하나의 조치가 동시에 나타날 수 있음. 통합 대장에 중복 건수·중복 합산 금지 명시.
- 개별 행에는 날짜상태와 재점검 상태를 함께 보여주고, 초보자도 이해할 다음 확인 행동을 안내. 담당자·기한 결측을 임의로 메우지 않음.
- CSV에 날짜 초과 여부/재점검 대기 여부/현장 확인할 다음 단계 열 추가. 기존 CSV/검색, 합의 기한근거, 보고서, 저장본은 유지.
- 최근 점검 20건 수동 조회, 현장 관리자 인증, 삭제 보류 점검 제외, 추가 API·AI 호출·DB·cron 없음.

## 출고 게이트
새 단위테스트 5건 + 기존 테스트 갱신 + 입력 순서 교란 1,000회. 전체 릴리즈/TypeScript/7개 업무 교차 브라우저 CI/인스펙터 모바일 CI/동일 SHA Vercel Preview READY 성공일 때만 main 병합. 병합 후 릴리즈 및 회사 통합 CI + Vercel Production alias 동일 SHA READY 확인.

## 한계
관리자가 직접 불러온 점검만 해당하며 전체 사업장의 이행률이나 위반 상태는 확정할 수 없다. 현장 통제 필요성은 기한과 독립, 작업재개 또는 안전법령 위반 자동판정 없음. 실제 Android 기기/현장 방문 재점검은 별도 실증.
