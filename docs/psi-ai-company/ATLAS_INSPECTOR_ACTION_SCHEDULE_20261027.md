# ATLAS Inspector · 기한부 시정조치 일정·재점검 진행표 (2026-10-27)

## 목표
정기·컨설팅점검의 모든 지적이 당일 시정·작업중지 대상은 아니다. 저장된 점검의 담당·약정기한·개선사진 제출·현장 재점검을 **날짜와 검증 상태의 두 기준**으로 표시해야 한다.

## 현재 코드 재사용
- PR #97: 달력일 기한, 현장여건·기한근거, 담당 변경이력, 조치상태 open / review-requested / verified.
- PR #98: 다중 점검 통합조치대장 및 기한별 통계. 한 번에 20개 점검 문서 조회.
- PR #114: 점검 자체의 수시/정기/컨설팅/기타 유형을 보존하기 위한 메타정보; PR114의 전제품 합성검사 완료 여부는 독립 출고 게이트.
- `InspectorActionRadar`: 한 점검의 우선 조치·5가지 집계 카드는 구현되어 있으나 **개별 저장 조치를 기한순으로 한눈에 열어보기 어렵고 재점검 대기/기한경과의 중첩을 잘못 합산할 위험**이 있었다.

## 신규 구현
1. `lib/inspector/actionSchedule.ts`: **기존 조치 상태를 변경하지 않는** 읽기전용 진행표. 미결 조치를 기한 경과 → 현장 재점검 대기 → 오늘 기한 → 담당·기한 보완 → 기한 내 진행 순으로 정렬.
2. `InspectorActionRadar.tsx`: 기존 우선 조치 카드 아래 '기한부 개선조치 일정 보기' 접기/펼치기. 조치별 약정기한·담당·개선사진 접수·관리자 재점검 필요 여부와 '이 조치 열기' 제공.
3. **기한 경과와 개선사진 접수/현장재점검 대기가 동시에 참인 경우 모두 표시.** 이 두 항목은 분류가 중복될 수 있으므로 통계 합계를 미결 건수로 오인하지 않도록 별도 안내.
4. 개선사진을 **언제 접수했는지 정확히 증명하지 못하므로** 약정기한 내 실질적인 조치 이행 여부를 자동 확정하지 않음. 작업재개/접근통제 필요성 판단과 현장 안전 승인도 자동으로 처리하지 않음.
5. 전용 반응형 목록 CSS(44px 버튼, dark 모드), 기존 등록 조치로 이동하는 버튼 재사용. 미저장 입력 이동 차단은 기존 Planner 기능 그대로 사용.
6. 기존 액션 원본/서버/API/DB 구조·실제 상태·공유 링크·자동 발송·AI 분석호출 **변경 없음**.

## 향후
점검별 관리자 일정표는 읽기 전용. 전현장 통합대장의 자동 새로고침·외부 카톡 발송·미입력 기한 자동 설정·현장 작업재개 승인으로 확대하지 않음. 차기 과제는 여러 점검에서 기록한 시정조치의 수신/증빙/재점검/수정권한을 최소정보로 보호하면서 연결하는 것.
