# ATLAS · 인스펙터 우선 조치 바로가기와 보고서 최신성 가이드 (2026-10-26)

## 소스 확인
- 회신함 분류·최신 회신 버그는 PR #95에서 해결됨. 그러나 `InspectorActionRadar`의 '조치 관리 열기'는 담당·기한·재점검의 **우선 순위가 표시돼도 정확한 조치가 있는 페이지로 직접 이동하지 못한다**. 3개 항목씩 페이지가 나뉘어 있어 관리자가 직접 찾는 부담.
- 조치 상태는 `open` / `review-requested` / `verified` 구분. 완료 검토 요청 또는 회신 사진 제출이 현장 재점검 확인을 의미하지 않음.
- `InspectorQuickWorkspace`의 report 생성은 저장된 item revision을 기준으로 API 보고서를 생성하고 조치 저장·재배치·사진 개선·재점검 확인 후 `setReport(null)`로 기존 보여주는 보고서를 닫는다. 이를 유지하고 새 보고서 제작 안내를 추가함.

## 실제 구현
1. `selectPriorityAction`: 한 점검의 저장된 조치에서 기한 초과 → 현장 재점검 대기 → 담당/기한 누락 → 미조치 순. 동일 우선순위 내 날짜와 ID로 결정적 선택. verified 항목은 우선 목록에 포함하지 않음. 이는 사람이 확인할 작업 큐이지 안전 위험도 자동 예측이 아님.
2. 레이더에는 선정된 조치명과 이유, **'우선 조치 바로 확인'** 버튼을 보여주며, 기존 일반 목록으로 이동 버튼 대신 1차 행동 CTA 한 개를 제공함. 별도 '회신 기록 확인' 버튼은 유지.
3. `InspectorActionPlanner`는 정확한 actionId를 받아 등록 배열의 페이지(3개 단위)로 이동, 해당 행의 전후사진/재점검 세부항목을 열어 초점을 둔다. API 추가 호출·자동 상태 변경 없음. 저장 전 조치·담당·사진/확인 의견 입력이 남아 있으면 화면 이동을 차단하고 안내.
4. 보고서 준비 화면에 **재점검 대기 개수**와 **최신 저장본으로 새 보고서** 작성 안내 추가. 예전 보고서 스냅샷을 덮어쓰지 않음.

## QA
Vitest: 우선순위, verified 제외, 데이터 불변, 정확한 조치 페이지, 미저장 자료 보호, 보고서 최신성 가이드. 릴리즈 verify:ci + 인스펙터 Android 합성 QA + 전제품 7 여정 검증 + 동일 SHA Vercel Preview READY. 모바일 실기기/실현장 조치 검증은 별도.

PSI/Inspector 본프로그램은 안전관리자·운영 담당자 전용. 근로자 대상 프로그램 공유 없음. 기존 제한 회신 링크는 독립 경로, 담당자의 진술은 전문가 확인 전 조치 완료 아님. 협력사 안전관리비/안전시설비/신호수 인건비, SMART TBM, PSI ZERO DAY 별개. DB/인증/사진 실제 자료/AI 과금/작업재개 자동승인 수정 없음.
