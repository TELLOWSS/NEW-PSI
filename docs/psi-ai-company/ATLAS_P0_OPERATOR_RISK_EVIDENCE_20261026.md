# ATLAS P0-1 실제 구현 — 관리자 첫 화면 위험신호·결측 근거 구분 (2026-10-26)

## 적용 범위
NEW-PSI 종합심사의 P0: 중대위험 우선 검토·6대 지표 근거 투명화·현장 사용자 다음 행동 개선의 첫 단계. 16개 과제를 모두 구현한 것은 아님.

## 기존 코드 점검에서 발견한 문제
- 근로자별 최신 기록 선택 과정에서 과거 CRITICAL_STOP 기록은 첫 행동 추천에서 빠질 수 있었다. 해제 여부는 최신 점수만으로 판단 불가.
- 유효 점수나 개선이행 응답이 없으면 평균 0/개선 신호 0%라는 계산 결과가 본체에 표시돼 실제 0과 결측을 혼동할 수 있었다.
- 보호 우선 점수 집계, 6개 상세지표 응답, 인스펙터 서버 상태는 서로 다른 기준이며 UI에서 명확한 구분 필요.

## 구현
1. utils/operatorSafetyEvidence.ts — 현재 브라우저의 자가 위험성평가 기록만 읽는 순수 집계. 근로자별 최신 기록, 과거 중지 신호 기록 수, 점수 결측, 응답 개선이행 수를 별도로 계산. 서버나 현장 DB/인스펙터를 조회하지 않음.
2. utils/operatorNextTask.ts — 최신 중지→현재 보호우선→과거 중지 신호 처리경위 검토→관리자 검토대기→점수 결측→교육의 우선순위. 과거 신호를 현장 실제 작업중지 상태라고 자동 확정하지 않음.
3. components/IntegratedWorkBoard.tsx — 관리자 첫 화면에 출처 범위와 현재/과거 작업중지 표식, 미확인 점수 건수, 인간 검토 연결 표시.
4. 실수치 0점/0%는 남기되 평가 자료가 없을 때는 '자료 없음'을 표시. AI 완료나 현장 위험 조치의 확인 여부를 오인할 기존 KPI 문구 교정.
5. 실제 위험등급·6대 지표 계산 규칙/데이터 저장/AI 호출/법적 승인 기능은 변경하지 않음.

## 수용 및 검증
- 새 12개 합성 테스트: 현재·과거 위험 분리, 관리자 공종 제외, 0/null/문자/NaN, 미기재 개선이행, 1000회 재배열, 서버 비용·인증 경계.
- 전체 verify:ci + 7개 제품 합성 브라우저 CI + PR SHA의 Vercel Preview READY 후 main 병합.
- main 병합 후 동일 병합 SHA의 CI/Production READY/운영 별칭 일치 확인.
- 실제 안전조치 완료·작업중지/재개 판단, Android 실기기, 근로자 동의·사람통역 검수는 이번 자동검사로 입증되지 않음.
- Vercel Hobby 유지, 신규 Function/cron/DB 마이그레이션/유료 모델 호출 없음.
