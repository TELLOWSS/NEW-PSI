# PSI 전체 기능 고도화 실행계획 · 2026-10-25

## 범위와 성공 기준

- **대상:** `TELLOWSS/NEW-PSI`의 현장 안전지능 **본프로그램 전체**. SMART TBM(독립 교육/일지 운영)·PSI : ZERO DAY(게임)·SMART-SFCS는 수정 또는 데이터 혼용하지 않는다.
- **최종 경험:** 현장 입문자는 **사진 촬영/위험성평가 기록 → 확인 요청 → 보호조치 → 교육 → 재점검/보고서**를 기술용어 없이 수행하고, 전문가는 원문·근거·권한·누락값·변경 이력을 추적한다.
- **절대 경계:** AI가 사진만 보고 법 위반, 처벌액, 작업 재개 승인, 위험 없음, 근로자 신원 등을 확정하지 않는다. 실제 근로자 기록은 합성 검증에 사용하지 않는다.
- **성공 판정:** 코드가 브랜치에 존재하는 것, CI 통과, PR 병합, Vercel 운영 READY, 운영 도메인 SHA 일치, Android 실기기·실현장 사용자 검증은 **각각 별개의 증거**로 기록한다.

## 이번 PR에서 실제 변경한 것 (Phase 1)

1. `utils/operationsBoard.ts`: 수치 점수는 타입이 `number`이고 유한한 0~100일 때만 신호 평가에 사용. `null`, 문자열, 빈 값은 결측으로 유지. 다만 별도 고위험 진술·판단 신호는 계속 우선적으로 표시.
2. 같은 모듈: `CRITICAL_STOP` 기록도 현장 작업중지 완료로 단정하지 않고 **작업중지 신호 · 현장 확인**으로 표기. 관리자/현장 확인을 유도.
3. `components/dashboard/PrecisionOperationsBoard.tsx`: 기본 보드의 빠른 업무에 **사진점검**·**6대 지표**·**다국어 교육** 경로 명시. '위험 없음' 표현을 선택된 기록 범위로 제한.
4. 같은 화면: 기존 `AI 제안`은 외부 AI 호출이 아니라 규칙 기반이므로 **기록 기반 확인 제안(새 AI 호출 없음)**으로 정직하게 표기. 안전점검 건수와 점수지표 집계가 자동 합쳐지지 않음을 명시.
5. `components/management/PsiCompanyAuditPanel.tsx`: 9개 부문 진행상태·책임/교차검토·다음 과제·통과조건을 표시하고 P0/P1 필터 제공. 사업용 게임/SMART TBM 합병 금지 표시.
6. `tests/operationsBoard.test.ts`, `tests/psiWholeProductRoadmap.test.ts`, `scripts/verify-psi-company-visibility-ui.mjs`: 정밀 결측과 현장 판단 문구, 로드맵 필터의 합성 검증 강화.

## 리스크·의존 관계

- Supabase `PSI-Database` 2026-10-25 읽기 전용 권고에서 **RLS 정책 없는 활성 테이블 20개(INFO)**, `authenticated`에서 실행 가능한 `SECURITY DEFINER` 함수 **5개(WARN)**, 별도 인덱스 권고를 확인. '정책 없는 테이블'은 서버 전용 접근을 차단하는 의도일 수 있으므로 일률적으로 정책을 추가하거나 RLS를 끄지 않는다.
- 함수 내부 `auth.uid()` 호출 존재 여부만으로 완전한 사용자/테넌트 권한 검증을 증명하지 못한다. 함수별 SQL·소유자·GRANT·실제 호출자·서비스 연계·대체/롤백 계획 확인 후 별도 보안 PR로 처리한다.
- `config/psi-company-progress.json`은 과거 시점의 승인 후보 **사본**. GitHub CI와 현재 Vercel SHA 확인 없이 상태를 PASS로 바꾸지 않는다.
- 11개 언어의 현장 작성·교육 내용은 전문 언어감수 및 실사용자 이해 확인 전에는 번역 정확도를 확정하지 않는다.
