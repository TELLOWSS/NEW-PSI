# 03 · 기술개발본부 제안서 (CORE 관점)
**성격:** 코드 경로/CI/Vercel 실제 상태에 기반한 가상 역할 검토. 데이터 정합성과 비용은 실측 전까지 추정.

## 근거
- `api/admin.ts`, `api/gateway.ts`, `api/inspection-share.ts`가 기존 Vercel 함수; `vercel.json`의 Hobby Fluid 설정과 `build:verified`를 유지.
- `lib/inspector/globalActionRegister.ts`의 저장원본 기반 조치대장은 점검을 페이지로 나누어 가져오며 '현재 불러온 자료'는 전체 건수 아님.
- `.github/workflows/psi-company-wide.yml`의 7개 합성 브라우저 여정과 release CI 존재; Required Checks 강제 확인은 별개.
- 계정 비용은 로컬 가정 시뮬레이터가 있어도 실제 Usage API에서 전부 검증되지 않았음.

|---|---|---|---|
| P0 | CO-01 | **다중 모듈 안전 업무 원장 조회 계약:** 위험성평가/Inspector/교육/조치별 건수·상태·원본 ID·조회 범위를 명시하고 운영카드가 보유하지 않은 데이터는 '미조회' | '전 현장 전체'로 오인할 데이터 합산 금지. 페이지네이션 누락·중복 테스트 |
| P0 | CO-02 | **불확실한 저장/공유 멱등성:** 업로드 실패·시간 초과·재시도에서 중복 조치/회신/링크를 막는 상태·요청키 계약 | 네트워크 중단, 지연 응답, 두 번 탭 테스트. 서버 접수 확인 전 성공 배지 금지 |

## 교차검토 요청
- KEEPER: 테넌트/인증/삭제 경계. PROOF: 실패주입 및 중복 쓰기. SAFI: 다른 시스템 기록 합산의 위험.
