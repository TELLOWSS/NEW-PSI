# PSI AI 개발회사 운영 헌장 v1.0

> 적용 범위: NEW-PSI 메인 안전지능 플랫폼 전체. SMART TBM 및 PSI : ZERO DAY 게임은 별도 제품이며 자동 편입하지 않는다.
>
> 이 문서는 독립적으로 상시 실행되는 AI 직원이 존재한다는 뜻이 아니다. 실제 구현은 책임 역할, 분리된 GitHub 작업, 자동 검증, 명시적인 승인 증거로 구성한다.

## 최고 책임과 독립 검증

- **제품 소유자(인간):** 최종 비전, 주요 정책 변경, 개인정보의 외부 제공, 파괴적 데이터 작업과 운영상 안전 의사결정의 최종 판단.
- **개발총괄/CTO:** 범위·우선순위·수용 기준 정의, 부서 충돌 조정, PR·검증 근거·배포 종합 책임.
- **본부장:** 자신이 담당하는 경로와 기능의 변경 정확성 및 회귀 영향을 설명한다.
- **실무 작업자:** 단일 책임 단위로 구현하고 작업 PR에 테스트와 남은 위험을 명시한다.
- **품질검증본부:** 구현과 별개로 회귀·접근성·동작 검증. 테스트 실패 시 배포 거부.
- **데이터보안본부:** 권한·사진·민감정보·삭제·Supabase 변경을 검증. 보안 우려 시 배포 거부.

## 전문 6개 부서

| 부서 ID | 주요 책임 | 교차 검토 |
|---|---|---|
| product-ux | 제품기획, 초보자/전문가 여정, 다국어 이해도, 장애 복구 | design, qa |
| design | PSI 비주얼, 컴포넌트, 가독성, 모바일·다크모드 | product-ux, qa |

| safety-ai | PSI 6대 지표, 위험성평가, OCR/사진 AI 판단 한계 | product-ux, qa |

| qa | 기능/회귀/시각·성능 검증, 안전한 합성 시뮬레이션, 증거 | 독립 검증 권한 |

## 결재 흐름

1. 제품 소유자의 요청을 검증 가능한 기능·안전·성능 수용 조건으로 변환한다.
2. 책임 본부 한 곳과 교차검토 본부를 배정한다.
3. 부서별 브랜치에서 서로 충돌하지 않게 구현한다.
4. 각 부서가 단위 검증, 전체 제품 및 브라우저 회귀 검증, 안전·개인정보 확인 결과를 제출한다.
5. 독립 QA와 보안 부서의 미해결 치명적 지적사항은 병합하지 않는다.
6. 검증한 PR 병합 후 운영 SHA, Vercel 배포 READY, 도메인 연결과 오류를 확인한다.

## 근로자 안전·데이터 보호 절대 원칙

- 사진 AI의 관찰·추정·확인 불가를 구분하고, 작업중지/작업재개·법 위반·처벌·개선 완료를 사진만으로 확정하지 않는다.
- 데이터 저장, 외부 AI 전송, 개인정보 외부 제공은 명확한 이용자 동의와 권한 검사를 거친다.
- 실근로자 식별 정보, 실현장 사진, 의료/산재 기록, 공유 토큰을 QA fixture·스크린샷·로그에 사용하지 않는다.
- 외부 발송/유료 호출/대량 삭제/스키마 변경은 독립 승인 및 복구 계획 없이 자동 실행하지 않는다.
- 합성 테스트 통과는 실제 Android, 외부 카카오톡, 사람 중심 현장 검증을 의미하지 않는다.
- 에러가 났을 때 성공했다고 표시하지 않으며, 이해하기 쉬운 원인·상태·복구 동작을 제공한다.

## 코드와 품질 증거

- 소유권 규칙: config/psi-company-ownership.json
- 소유권 실행 검사: scripts/check-psi-company-ownership.cjs
- 제품군 브라우저 검증: scripts/verify-psi-company-browser.mjs
- 부서 책임과 독립 검증을 적용해도 실제 자율 AI 직원 여럿을 상시 실행하는 시스템으로 오인하지 않는다.
- GitHub Branch Protection 설정 조회는 현재 커넥터 권한 403으로 확인할 수 없다. Required Checks 및 운영 병합 제한은 저장소 관리자 설정 확인 전에는 강제된 것으로 주장하지 않는다.
