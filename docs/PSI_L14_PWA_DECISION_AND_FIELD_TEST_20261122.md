# L14 · NEW-PSI 모바일 설치형/PWA 전환 검토와 안전한 1차 파일럿

> 2026-11-22 · Draft PR #237 전용 / main 병합 및 Production 반영 금지  
> 범위: `/field-local/` 단독. NEW-PSI 전체 관리자 앱 및 `/camera`, `/inspector`, 근로자 QR 입력은 **설치형·오프라인 보장 대상으로 포함하지 않는다**.

## 1. 현재 구현 근거

- 현재 React 19/Vite 웹앱은 반응형 UI를 보유하고, `/field-local/`은 이미 별도 HTML 진입점과 명시적 클릭으로 설치하는 서비스워커(`scope:'/field-local/'`), 컴파일된 진입 리소스 캐시 검증 메시지 `VERIFY_LOCAL_ASSETS`를 보유했다.
- 이 화면의 사진 및 점검 기록은 이 기기 브라우저의 저장소를 사용한다. OS 사진첩 영구 파일 저장이나 회사 클라우드 자동 동기화로 간주하지 않는다.
- 저장소 `estimate/persist/persisted`는 근사치/브라우저 허용만 표현하며, 사용자의 데이터 삭제·기기 분실·공용 프로필·브라우저 정책 변화로부터 영구 보호를 보장하지 않는다.
- 기존 `vite.config.ts`는 로컬 진입 번들 + CSS 의존성만 캐시하고, `field-local/sw.js`를 빌드 중 생성한다. 이 단계에서는 기존 기록 DB/업로드/권한/유료 API를 변경하지 않는다.

## 2. 이번 L14 구현 (브랜치 한정)

1. **설치 정체성 분리:** `public/field-local-l14.webmanifest`에 `id/start_url/scope` 모두 `/field-local/`, `display:'standalone'`을 명시. 루트 `index.html`에는 매니페스트를 심지 않는다.
2. **192×192 및 512×512 실제 PNG** 아이콘을 `public/`에 포함. 이는 파일럿용 PSI 기기 점검 아이콘이며 최종 브랜드 원화 승인을 대체하지 않는다.
3. **사용자 요청 설치 안내:** 브라우저가 `beforeinstallprompt`를 제공할 때만 버튼을 표시하고 사용자 클릭 후 `prompt()` 호출. 설치 요청 수락·설치 이벤트·독립 화면 시작을 각각 **서로 다른 사실**로 설명.
4. **브라우저별 수동 안내:** 설치 프롬프트가 없는 Android/iOS에서는 메뉴/공유 경로를 설명하되 설치가 가능하다고 단정하지 않는다.
5. **별도 오프라인 준비 유지:** 기존 서비스워커 수동 준비/검증을 바꾸지 않고 매니페스트·PNG 두 개를 오프라인 셸 캐시 확인 대상에 추가. 인쇄·AI 원격 분석·관리자 클라우드 데이터까지 오프라인이라고 주장하지 않는다.
6. **회귀 계약:** manifest 범위, PNG 실제 파일 차원, 로컬 서비스워커 범위, 사용자 클릭 설치, 설치≠기기 저장≠영구보존≠서버수신을 Vitest로 검증.

## L39 — 기기별 자체 지원상태 확인(현장 시험 전 사전 진단, 2026-11-22)

- `/field-local/`에 **사용자가 버튼을 직접 눌러 실행하는** 기기 지원상태 확인 추가. 브라우저 신호·보안 컨텍스트·설치형 여부·서비스워커 활성/캐시·IndexedDB API·브라우저 지속보관·카메라 API 총 **8개 항목**을 로컬에서 확인한다. 지원 API 감지는 실제 사진촬영 성공·기기 저장 무결성·실제 현장 통신·정식 서버 수신의 증거가 아니다.
- 결과 복사는 사용자가 명시적으로 누를 때만 브라우저 클립보드에 넣으며, 자동 서버 전송/로그 업로드는 구현하지 않는다. 기기명, UA, GPS, 고유 ID, 실제 사진·점검 메모, 근로자/로그인 데이터는 보고서에 수집하지 않는다.
- `field-local/devicePreflight.ts`, `tests/psiFieldDevicePreflight.test.ts`에 수동 진단의 정확한 의미와 비식별 결과·실제 인수 미완료 경계를 작성. 기존 `scripts/verify-psi-l16-resilience.mjs` 합성 Chromium이 화면 버튼 클릭 후 8개 진단항목·미승인 안내를 검증한다. `P3 실제 Android QA PASS`라는 주장 금지.
- **실검수 순서:** 현장 Android Chrome 및 삼성 인터넷 각 브라우저에서 진단 실행→지원표 복사(필요시 개인정보 검토)→실제 비행기 모드/사진·메모 저장·복원·확대/TalkBack 별도 재현→동일 브라우저·버전별 승인자가 확인. 기기 미확보 상태에서는 L18 모바일 인수 게이트 계속 pending.
- 이 변경은 개발 PR #237 한정이며 기존 운영 `main`/Production/DB/Auth·외부 API/사진 데이터 변경 없음. 같은 최종 HEAD의 릴리스·전사 Chromium·Inspector CI 종료 전 자동검증 완료 주장 금지.
