# PSI 로컬 우선 월 마감 구조와 개선 파급효과

작성일: 2026-09-02 / 최종 확인: 2026-09-03
상태: 로컬 우선 저장 구조 운영 반영 완료. 최종 검증 범위와 미구현 항목은 9절 참고.

## 1. 사용자가 추구하는 PSI의 가치

PSI의 목적은 위험성평가 서류를 중앙 서버에 끝없이 모으는 것이 아니다. 현장은 상세 증빙을 직접 소유하고, 근로자에게는 현장이나 회사가 달라져도 끊기지 않는 안전역량의 성장 이력을 제공하는 것이다.

이를 위한 원칙은 다음과 같다.

1. 원본 자료는 현장 PC의 월별 파일로 보관한다.
2. 서버는 원본 보관소가 아니라 작고 제한된 연속성 정보와 백업 검증 영수증을 담당한다.
3. 성명·공종이 같다는 이유로 사람을 자동으로 합치지 않는다.
4. 타회사 이동 추적은 근로자의 동의와 회사별 접근권한이 전제다. 무단 평판조회 기능으로 만들지 않는다.
5. 비용이 발생할 수 있는 유료 OCR은 관리자 비밀번호와 건별 명시 승인이 없으면 호출하지 않는다.
6. 자동화보다 자료 보존, 추적 정확성, 비용 통제의 안전장치를 우선한다.

## 2. 개선 전후와 직접적인 파급효과

| 영역 | 개선 전 위험 또는 한계 | 이번 변경 | 기대 효과와 주의점 |
|---|---|---|---|
| 원본 보관 | 기록 저장·수정 때 평가 본문과 개인정보가 서버로 누적될 수 있음 | 자동 기록 동기화, 자동 근로자 개인정보 등록, 승인 우수기록 원문 자동 적재 제거 | 원본의 중앙 축적과 불필요한 저장·전송을 줄임. 기존 서버 행은 별도 점검·승인 없이 삭제하지 않음 |
| 월별 백업 | 전체 누적 파일을 반복 저장하여 파일이 커지고 월 경계가 불명확 | 대상 월만 내보내고 월·세대 파일명과 내부 내용 해시 사용 | 월별 찾기·보관·이관이 쉬워지고 과거월 수정본을 구분할 수 있음 |
| 백업 신뢰성 | 다운로드를 요청한 것과 실제 복원 가능한 파일을 혼동할 수 있음 | 파일 재불러오기 후 건수·날짜·식별 집계와 SHA-256 내용 해시 검증 | 저장된 해시와 내용 불일치·부분 저장을 복원 전에 탐지. 내용과 해시를 함께 다시 쓴 조작까지 증명하지 않으며 암호화·전자서명을 대신하지 않음 |
| 대용량 복구 | 이미지 포함 JSON을 한 번에 읽으면 메모리 압박 | 순차 판독 중 원본 내용을 해시 검증하고 브라우저 복구본에서는 이미지 제외 | 대용량 복구 안정성 개선. 전체 원본 이미지는 PC 파일에 남고, 메타데이터 복구본에는 없음 |
| 복원 충돌 | 오래된 백업이 최신 PC 수정본을 덮을 수 있음 | 같은 ID의 더 최신·동시각·시각 불명 PC 기록 보호 | 검수·승인 내용이 과거 상태로 돌아가는 위험 감소. 충돌 자료는 관리자 확인 필요 |
| 서버 저장량 | 원문·이미지·상세 이력이 기록 수와 수정 횟수에 비례하여 증가 | 검증된 월별 영수증과 고정 필드 요약만 전송 | 저장 단위가 문서 전체에서 작은 요약으로 축소됨. 요약 행도 장기적으로 증가하므로 보존정책은 필요 |
| 근로자 식별 | 이름·국적·공종 기반 식별자는 동명이인 오병합 또는 공종 변경 시 단절 가능 | 휴대용 안정 ID를 우선하고 이름 유사성은 수동 확인 후보로만 사용 | 잘못된 이력 합치기를 줄이고 안정 ID가 유지된 이동을 연결할 기반 확보 |
| 회사 간 이동 | 전역 이름·전화·생년월일 매칭은 다른 회사 자료 노출 위험 | 서버 조직·현장 범위를 환경변수로 고정하고 무단 타회사 조회는 제공하지 않음 | 경계 밖 조회 방지. 다회사 공용 서비스의 완성형 회원·동의 모델을 대체하지는 않음 |
| OCR 감사 저장 | Harness에 원문·파일명·이름·자유서술이 남을 수 있음 | 판정 코드·숫자·해시·버전 중심으로 영속 저장 축소 | 디버깅에 필요한 최소 근거는 유지하면서 원문 축적을 차단 |
| 관리자 보안 | 실행 인스턴스가 바뀌면 로그인 제한이 초기화될 수 있음 | DB 기반 제한, 실패 시 안전 차단, 요청 비밀번호 정리 | 반복 대입 공격과 비밀번호 잔존 위험 감소 |
| 잔여 자동 적재 | 오래 열린 구버전 화면이 원문 적재 API를 계속 호출할 수 있음 | 구버전 우수사례 적재 API를 서버에서 건너뛰고 브라우저 벡터 조회·임베딩 호출 제거 | 추가 원문 적재와 해당 임베딩 호출을 차단. 과거사례 검색 대신 현재 문서·내장 평가기준을 사용하므로 동일 문서 품질 비교는 별도 점검 필요 |
| 재평가 연결 | 이름·공종만 같은 기록을 보호조치에 자동 연결할 수 있음 | 정확한 휴대 ID가 일치할 때만 PC 안에서 연결 | 동명이인 오연결과 자동 개인정보 업로드 감소. 사용자가 명시적으로 저장하는 별도 안전조치 업무는 유지 |
| 화면 이해 | 백업·복구·서버 저장의 의미가 혼재 | 로컬 우선 안내, 월 마감 버튼, 검증·복원 버튼을 한 묶음으로 배치 | 사용자가 자료의 실제 위치와 다음 행동을 이해하기 쉬움 |

## 3. 저장 위치와 전송 범위

| 자료 | PC 월별 파일 | 브라우저 작업 저장소 | 서버 영속 저장 |
|---|---:|---:|---:|
| 원본 이미지·프로필 이미지 | 포함 | 작업 중 보관 | 월 마감 기능에서는 금지 |
| 수기 원문·번역·평가 본문 | 포함 | 보관 | 월 마감 기능에서는 금지 |
| 상세 검수·수정·승인 이력 | 포함 | 보관 | 월 마감 기능에서는 금지 |
| 월·세대·건수·내용 해시 | 포함 | 작은 백업 목록 | 검증·사용자 확인 후 허용 |
| 안정 근로자 ID별 평가 건수·점수·등급 요약 | 원본에서 재생성 가능 | 필요 시 계산 | 검증·사용자 확인 후 허용 |
| 성명·전화·생년월일·여권번호 | 기존 원본에 있을 수 있음 | 원본 범위 | 월 요약 API에서 금지 |

“서버에 영속 저장하지 않는다”는 “서버로 전혀 전송하지 않는다”는 뜻은 아니다. OCR 분석을 위해 문서가 서버와 OCR 제공자에게 전달되는 처리 경로는 존재한다. OCR 제공자의 보관·학습 정책은 별도 적용되며, 이번 변경이 제공자 측 즉시 삭제를 보증하지는 않는다. 이번 변경은 PSI의 데이터베이스에 평가 원문을 자동으로 쌓는 동작을 제거하는 것이다. 교육서명·안전조치 등 별도 업무 기능의 저장정책까지 모두 없애는 변경은 아니다.

안정 ID와 점수 요약은 연결 가능한 **가명정보**이지 완전한 익명자료가 아니다. 서버 영수증도 PC에서 검증했다는 결과를 접수하는 것이며, 서버가 원본 파일을 직접 읽고 검증·보관한 증명서는 아니다.

## 4. 비용과 규모 확장에 미치는 영향

### 저장비용

원본은 이미지가 크기 때문에 서버 원본 저장을 없애는 효과가 가장 크다. 예를 들어 근로자 1,000명, 월 22건/명, 문서당 평균 0.5MB라는 가정이면 월 원본은 약 11GB다. 같은 근로자의 월 요약을 1KB/명으로 잡으면 요약 본문은 약 1MB다. 이 수치는 구조 차이를 보여주는 가정 예시이며, 실제 파일 크기·DB 인덱스·행 오버헤드·보관기간·요금제에 따른 청구액 측정값은 아니다.

이번 구조는 기록 수정 때마다 원문을 재전송하지 않으므로 DB 쓰기 횟수와 네트워크 전송도 줄인다. 월 마감 파일을 확인했을 때만 작은 서버 요청을 보낸다. 다만 서버 요약·영수증·보안 로그도 저장공간을 사용하므로 “서버 비용이 영원히 0원”이라고 보장하지 않는다.

### OCR 비용

- 월별 백업·해시 계산·복원 검증은 로컬 연산이며 LLM 호출이 필요하지 않다.
- 이 기능을 사용한다고 유료 OCR로 자동 전환하지 않는다.
- 무료키 소진 시 중단하고, 유료 호출은 기존의 비밀번호·건별 승인·상한 검사를 통과해야 한다.
- 이번 저장구조 검증에는 유료 OCR을 호출하지 않는다.

### 관리비용

월별 파일과 세대 번호가 생기면 자료 요청 시 전체 누적 파일을 찾는 대신 해당 월만 확인할 수 있다. 반면 PC 원본 보관 책임이 명확해지므로 현장에는 월 마감 담당자, 보관 폴더, 별도 저장장치 사본, 복원 점검 절차가 필요하다.

## 5. 현장·회사 이동 시 연속성의 범위

안정 ID는 이름·팀·공종·평가등급과 분리되어야 한다. 같은 안정 ID가 확인된 기록은 현장 이동 후에도 연결할 수 있지만, 이름이 같다는 사실만으로 과거 이력을 공개해서는 안 된다.

이번 단계는 안정 ID 우선 정책과 최소 월 요약의 기반을 만든다. 완성형 타회사 휴대용 이력 서비스에는 다음이 추가로 필요하다.

- 회사별 관리자 계정과 소속·현장 권한
- 근로자 본인확인과 공유 동의, 목적·범위·만료·철회
- 짧게 유효한 서명 QR 또는 휴대용 패스
- 이전 회사의 자유메모·원문·상세 사고기록을 제외한 제한 요약
- 조회·연결·해제 감사기록

현재 공용 관리자 비밀번호만으로 위 기능을 구현했다고 간주하지 않는다. 해당 경계가 완성되기 전에는 타회사 자동 조회·자동 병합을 열지 않는 것이 안전하다. 전체 월별 백업 파일을 다른 회사로 전달하는 방식은 휴대용 이력 공유를 대신할 수 없다.

또한 기존 관리번호만 있고 회사·현장 범위가 확인되지 않는 경우에는 다른 회사의 같은 번호와 자동 연결하지 않는다. 휴대 ID 또는 검증된 QR 없이 자동 생성 관리번호만 있는 과거 자료는 수동 확인 대상으로 남는다.

현재 운영 배포는 하나의 고정 조직·현장 범위를 사용한다. 다른 현장 파일을 가져왔을 때 출처를 자동 인증하는 다현장 관리 시스템은 아니므로, 해당 배포의 대상 현장 자료만 등록해야 한다. 회사·현장별 독립 배포는 서로 다른 범위를 설정해야 한다.

## 6. UI·운영 설계

권장 월 마감 흐름은 `월 선택 → PC 파일 저장 → 파일 재불러오기 → 해시 검증 → 사용자 확인 → 최소 서버 영수증`이다.

- 파란 영역: 원본이 PC에 있다는 위치 안내와 월 마감 행동
- 녹색 상태: 파일 저장 또는 검증 성공
- 황색 상태: 다운로드 확인 필요, 서버 영수증 등록 보류
- 붉은 상태: 해시 불일치 또는 복원 차단
- 전체 백업과 전체 삭제는 보조 작업에 남겨 월 마감과 구분
- 저장·검증·서버 등록을 서로 다른 상태로 표현하며 다운로드 요청만으로 “마감 완료”라고 표시하지 않음

## 7. 남아 있는 운영상 주의사항

1. PC 한 대에만 원본이 있으면 디스크 고장·분실·랜섬웨어에 취약하다. 검증된 파일을 별도 저장장치에도 복사해야 한다.
2. 현재 JSON 백업 자체는 암호화되지 않는다. 파일 접근권한과 저장장치 암호화가 필요하며, 파일 암호화 내보내기는 별도 구현 과제다.
3. 브라우저 데이터 삭제나 기기 교체 후 상세 기록은 서버에서 자동 복원되지 않는다. PC 월별 파일을 가져와야 한다.
4. 오래된 월 기록의 자동 삭제는 하지 않는다. 백업 확인 전에 자료를 정리하지 않도록 운영해야 한다.
5. 서버 월 요약도 장기 누적되므로 실제 사용량을 보고 최근 기간 요약과 장기 압축 요약의 보존정책을 정해야 한다.
6. 과거 서버 원문·벡터·Harness 행은 이번 코드 변경만으로 삭제되지 않는다. 현황·백업·업무 영향 확인 후 별도 승인으로 정리해야 한다.
7. 낮은 점수나 교육 이력을 채용 배제·낙인으로 사용하는 기능은 제공하지 않는다. 이력의 목적은 교육과 개선 지원이다.
8. 월별 백업을 만들었다고 브라우저 작업 저장소가 자동으로 줄어들지는 않는다. 자동 삭제는 없으며, 검증된 별도 사본을 확보한 뒤 수동 정리해야 한다.
9. 이미지 제외 방식으로 복구한 데이터를 다시 내보내도 빠진 이미지가 재생성되지는 않는다. 최초의 이미지 포함 월별 파일을 보존해야 한다.
10. 서버 요약 등록은 요청당 2 MiB·5,000명 상한이다. 초과하면 서버 등록만 보류하고 PC 백업과 로컬 검증은 유지한다. 여러 PC에서 같은 월·같은 세대를 만들면 서버가 충돌을 거부하므로 마감 담당 PC와 세대 관리가 필요하다.

## 8. 검증 기준

- 월별 파일의 건수·해시 일치 및 변경·추가월·손상 manifest 차단
- 대용량 스트리밍에서 원본 이미지 포함 내용 해시 일치
- 최신·동시각·시각 불명 PC 기록 덮어쓰기 차단
- 기록 저장·수정·로그인 과정에 자동 원문 및 개인정보 등록 요청이 없음
- 서버 API가 원문·이미지·성명 필드 및 임의 조직·현장 입력을 거부함
- 서버의 월 등록은 멱등적이며 같은 세대의 다른 내용을 덮어쓰지 않음
- 유료 OCR은 승인 없이 호출되지 않음
- 타입 검사·회귀 테스트·빌드와 배포 후 운영 확인

- 운영 API: 관리자 로그인 HTTP 200 / DB 제한 모드, 월 요약 저장소 정상, Harness `service_role`·테이블 연결 정상, 구버전 원문 적재 요청은 `local-first-storage-policy`로 건너뜀.
- 운영 DB: 월 요약 구조, 기록 마스터 서버 경계, Harness·기존 벡터 서버 경계 마이그레이션 적용. 관련 테이블·뷰 15개를 집계해 공개 읽기 허용 0개, 보호 미적용 0개 확인. 기존 행은 삭제하지 않음.
- 실제 DB 트랜잭션: 새 세대 등록·동일 재시도·이전 세대 보존·동일 세대 충돌·조직/현장 격리·원문 필드 거부·접근권한 검증 통과. 검증 데이터 롤백 후 두 테이블 모두 잔여 시험자료 없음.
- 운영 화면에서 월 마감 저장·검증/복원 버튼과 로컬 우선 안내 표시 확인. 배포 순간 이전 화면의 옛 파일 주소 오류는 새로고침으로 회복됐으므로 업데이트 후 새로고침 권장.
- 실제 근로자 자료는 이번 검증에서 업로드·수정·삭제하지 않았고 유료 OCR 호출도 하지 않음. 브라우저 파일 저장/재불러오기 전체 조작과 실문서 OCR 정확도 재측정은 이번 운영 검증 범위에 포함하지 않았다.

이번 완료 범위는 **평가 원문 자동 적재 차단, PC 월별 백업·검증, 최소 요약 접수, 식별 오연결 방지, 운영 배포**다. 회사별 회원·본인 동의 기반 타회사 이력 패스, 암호화 백업, 장기 보존·정리 자동화는 미구현 후속 범위이며 완료로 간주하지 않는다.

별도 보안 점검 사항: 배포 의존성 검사에서 기존 PPT 생성 의존성의 `image-size` 관련 고위험 경고가 확인됐다. 이번 저장구조 변경으로 새로 추가한 패키지는 없으며, 과거 버전으로 강제 내리는 자동 수정은 하지 않았다. PPT 이미지 처리 경로 검증과 호환 가능한 보안 업데이트를 별도 진행해야 한다.
