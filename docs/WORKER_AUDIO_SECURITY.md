# 근로자·교육 음성 접근 경계

2026-09-30. 근로자 테이블의 전체 허용 정책과 교육 음성 파일의 공개 업로드/목록 조회 정책을 보완한다. 실제 앱의 근로자 등록·수정·조회와 음성 업로드·삭제는 관리자 서버 API를 사용한다. 근로자 교육 화면은 별도 교육 세션 조회와 기존 음성 URL을 이용하며 근로자 테이블이나 음성 목록을 직접 조회하지 않는다.

`20260930002000_worker_audio_server_boundary.sql`은 `workers`의 PUBLIC/anon/authenticated 권한을 회수하고 RLS를 활성화·강제한다. 기존 전체 허용 정책을 보존하되 조건을 false로 바꿔 비활성화한다. 기존 서비스 역할의 CRUD 권한과 BYPASSRLS가 유지되지 않으면 전체 변경을 롤백한다.

교육 음성의 기존 6개 허용 정책을 비활성화하고 `training_audio`의 목록·메타데이터·업로드·수정·삭제를 막는 제한 정책을 추가한다. 이후 광범위한 허용 정책이 추가되더라도 일반 계정은 이 버킷에 접근할 수 없다. `signatures` 등 다른 버킷의 정책과 업로드 경로, 실제 객체 및 기존 자료는 유지한다. 호스팅 저장소의 객체 메타데이터를 SQL로 등록·수정·삭제하지 않는다.

## 남은 공개 재생 범위

버킷의 공개 설정과 기존 교육 음성 URL을 유지한다. 따라서 파일 주소를 아는 사람은 재생할 수 있다. 목록 차단을 개별 파일의 비공개화로 설명하면 안 된다. Supabase의 공개 버킷은 파일 제공을 RLS와 별도로 처리한다([공식 문서](https://supabase.com/docs/guides/storage/buckets/fundamentals)). 전체 공용 SaaS에 적용하려면 교육 링크의 기업·세션·유효기간 확인과 제한 시간 서명 URL 발급을 구현한 뒤 기존 URL·공개 버킷을 전환해야 한다.

## 검증

사용자가 지정한 호스팅 Supabase 프로젝트에 적용했고 `supabase/tests/worker_audio_server_boundary.sql`의 읽기 전용·롤백 검증이 통과했다. Security Advisor는 Errors 0건, Warnings 9→7건으로 확인됐다. 남은 항목은 기존 함수 6개의 검색 경로와 public 스키마의 vector 확장이다.

실제 PostgreSQL 테스트에서 익명/일반 계정의 근로자 읽기·쓰기 거부, 음성 목록·업로드·수정·삭제 거부, 향후 잘못된 허용 정책에도 차단 유지, 기존 기록 보존, 서비스 역할 작업, 다른 버킷 업로드 유지와 재적용을 확인한다. 운영 DB에서는 정책·권한·RLS·공개 설정만 확인하며 고객 기록과 음성 원문을 읽거나 변경하지 않는다. 실제 관리자 계정의 업로드/삭제와 근로자 음성 재생은 별도 계정 흐름 검증이 필요하다.
