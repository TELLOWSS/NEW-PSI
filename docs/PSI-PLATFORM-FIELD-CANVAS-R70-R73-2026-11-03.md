# NEW-PSI FIELD CANVAS — 운영 플랫폼 통합 UX/UI 설계 (R70–R73)
작성일: 2026-11-03 | 단계: 개발 브랜치 / 검증 전 | 기존 R66~R69 사진점검과 연동

## 1. 소스 진단 및 문제정의
- 운영 메인 `Layout` + `AppShell` + `TopBar` + `Sidebar` + `PrecisionOperationsBoard`는 기존 파란색 토큰/다중 카드/그룹별 메뉴로 구성되어 있다. 사진점검 전용 `inspector-refresh.css`와 스타일/브랜딩이 다르다.
- 12개 업무 바로가기와 KPI, 기록 테이블 및 분석 기능이 있으나 기본 화면 첫 구간에 「위험성평가 기록 → 현장 사진점검 → 교육 환류」를 연결하는 명료한 진입로가 없다.
- 사이드바에는 많은 메뉴가 있고 사용자가 메뉴의 중요도를 한눈에 구분하기 어렵다. 기존 사용자별 메뉴 구성/운영 모드/승인·검증 기능은 유지해야 한다.
- **분석 범위**: GitHub main 기준 컴포넌트/스타일 소스. 실제 Android/Samsung Internet에서 고객 테스트한 결과라고 주장하지 않는다.

## 2. 디자인 콘셉트
### Field Canvas / Safety Intelligence, legible by default
- 제품 메시지: **근로자가 인식한 위험을, 관리자가 검토하고, 안전조치·교육·재확인으로 연결한다.**
- R66–R69 사진점검의 네이비(잉크)·틸·오프화이트 색상과 타이포 계층을 운영 대시보드의 shell / 주요 카드에 확장한다.
- 업무상 위험 색상(긴급·경고·진행·일반)은 의미가 있으므로 브랜드색으로 덮어쓰지 않는다. 위험 0건도 '현장이 안전하다'는 근거로 사용하지 않는다.
- 모국어·접근성: 시스템 기본 글꼴만 사용하고 외부 폰트 다운로드를 요구하지 않는다. 키보드 포커스, min-height 44px, 최소 14px 본문, 모바일 360~390px 줄바꿈, 다크모드/감소모션을 지원.
- 장식만 위한 이미지/배경 애니메이션/외부 AI 호출/유료 API 추가 없음. 데이터·서버 스키마/저장소 변경 없음.

## 3. 화면 구성
### R70 — 공통 Shell / Navigation
- 프로젝트 일반 운영 화면에만 `psi-platform-field-canvas` 스코프를 적용. 별도 경로(`/product`, `/field-local`, 근로자 교육, 인쇄용 보고서)는 변경하지 않는다.
- 사이드바: 브랜드 영역, 그룹 헤더, 활성 메뉴, 인식 쉬운 대비, 44px 버튼, 모바일 햄버거·하단 메뉴. 사용자별 구성·숨김·순서는 유지.
- Topbar: 페이지명/현장명/운영자 메뉴 정보가 군더더기 없이 보이는 타이포그래피와 테두리. 안전 상태는 텍스트를 유지. 불필요한 '실시간'·'승인 완료' 표기를 만들지 않는다.
- 공통 PageHeader 카드 및 캔버스, 빛 번짐을 줄인 선명한 패널, 명도 대비. 바탕과 다크 테마를 균형 있게 구현.

### R71 — Precision Dashboard의 '오늘 할 일' 단축 진입
- 데이터를 건드리지 않는 읽기 전용 진입 레일. 3개 경로: 위험성평가 원문 확인/기록(`ocr-analysis`), 사진으로 위험 확인(`safety-inspector`), 관리자 검토 내용을 교육으로 환류(`education-return`).
- 각 카드에 내용·직접 이동 동작과 'AI 제안은 최종판단이 아님' 안내. 기존 6단계 흐름과 역할별 메뉴/기간 필터는 그대로.
- 카드의 시각적 경중은 위험도 판정을 뜻하지 않음. 수치 없는 시작 카드에 거짓 카운트 표시 금지.

### R72 — 대시보드 카드 및 상세 관리 외관
- 기존 KPI/검토대기 큐/차트/분포/재점검 화면에서 표·차트 폭, 타이포·간격·테두리·카드 높이를 통일. 값과 위험 상태 텍스트는 보존한다.
- '상세 분석'의 헤더 톤도 공통 Field Canvas 테마와 연결하되, 분석 지표 내용/감사로그/인쇄 기능은 변경하지 않는다.

### R73 — 자동검증과 묶음 출시
- 정적 UI 계약: 주요 경로가 라우트에 정확히 연결되고 외부 API 호출·저장 데이터 변조 코드를 추가하지 않았는지 확인.
- 빌드/타입/기존 Vitest/F10 오프라인 300건/모바일 사진점검/부서 간 플로우 유지.
- 헤드리스 브라우저 회귀: 가능하면 공개 앱과 관리자 샘플 환경에서 320/390/768/1440px, 키보드 및 스크롤, 버튼 반응, 다크모드 등을 확인. 자동 테스트가 안 되는 경로는 미검증이라고 명시.
- 본 배치는 **Draft PR**에 누적. 42~69차 Production이 막 출시되어 Vercel Hobby 배포를 불필요하게 소모하지 않는다. PR HEAD 전 검증 전부 성공 및 운영 배포 승인 조건이 충족될 때만 단일 릴리스로 결합.
- 실제 현장 반영 판단은 관리자 검토, 모바일 Android 실기기, 오프라인/데이터 백업, 접근성 검토 이후로 별도 구분.
