# NEW-PSI 12차 — 제출 검토안의 독립 승인과 반출 통제: 서버 기반 시범 설계

## 이번 범위
- 11차 PR #185의 **로컬 ZIP 제출 검토 초안**은 사용자 입력에 의한 자료 준비 기록이며 서버 승인으로 해석하지 않는다.
- 12차는 기업별 관리자 인증 계정을 전제로 한 PostgreSQL **검토안 등록·독립적인 검토 승인/반려**의 기초 SQL 및 격리 테스트만 작성한다.
- SQL은 `supabase/proposals/psi_tenant_disclosure_reviews_staging.sql`에 있으며 **정식 운영 마이그레이션이 아니다**. Vercel/API/관리자 UI에서 이 DB에 대한 요청을 자동 수행하지 않는다.

## 상태 모델
1. `psi_tenant_disclosure_requests` 신규 등록 — 기업 소속 owner/admin/reviewer 중 한 명, 패키지 전체 SHA-256, 선택파일 목록의 SHA-256, 제출목적·예정기관·요청근거를 기록. 서버 수신시각과 인증된 등록자를 DB에서 작성.
2. `psi_tenant_disclosure_decisions` — 다른 owner/admin 계정이 동일 기업 검토안에 대해 `review_plan_approved` 또는 `review_plan_rejected` **하나의 결정**을 생성.
3. 작성자와 결재자는 동일 계정일 수 없으며, 해당 기업의 활성 멤버십이 없는 계정·viewer·reviewer의 결재는 거부.
4. 두 테이블은 INSERT만 허용. UPDATE/DELETE를 차단하고, 결정 중복과 기업을 달리한 참조를 기본키·복합 외래키로 차단.
5. 신청·결정은 **파일 전달 승인이나 실제 반출 기록이 아니다.** 검토안의 승인과 실제 파일의 마스킹·제출본 생성·제공·수신 확인은 별도 승인 단계가 필요.

## 보안 및 법적 한계
- 기업 단위 `tenant_id` 격리만을 검토했다. 동일 기업 내 현장 `site_id` 권한 분리는 미구현이다.
- 가상 SQL 테스트가 통과하더라도 실제 사용자 연결·승인 권한·파일 제공의 전송 경로는 검증된 것이 아니다.
- 패키지나 선택 목록 해시는 각 내용의 무결성 대조 정보일 뿐 제출이 적법한지, 모든 개인정보를 마스킹했는지 확인하지 못한다.
- DB 소유자·백업 운영자는 원리상 데이터 접근이 가능하다. 공인 WORM·시점 인증이나 법적 증거능력 인증은 아니다.
- 별도 반출 승인 및 서버 감사 기록, 제출받는 기관의 수신 확인, 보존·파기 정책은 아직 없다.
- SQL은 운영 데이터에 반영하지 않으며 기존 근로자 정보를 실험 대상으로 사용하지 않는다.
