# 지정 교육 대상자 접근 제한

2026-09-30. 사용자의 선택에 따라 지정 교육의 대상자 명단을 접근 권한으로도 사용한다. `attendance_only` 교육은 현재 명단의 근로자 ID로 본인 확인 성공, 교육자료 열람·음성 주소 발급, 이수 확인, 공개 서명 제출을 허용한다. 이름이 같아도 다른 ID는 허용하지 않는다. 명단이 비어 있거나 이름만 있는 과거 명단은 접근을 차단하며 관리자가 대상자를 다시 선택해야 한다. 기존 명단이나 고객 기록을 자동으로 수정하지 않는다.

각 요청에서 서버가 활성 근로자와 최신 교육 대상 설정을 읽는다. 삭제된 근로자는 기존의 유효한 인증 토큰이 있어도 접근할 수 없다. 대상자 변경도 다음 요청부터 적용된다. 이미 발급된 음성 주소는 기존의 최대 5분 유효기간 내에서 사용될 수 있으며, 공개 음성 버킷의 기존 URL 자체를 회수하는 변경은 아니다.

범위 미지정(`submitted_only`)과 과거 null 모드 교육은 등록된 활성 근로자의 본인 확인을 계속 허용한다. 누락된 열, DB 오류, 알 수 없는 모드에는 접근을 허용하지 않는다. 관리자 인증을 받은 대리 서명은 기존 업무 계약을 유지하며, worker ID가 있는 개별 대리 서명은 활성 근로자를 확인한다. 이 정책은 기업 소속 권한을 대신하지 않으며 공용 SaaS 출시 차단은 유지한다.

운영 Supabase에서 `workers.deleted_at` 및 `training_sessions.target_mode`, `target_worker_names`의 존재와 형식을 읽기 전용 메타데이터 조회로 확인했다. DB 마이그레이션은 필요하지 않았다. 회귀 검사에는 이름 변경, 동명이인, 빈 명단·이름 전용 명단·잘못된 설정, 삭제된 근로자, 토큰 발급 후 명단 변경, 실제 gateway 네 경로와 공개 서명 어댑터의 차단을 포함한다.

운영 집계에서 지정 모드 교육은 0건, ID 재선택이 필요한 지정 교육도 0건이었다. 개인정보·교육 내용은 조회하지 않았다. 전체 93개 파일·728개 테스트, verify:fast(타입 검사 포함), 빌드가 통과했고 운영 의존성 감사의 취약점은 0건이었다.

테스트 교육과 등록 테스트 근로자가 아직 없어 운영의 실제 본인 확인·음성 재생·서명 완료는 검증하지 않았다. 음성 버킷 비공개 전환은 이 검증 후 별도로 진행해야 한다.
