# 위험성평가 분석 — 처음 사용하는 사람의 진입 흐름

## 문제와 결정

신규 분석, 재분석, 백업, 연결 점검과 진단 지표가 비슷한 비중으로 노출되어 사용자가 버튼을 찾아다녔다. 기능을 삭제하거나 새 용어를 더하기보다, 사용자가 하려는 일을 첫 화면의 선택 기준으로 삼는다. 기존 PSI/Vercel 프로젝트와 데이터 처리 경로는 유지한다.

| 첫 화면 선택 | 사용자의 상황 | 실제 동작 |
| --- | --- | --- |
| 새 문서 분석 | 아직 분석하지 않은 사진·파일이 있음 | 신규 등록 영역을 펼치고 이동·키보드 초점 연결 |
| 백업에서 이어하기 | 예전 작업을 다시 열고 싶음 | 작은 JSON 불러오기 또는 큰 JSON·PC 보관함 경로 안내 |
| 기존 기록 확인 | 작업 목록에 있는 사람·문서를 찾고 싶음 | 검색과 기록 목록을 펼치고 해당 영역으로 이동 |

## 적용 내용

- 상단의 쉬운 질문과 세 선택지를 먼저 표시한다. 버튼을 누르는 것만으로 OCR을 실행하지 않는다.
- 새 문서는 파일 등록 → 원문·분석 결과 확인 → 수정·저장의 순서를 설명한다.
- 연결 점검·일괄 처리·백업 도구는 기본적으로 접는다. 분석 진행 또는 복원 검사 결과가 있으면 자동으로 펼쳐 상태가 숨지 않도록 한다.
- PC 보관함으로 이동할 때 모바일 상세 모드와 내부 보관함도 함께 펼친다.
- 기록이 없을 때는 새 문서 등록 또는 백업 이어하기를 안내한다.
- 주요 목적지에 처음 작업 선택으로 돌아오는 버튼을 둔다.
- 새 안내는 일반 본문 16px, 보조 설명·버튼 14px 중심으로 구성한다. 모바일에서는 세로로 배치하고 키보드 초점을 이동한다. 동작 줄이기 설정에서는 부드러운 스크롤을 사용하지 않는다.
- 기존 현장 요약·촬영 빠른 메뉴·리포트·검증 기능은 삭제하지 않는다. 유료 분석 승인 정책 및 저장 로직은 변경하지 않는다.

## 확인 범위

TypeScript와 verify:fast, 배포용 빌드 확인. 1440px PC 및 390px 모바일의 신규 등록 이동, 파일 선택 창, 보관함 확장, 기록 검색 확장을 분리된 브라우저에서 검사했다. 외부 API는 차단했으며 실제 OCR이나 사용자 데이터 변경은 실행하지 않았다.

사용성이 좋아졌다는 정량적 인증은 아니다. 실제 처음 사용하는 현장 담당자에게 세 과제를 시켜 도움 없이 찾는지, 잘못 선택하는 지점이 있는지 후속 확인하면 된다. 현재 단계는 로컬 구현이며 배포 상태는 별도 확인한다.
