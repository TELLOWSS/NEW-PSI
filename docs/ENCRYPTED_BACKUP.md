# 암호화 PC 보관함 사용·복원 절차

2026-09-29. 대상은 위험성평가 분석 화면의 **PC 저메모리 보관함**과 `scripts/create-private-local-archive.mjs`이다. 다른 JSON 내보내기, 기존 평문 파일, 브라우저의 운영 자료 전체를 자동 암호화하는 변경은 아니다.

## 새 보관함 만들기

1. 백업에서 이어하기 → 큰 JSON·PC 보관함 열기에서 원본 월별 JSON을 선택한다.
2. 백업용 비밀번호를 12자 이상 입력하고 동일하게 확인 입력한다. 충분히 긴 임의의 비밀번호를 사용하고 원본/보관함과 별도로 안전하게 보관한다. 비밀번호 재설정으로 기존 암호문을 복구할 수는 없다.
3. 새 암호화 PC 보관함 만들기를 누르고 저장할 상위 폴더를 선택한다. 임의의 고유 이름을 가진 새 하위 폴더에 저장하며 기존 폴더는 덮어쓰지 않는다.
4. 보관 완료 후 **전체 복원 검증**을 실행한다. 모든 기록을 한 건씩 복호화하여 해시·JSON 형식을 확인하고 출처 정보를 읽는다. 운영 자료에 자동 합산하거나 유료 분석을 호출하지 않는다.
5. 사용을 마치면 **보관함 잠그기**를 누른다. 목록·원문·폴더 참조를 화면에서 해제한다. 보관함 안의 파일은 분리하지 않고 폴더 전체를 복사한다.

원본 JSON은 변경하지 않는다. 새 보관함을 만들었다고 기존 평문 원본이 암호화되거나 삭제되지는 않는다. 검증 완료만을 이유로 원본을 자동 삭제하지 않는다.

## 다시 열기와 수정본 저장

- 암호화 보관함은 비밀번호 입력 후 보관 폴더 열기를 누른다. 확인 입력은 새 보관함 생성 시에만 필요하다.
- 기존 평문 보관함은 비밀번호 없이 읽을 수 있으며 화면에 암호화 보호가 없다고 표시한다. 암호화를 원하면 원본 JSON으로 새 보관함을 만든다.
- 비밀번호 오류 또는 인증 태그 불일치 시 원문과 목록을 표시하지 않는다. 오류 메시지는 잘못된 비밀번호와 파일 변조를 확정 구분하지 않는다.
- 선택한 기록의 작업본이 있을 때 **수정본 암호화 보관 (1건)**으로 별도의 새 폴더에 저장한다. 두 비밀번호 칸을 다시 입력해야 한다. 편집창에서 아직 저장하지 않은 내용은 포함되지 않는다.
- 입력한 비밀번호는 작업 종료 후 입력창에서 지우며 서버·브라우저 저장소에 저장하지 않는다. 열려 있는 동안에만 복호화 키를 가진 폴더 접근 객체를 메모리에 유지한다. 잠금은 JavaScript 메모리의 물리적 완전 소거를 보장하는 기능은 아니다.

## 저장 형식과 안전 한도

- 공개 설정 파일 `encryption.json`: 형식 버전, 암호 알고리즘, KDF, 반복 횟수, 무작위 salt, 보관함 ID만 포함한다.
- 이름·날짜 목록 `index.json`, 기록 원문/이미지 `records/*.json`, 출처 정보 `source-envelope.json`, 생성 시작 표식도 암호화한다.
- AES-256-GCM과 128비트 인증 태그를 사용한다. 파일마다 새 96비트 IV를 생성하고 보관함 설정과 상대 파일 경로를 인증 데이터에 묶어 파일 교체를 검출한다. [MDN AES-GCM 설명](https://developer.mozilla.org/en-US/docs/Web/API/AesGcmParams)
- 비밀번호에서 PBKDF2-HMAC-SHA256 600,000회와 보관함별 32바이트 무작위 salt로 키를 파생한다. 비밀번호 저장용 OWASP 권고의 작업 비용을 참고한 구현 선택이며 제품 인증을 의미하지 않는다. [OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)
- 원문 1건 32MiB, 기록 10,000건, 목록 8MiB의 기존 한도를 유지한다. 암호문도 크기를 먼저 확인한 뒤 읽는다. 파일 수·파일 크기·폴더 생성 시각까지 숨기는 형식은 아니다.
- 전체 JSON을 한꺼번에 메모리에 올리지 않고 기록 단위로 처리한다. 암호화·Base64 처리를 위한 추가 메모리는 필요하다. 저사양 PC의 총 메모리 상한을 인증한 것은 아니다.

## 실패 시 처리

- 암호화 설정이나 시작 표식만 있고 유효한 완료 목록이 없으면 미완료로 취급한다.
- 취소·디스크 오류·손상 시 원본을 보존한다. 중단된 폴더를 덮어쓰지 않고 새 폴더에 재시도한다.
- `encryption.json` 삭제·변조, 다른 기록으로 교체, 원문 누락은 정상 복원으로 인정하지 않는다.
- 전체 복원 검증은 파일을 읽고 해시와 형식을 확인하는 검사다. 새 운영 DB에 대한 실제 재해 복구 훈련이나 OCR 정확도 인증을 대신하지 않는다.

## 명령줄 도구

`PSI_BACKUP_PASSWORD`를 비밀번호 관리자나 숨김 입력으로 현재 프로세스에만 전달하고 다음 명령을 실행한다. 비밀번호를 명령 인수, 스크립트 소스, 저장소, 로그에 작성하지 않는다. 호출자는 실행 후 환경변수를 제거한다. 도구도 시작 시 전달받은 환경변수를 제거하며 값은 출력하지 않는다.

```text
node scripts/create-private-local-archive.mjs source.json NEW-private-folder
```

보관 폴더는 저장소 밖의 새 폴더여야 한다. 도구는 저장 후 재열기·전체 복호화 검증·원본 해시/크기/수정시간 대조를 수행한다. 검증 보고서도 `verification.json`에 암호화해 저장한다.

## 확인한 범위

- 전체 회귀 검사: 82개 파일의 619개 테스트, 타입 검사, 운영 빌드 통과. 배포 전 의존성 검사 취약점 0건.
- 자동 테스트: 원문·이미지·출처 보존, 비밀번호 오류, 인증 태그 변경, 기록/보관함 교체, KDF 변조, 평문 호환, 취소, 덮어쓰기 방지, 디스크 오류, 경로/크기 제한.
- 브라우저: 합성자료로 암호화 생성·잠금·잘못된 비밀번호 차단·정상 재열기·원문 표시·전체 검증·수정본 암호화 저장 확인. 폴더 선택은 OPFS 대체 경로를 사용했다.
- 명령줄: 3MiB 규모의 합성자료 3건을 실제 임시 폴더에 저장하고 전체 재열기·원본 불변 검증 통과.
- 실제 고객 자료와 운영 DB는 변경하지 않았다. 네이티브 폴더 선택창/외장 디스크/다른 PC에서의 복구 훈련은 별도로 필요하다.
