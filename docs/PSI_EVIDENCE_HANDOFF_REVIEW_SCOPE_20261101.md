# PSI 11차: 증빙 제출 검토 초안과 반출 승인 경계

## 현재 구현
기존 관리자 OCR 원문·번역, 현장 조치, 교육 실천 확인, 8차 ZIP 기능 하단에서 **제출 전 검토서**를 작성한다.

1. 8차 ZIP을 원래대로 다운로드하고 ZIP **전체의 SHA-256**을 별도 승인된 대장에 기록한다.
2. 제안된 제출에 대해 별도 보관 해시를 입력하고 실제 ZIP을 선택해 **파일 무결성**을 검증한다.
3. 확인된 ZIP 속 파일 목록에서 제출 후보 항목을 최소화해 선택한다.
4. 목적·수신 예정 기관·요청 공문/접수번호·검토자·별도 해시 보관 위치·개인정보 유의사항을 작성한다.
5. 로컬 `PSI_handoff_review_*.json`을 저장한다. 이것은 검토 초안이며 **승인·반출·전송 기록이 아니다**.

## 필수 차이
- 검토서를 저장해도 외부 전송, 결재, 반출 승인, 서버 원장 등록, 파일 수정, 개인정보 가림, 법적 증거능력 인증은 일어나지 않는다.
- **파일 선택은 검토 계획만 나타낸다.** 기존 ZIP의 내부 파일은 삭제하거나 줄이지 않는다. 원본 ZIP을 외부 기관에 그대로 보내면 선택하지 않은 개인정보까지 포함될 수 있다.
- SHA-256 입력은 사용자가 별도 보관했다고 **주장한 값과 ZIP을 대조**한 결과다. 대장이 언제 누구에 의해 생성됐는지 자동 확인하지 않는다.
- 최초 사고일 이후에 입력한 원문과 번역은 과거에 같은 값이 존재했다는 증거가 아니다.
- 제출 당사자의 실제 권한, 적법한 자료 제공 범위, 최소 공개·비식별화, 제출형식·보존기간은 별도로 확인해야 한다.

## 운영에서 요구되는 후속 기능 (아직 없음)
- 기업별/현장별 인증된 권한: 제출안 작성자와 승인자 분리, 제출 권한 허용 범위 검증
- 제출사유·요청근거·받는 기관·신원정보 제외 여부에 대한 **서버 심사**
- 저장 불변 이력: 작성 → 수정 → 결재 요청 → 승인/반려 → 안전한 파일 구성 → 실제 전송/인수 확인 → 폐기/보관
- 선택파일만 포함한 새 ZIP 생성, PDF/이미지의 개인정보 실제 비식별화, 기존 ZIP 재발송 방지
- 제출본별 SHA-256, 접근 및 다운로드 로그, 수신확인, 분쟁 처리 이력
- 독립 보관 시점·승인 ID 및 별도 증빙 보전 절차
- 사고/진정 대응의 원문·수정본·사후 자료를 명시적으로 구분한 타임라인

## 출시 단계
- 이번 단계는 **P12 부분 구현(검토서 준비)**만 수행한다.
- 운영 Vercel에 8~11차가 아직 배포되지 않은 한 코드 병합과 무관하게 운영 완성을 주장하지 않는다.
- P03/P04 10차 테넌트 원본 수신 원장은 아직 운영 DB에 적용하지 않았고 기본 비활성화 상태다.
- 가상 레코드와 검증된 샘플 ZIP으로 CI를 수행하고 실제 근로자 자료·외부 제출은 하지 않는다.
