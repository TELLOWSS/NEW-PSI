# 등록 조치 요청·사진 회신 (2026-10-24)

본 사진점검 프로그램의 `등록 조치 → 조치 요청 보내기 · 회신 받기`에서 사용한다. 전송 자체를 완료로 취급하지 않고, 상대의 예정·어려운 사항·개선사진을 원래 조치에 연결하는 기능이다.

## 사용 흐름

1. 미조치 항목에서 공개할 원본 한 장과 링크 유효 시간(1·24·72시간)을 정하고 공개 범위를 확인한다.
2. 카톡 등 운영체제 공유창, 링크·요청문 복사, 위치 표시·QR 카드 중 선택한다. 동그라미·화살표 최대 8개는 전달용 JPEG에만 들어간다. 기기 원본·저장 원본은 수정하지 않는다.
3. 상대는 링크에서 요청 한 건을 확인하고, 응답자·설명을 작성해 조치 예정·조치 어려움·개선사진을 회신한다. 별도 앱·관리자 로그인이 필요하지 않다.
4. 점검자가 접수 상태를 새로 확인하고 전후 사진을 비교한다. 명시적으로 반영하면 `완료 검토 요청`으로 바뀐다. 최종 현장 재점검·승인은 기존 절차에서 별도로 한다.

## 공개·보관 범위

- 링크는 소지자 권한이다. 응답자 이름은 본인 입력이며 신원 인증이나 전자서명이 아니다. 민감정보를 처리한 사진만 공유한다.
- 공유 시점의 조치·담당·기한과 선택한 원본 한 장만 공개한다. 전체 점검 문서·법령·보고서·다른 사진·관리자 세션은 공개하지 않는다.
- 조치의 담당·기한·상태 등 기준 내용이 바뀌거나 원본이 없어지면 기존 링크는 사용할 수 없다. 만료·차단·반영·삭제 중인 점검도 새 열람과 회신을 거부한다.
- 토큰은 URL fragment에 두며 서버에는 해시만 저장한다. 서버가 원본을 직접 전달하므로 외부 수신자에게 Storage 경로나 유효기간이 남은 서명 URL을 발급하지 않는다. no-store/no-referrer/noindex 적용.
- 원본 파일을 중복 업로드하지 않는다. 회신 사진은 브라우저 JPEG 최적화, 긴 변 1280px 이하·1MiB 이하이며 해시·실제 JPEG 크기와 증빙을 서버에서 재검증한다. 기기의 원본은 유지한다.
- 점검당 링크 30개, 링크당 회신 3회·개선사진 1장·서로 다른 업로드 예약 2회. 기존 점검 20장·설치 저장량 900MiB 제한 및 IP/전체/링크 요청 한도를 공유한다. 무료 요금제를 무제한으로 보장하지 않는다.
- 미반영 회신·중단된 업로드도 같은 점검 경로에 저장하여 기존 사진 삭제 절차가 처리한다. 자료 전체 삭제는 공유 기록을 FK cascade로 함께 지운다. 사진만 삭제할 경우 기록은 유지되고 원본 열람·회신은 차단된다.
- 내려받은 카드·회신·캡처·기기 사본과 이미 전송 중인 데이터는 회수할 수 없다. OS 공유창을 열었다고 전송·열람·완료를 추정하지 않는다.

## 구현과 검증

- Supabase migration `20261023110141_inspector_action_share_reply.sql` 적용. 새 테이블 RLS FORCE, 브라우저 역할 무권한, 새 RPC SECURITY INVOKER·service_role 전용.
- API 계약/실제 PostgreSQL(PGlite) 테스트: 공개 범위, 만료·차단·조치 변경, 동일 회신 재전송, 최적화 검증, 예약·수신·명시 반영, 중복 반영, 전체 삭제 cascade. 합성 ID만 사용하며 트랜잭션은 rollback.
- 실제 Supabase: 합성 메타데이터로 명시 반영·동일 요청 재시도, 만료·차단 거부를 짧은 rollback 쿼리로 확인. 긴 통합 쿼리는 MCP requestState 오류로 실행 결과를 확정하지 않았으며 로컬 PostgreSQL 통합 검증과 구분한다.
- Playwright: 실제 빌드 UI + 합성 API 응답으로 관리자 링크 생성·표시 카드·수신자 예정 회신 응답 유실/재시도·사진 최적화/수신·전후 비교·반영·링크 닫힘을 확인. 무효·차단·만료 시 비공개 내용이 나오지 않음을 확인. 320/390/844/1440px 넘침 검사. 이 테스트는 실제 메시지 발송이나 실기기 카카오톡 검증이 아니다.
- 생성 JPEG의 QR을 독립 디코더(zxing-cpp)로 해독하여 회신 URL 일치 확인. 한글 폰트 주입 후 실제 카드/모바일 화면 시각 검수.
- 관리 UI와 카드 편집기는 필요한 때 lazy load. 수신자 페이지는 관리자 앱을 거치지 않는다. object URL·글로벌 이벤트·요청 중 상태 및 입력 레이블을 점검했다.
