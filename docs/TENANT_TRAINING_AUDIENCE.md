# 기업별 근로자 명단과 교육 대상자 연결

2026-09-30. 신규 기업 작업 공간에서 근로자 이름·기업 내 관리번호·직종을 등록하고 교육 초안에 대상자를 지정합니다. 기존 `workers`나 기존 교육 자료는 읽거나 자동 배정하지 않습니다. 이 기능은 초안 준비 단계이며 공개 교육·서명 링크를 발급하지 않습니다.

## 사용 방법과 역할

1. `/saas/access`에서 개인 계정으로 로그인하고 기업을 선택합니다.
2. 기업 책임자(owner) 또는 관리자(admin)가 기업별 근로자 명단에서 등록합니다. 관리번호는 기업 내에서 고유하며 등록 후 변경할 수 없습니다. 이용 중지 상태에서도 번호를 재사용하지 않습니다. 연락처·주민등록번호·비밀번호를 저장하는 필드는 없습니다.
3. 교육 초안에서 대상자 명단 조회를 누르고 이용 중인 근로자를 선택합니다. 조회는 25명씩, 더 보기로 추가 조회하며 한 초안에 최대 200명을 지정합니다. 이름이 같아도 고유 ID로 구분합니다.
4. owner/admin/reviewer는 교육 초안의 대상자를 지정·변경할 수 있고 viewer는 읽기만 가능합니다. reviewer는 근로자 명단을 수정하거나 이용 상태를 변경할 수 없습니다.
5. 저장 시 기업 소속·이용 상태를 다시 확인합니다. 이용 중지된 근로자가 기존 초안에 남아 있으면 수정이 거부되므로 지정을 해제하고 다시 저장합니다. 명단이 아직 조회되지 않았어도 이미 저장된 지정 ID는 보존합니다.
6. 등록 재시도에는 같은 요청 UUID를 사용하고 수정에는 예상 버전을 사용하여 중복·동시 변경을 방지합니다. 기업 변경·로그아웃 시 열린 명단과 초안 입력을 폐기합니다.

## 보관과 권한

추가 마이그레이션 `20260930020000_tenant_training_audience.sql`은 tenant identity foundation과 training drafts 이후 한 번 적용합니다. 근로자 명단·원문 이력의 새 테이블에 FORCE RLS와 기업별 복합 키를 적용하며 사용자 토큰으로 요청합니다. 명단과 초안의 변경 이력은 같은 트랜잭션으로 저장합니다. 인증된 사용자의 직접 이력 수정·삭제는 금지합니다.

초안의 `worker_ids`는 동일 기업의 이용 중인 근로자만 허용하는 DB 트리거로 검사합니다. 검토자에게 명단 수정 권한을 주지 않고도 이용 중지와 대상자 선택을 직렬화하기 위해, 검증 트리거는 실제 사용자의 활성 기업 소속·교육 편집 역할을 먼저 확인한 뒤 그 기업의 선택된 행만 잠급니다. 빈 search_path와 정규화된 테이블 참조를 사용하고 함수의 직접 실행 권한은 부여하지 않습니다. API를 우회한 사용자 토큰 요청도 이 검사를 거칩니다.

기존 초안과 이력에 추가된 대상자 목록의 기본값은 빈 배열입니다. 기존 현장 자료나 근로자 이름으로 대상을 추정하지 않습니다. 새 `/api/saas/access?resource=workers` 경로는 기존 SaaS 함수 안에서 처리하므로 전체 서버리스 함수는 4개입니다. 자동 조회·반복 폴링은 추가하지 않았습니다.

## 검증과 남은 범위

- 전체 102개 테스트 파일 / 860건 통과, verify:fast(타입 검사 포함)·Vite 빌드 통과, production 의존성 취약점 0건.
- PGlite의 실제 PostgreSQL 정책 검증: 두 기업 양방향 격리, 조회자·검토자의 명단 수정 차단, 관리자 수정, 중복 관리번호, 소속 중지, 이력 위조·삭제 방지, 감사 저장 실패 시 롤백, 대상자 버전 충돌, 다른 기업·이용 중지·중복 ID 차단, 검토자 대상자 연결 허용.
- 운영 Supabase에 추가 구조 적용 후 롤백 검증: 기업 간 격리, 검토자 지정, 다른 기업·이용 중지 대상 차단, 버전 및 대상자 이력 통과. 임시 기업·계정 모두 0건으로 롤백 확인.
- 로컬 브라우저에서 예시 자료로 선택·저장·재수정·대상 해제·이력·이용 중지 표시와 역할별 화면을 확인했습니다. 콘솔 오류는 없었습니다. 이 검증은 메모리 예시 응답을 사용했으며 실제 운영 계정의 Auth→API→DB 저장 흐름을 완료한 검증은 아닙니다.

실제 기업 계정 및 테스트 근로자 자료가 아직 없어 운영 환경의 로그인부터 명단 등록·대상 지정까지 이어지는 실사용 검증은 남아 있습니다. 다음 범위는 기업별 공개 교육 배포·대상자 본인 확인·만료/철회 가능한 접근 경계입니다. 기존 교육/근로자 이관, 번역·음성, 이수·서명 전환과 공용 SaaS 출시 게이트는 유지합니다.
