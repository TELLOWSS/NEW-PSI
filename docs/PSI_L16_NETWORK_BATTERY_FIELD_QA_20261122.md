## A. 현장 사용 시 구분해야 할 사실

| 표시/측정 | 확인된 사실 | 확인되지 않는 사항 |
|---|---|---|
| 브라우저 온라인/오프라인 신호 | `navigator.onLine`의 현재 상태 및 `online/offline` 이벤트 | 실제 현장 LTE/5G 속도, DNS·방화벽·서버 정상 응답, 로그인 및 수신 |
| '이 기기 오프라인 준비' 검증 | SW 메시지 `VERIFY_LOCAL_ASSETS`가 캐시에 필요한 셸 파일 존재를 확인 | 사진과 메모의 영구 보존, 배터리, 다른 PSI 메뉴의 오프라인 지원 |
| 사진·메모의 브라우저 저장 확인 | 기존 IndexedDB 원본/해시 재조회 테스트에 따라 브라우저 프로필 저장소로 기록 | 회사 서버 접수·관리자 열람/조치 승인, 브라우저 데이터 삭제/기기 분실 시 복구 |
| 150ms 합성 응답 지연 Chromium | 인위적 문서 요청 지연 후 진입, 오프라인 전환/복귀 자동 회귀 | 실제 3G 속도·전파 강도/음영·기기 발열·배터리 소모 수치 |
| 재연결 후 자동 API 0건 | 해당 합성 시나리오에서 자동 업로드/AI 호출을 관측하지 않음 | 다른 메뉴 또는 사용자 직접 공유 행동까지 API 0으로 일반화 |

## B. L16 코드 범위

- 기존 `field-local/main.tsx`: 브라우저 신호 변화만 수신하여 안내하고, API ping/재시도 폴링/자동 동기화/로그 업로드를 구현하지 않는다.
- 신규 `tests/psiL16ResilienceContract.test.ts`: UI·권한/수신 상태 독립성·자동 외부 요청 부재·테스트 연결을 검증.
- 신규 `scripts/verify-psi-l16-resilience.mjs`: 독립 브라우저 프로필과 합성 사진 1장, 수동 오프라인 준비, 비행기 모드 대리인 `context.setOffline(true)`, 오프라인 재실행/사진+메모 저장/재조회, 온라인 신호 복귀·API 자동 전송 0 테스트, 시나리오별 소요시간/자원 개수의 **참고값** 기록.
- 전사 Chromium QA 단계에 신규 시나리오를 추가하고 합성 결과 JSON만 artifact로 보존. 실제 사진/실근로자 개인정보/현장 문서 전송 없음.
