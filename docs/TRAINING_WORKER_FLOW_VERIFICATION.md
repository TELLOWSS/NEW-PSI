# 근로자 교육 및 서명 검증

2026-09-30. 근로자는 교육 링크에서 본인 확인을 하고, 지정 교육자료를 열람한 뒤 이해 확인과 서명을 제출한다. 관리자에게는 교육 기록과 이해 확인 기록이 함께 저장되어야 한다.

검증 중 교육자료 조회는 검수 상태를 확인하지만 공개 서명 제출은 확인하지 않는 차이를 발견했다. 두 경로가 같은 서버 검수 함수를 사용하도록 개선했다. 검수 전·누락된 음성·손상된 검수 정보는 자료 조회와 서명 모두 422로 차단한다. 검수한 교육에서 선택하지 않은 언어나 빈 언어로 서명할 때도 저장하지 않는다. 조회 후 검수 상태가 철회되면 제출 시 다시 확인한다. 검수 정보가 없는 과거 교육과 관리자 대리 서명의 기존 계약은 유지한다.

| 경계 | 검증 범위 | 근거 |
| --- | --- | --- |
| 운영 브라우저 진입 | 누락 링크 차단 확인 | 교육 링크 정보가 없는 합성 세션 주소에서 새 QR 링크 요청 안내 표시. 브라우저 오류 기록 없음 |
| 본인 확인 → 인증 토큰 | 자동 검사 통과 | 테스트에서 본인 확인 경로가 발급한 토큰을 이후 요청에 사용 |
| 인증 토큰 → 자료·음성 주소 | 자동 검사 통과 | 지정 ID 확인, 서명 음성 주소 발급, 최대 5분, 인증 만료 차단 |
| 공개 서명 → 저장 요청 | 자동 검사 통과 | 서버의 근로자 이름·국적 사용, 본인 서명 방식, 원본 PNG의 SHA-256과 비공개 파일 위치 확인 |
| 저장 실패 → 파일 정리 | 자동 검사 통과 | 저장 함수 누락·오류·중복 시 새 파일만 제거하고 기존 증빙 보존 |
| 실제 저장 SQL → 기록 | 로컬 PostgreSQL 검사 통과 | 저장소·테이블을 분리된 테스트 DB에 구성하고 저장 SQL 원문 실행. 일반 역할 호출 금지, 서버 역할 성공, 중복 차단, 이해 확인 실패 시 서명 기록도 취소 |
| 운영 브라우저 → 실제 재생·서명 완료 | 미검증 | 테스트 교육·등록 테스트 근로자가 아직 없음 |

tests/trainingWorkerFlow.test.ts는 네트워크를 사용하지 않는 합성 근로자·교육·PNG 자료와 DB/스토리지 대역을 사용한다. tests/trainingSignatureTransaction.test.ts는 PGlite에서 실제 PostgreSQL 저장 함수를 실행한다. 두 검사는 운영 Supabase 저장이나 브라우저의 실제 음성 재생을 검증한 것이 아니다. 운영 DB·기존 교육·파일·버킷 공개 설정을 변경하지 않는다. 서버리스 함수는 4개 구조를 유지한다.

전체 회귀 검사에서 95개 파일·743개 테스트와 verify:fast(타입 검사 포함), 빌드가 통과했다. 공개 서명 제출은 검수 자료 조회에서 얻은 보호사건 ID를 함께 사용하여 별도의 중복 조회를 추가하지 않는다.

의존성 재감사에서 brace-expansion 2.1.4의 서비스 거부 취약점이 확인되어 기존 2.x 호환 범위에서 2.1.7로 갱신했다. package.json의 override 최소 버전을 올리고 lockfile의 해당 패키지 한 건만 변경했다. 갱신 후 운영 의존성 감사의 취약점은 0건이었다. 근거는 [CPU 자원 소모 취약점 공지](https://github.com/advisories/GHSA-q2hr-2g5m-vwhr), [중첩 재귀 취약점 공지](https://github.com/advisories/GHSA-qhr7-859c-m2p7), [파싱 재귀 취약점 공지](https://github.com/advisories/GHSA-6j4f-fj2g-mc7p)다.

운영 재생·서명 확인은 분리된 테스트 환경에 테스트 근로자와 지정 교육을 준비한 뒤 진행한다. 대상자를 선택하고 모든 교육 언어의 검수를 완료한 후 화면에서 발급한 링크로 본인 확인, 자료 열람·음성 재생, 이해 확인, 서명 제출과 중복 제출 차단을 확인한다. 관리자 교육 현황의 이수·이해 확인 기록을 대조하고, 비대상자·삭제 근로자·만료 링크의 차단도 확인해야 한다. 이 검증을 완료하기 전에는 음성 버킷을 비공개로 전환하지 않는다.
