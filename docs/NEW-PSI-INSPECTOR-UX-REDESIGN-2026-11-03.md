# NEW-PSI 사진점검 UX/UI 재설계 기획서 · Design System R66–R69
> 2026-11-03 · 개발 기획/인수기준 · 현장사진점검 전용 · SMART TBM과 별개

## 1. 현행 구조 진단 — GitHub 개발본 코드 검토 기준
- `SafetyInspector`는 `InspectorQuickWorkspace`(간편)·`InspectorAdvancedWorkspace`(상세)·`InspectorLocalDraft`(기기 자체 점검)의 세 경로로 구성되어 있다.
- 간편 화면의 상단 사진 선택, AI 선택·비용 안내, 동의, 수동 점검, 아래쪽 별도 `<details>` 오프라인 점검으로 주요 행동이 분산돼 있다.
- 기존 CSS 파일(`inspector.css`, `inspector-experience.css`, `inspector-quick.css`, `inspector-collab.css`)에 여러 시대의 스타일이 누적됐다. 다른 스타일이 주동작보다 강조되는 것을 줄여야 한다.
- 기기 점검은 필수 단계, 보관 안정성, 재점검, 전문가 이력이 하나의 긴 문서에 있어 가독성이 약하다.
- **확인 범위**: 저장소의 소스 및 GitHub 합성 Chromium QA. 실제 사용자 기기 렌더링과 현장 사용성 인터뷰를 수행했다고 주장하지 않는다.

## 2. 디자인 콘셉트 — FIELD CANVAS
**브랜드 메시지**: “발견은 빠르게, 확인은 끝까지.”  
**정보 구조**: 사진 → 확인한 사실 → 조치/담당/다음 확인 → 관리용 보고서. 간편 사용자에게는 다음 행동을 하나만 주로 보여준다.

시각 언어
- 절제된 진한 잉크 네이비 + 청록 포인트, 안전 위험은 어조·아이콘·텍스트로 설명; 빨간/초록을 규제 확정처럼 쓰지 않음.
- 밝은 인쇄물 같은 배경, 선명한 타이포그래피, 낮은 장식 밀도. 과도한 그라디언트·카드 중첩·반복 경고 문단 축소/단계별 배치.
- 외부 폰트/이미지/런타임 API 자원 추가 금지. 시스템 폰트와 순수 CSS를 써 오프라인 성능과 비용 보존.
- 숫자·날짜·상태는 고정폭 숫자, 가독성 최소 14px, 입력 최소 16px, 터치 목표 최소 44px, 명확한 포커스 표시, `prefers-reduced-motion` 지원.

## 3. PC/태블릿/모바일 화면 설계
### 3-A 간편점검 — 행동 우선
1. 짧은 편집형 히어로: 제품 이름, 한 문장 가치, 외부 AI 비용/오프라인 모드 구분, 첫 화면/상세 관리 버튼.
2. 두 가지 명확한 진입: **사진점검 시작**(현재 입력 화면) / **통신 없는 기기 점검 열기**(기존 접힌 영역을 실제 열고 이동). 텍스트 링크만으로 접힌 영역을 이동한다고 주장하지 않음.
3. 사진 선택/촬영을 첫 번째 큰 패널로, 점검자 의견/AI 사용 여부/동의/시작을 두 번째 패널로 구성. PC는 2열, 모바일은 단일 열.
4. 업로드/보관/수동 작성/AI 유료 가능성은 기존 로직과 동의 게이트 그대로 보존. 정책·한도 불명확 시 유료 API 자동 호출하지 않음.
5. 결과·조치·보고서는 기존 시나리오와 연결, 저장하지 않은 입력에 대한 이동 경고 유지.

### 3-B 기기 자체 점검 — 작업 순서/복구 구분
- “사진”, “관찰·조치”, “기기 저장” 3단계 바로가기를 눈에 보이는 안내 레일로 제공.
- 작성 중 백업·복구는 사고/실패/요청 시 펼침. 급박한 위험의 접근통제·작업중지 필요성은 축약된 분명한 문구로 계속 노출.
- 기기 저장/보고/인계 부분은 각각 시각적으로 구획하고, 임시 체크는 수신·조치 증거가 아님을 유지.
- 기존 사진·입력·증빙·용량·이력·오프라인 복구를 삭제하지 않는다.

### 3-C 상세 관리
- 간편과 같은 브랜드 토큰/배경/카드 라운딩과 동일한 탭 선택·초점 상태. 데이터 테이블이나 보고서 인쇄 CSS는 별도 보호.
- 다건 관리 흐름에서 정보 밀도는 유지하면서 우선순위와 위험 안내를 명확히 분리한다.

## 4. 반응형 인수 기준
- 390×844, 360×800, 768×1024, 1280×800 이상에서 가로 스크롤 없이 주요 입력·버튼을 사용.
- 2열 폼은 800px 이하 1열. 주요 버튼 최소 44px; 모바일 고정 패널이 내용을 가리지 않음.
- 화면 전체 확대/다크 모드/키보드 포커스/모션 감소 환경에서도 정보가 잘리거나 숨겨지지 않음.
- 인계 복사·다운로드·재점검 체크의 IndexedDB 원본 검증, 사용자 동의, 오프라인 사용성은 UI 업데이트 후에도 같은 결과를 내야 함.

## 5. 개발 배치/검증/배포 게이트
- **R66**: 새 작업 화면 히어로/입구 카드, 펼침 상태와 실제 스크롤 연결.
- **R67**: 전용 `inspector-refresh.css` 디자인 토큰·모바일 레이아웃·다크/접근성·인쇄 분리.
- **R68**: 기기 점검 3단계와 F10 인계/재점검의 읽기 쉬운 위계(기능·안전 문구 변경 없음).
- **R69**: 타입·빌드·기존 inspector mobile Chromium·F10 300건 매트릭스·제품전체 QA, 새 디자인 계약/진입 이동 시험.
- Preview/Production 배포를 남발하지 않고 **검증 통과 후 단일 Production 후보**로만 진행. Vercel Hobby 잔여 한도를 확인할 수 없다면 자동 배포 금지, GitHub Draft에 누적.
- `main` 반영은 reviewed SHA/검증결과/배포 대상 일치 확인 후에만. Production 배포 후 alias READY·커밋 일치 및 사용성 스모크를 확인.
- **현장 검증 잔여**: Android/Samsung Internet 실기기 사진 촬영, 권한 거절, 브라우저 종료·오프라인 재실행, 파일 다운로드/클립보드, 실제 수신 확인. 자동 QA는 이를 대신하지 않음.

## 6. 제외
실제 법령/벌금 자동 확정, 사진만으로 위험 해소 판정, 실제 수신 증명, 자동 작업재개 승인, 외부 모델 유료 호출, SMART TBM 기능 통합, 기존 데이터 삭제/스키마 파괴는 포함하지 않는다.
