# 기업별 개인 계정 교육 배포

새 SaaS 교육은 `/saas/access`에서 근로자 명단 → 개인 교육 계정 관리 → 교육 초안 대상 지정 → 배포 관리 순서로 준비한다. 근로자는 `/saas/education?releaseId=…&workerId=…`에서 관리자가 연결한 개인 계정으로 로그인한다. 링크의 식별자만으로는 권한을 얻을 수 없다.

배포 목록에서 ‘대상자 이름·링크 확인’을 누르면 해당 기업의 현재 근로자 이름과 관리번호를 조회한다. 동명이인은 관리번호로 구분하고 각 근로자의 링크 복사 버튼으로 전달할 주소를 복사한다. 이용 중지된 근로자는 링크를 표시하지 않는다. 이 이름 표시는 배포 당시 이름의 증빙이 아니라 현재 명단 기준이며, 실제 열람 권한은 서버에서 다시 검증한다. 명단은 페이지 진입 시 자동 조회하지 않는다.

## 운영 조건

- 관리자는 본인 확인을 완료한 근로자에게 이미 발급된, 이메일 확인을 마친 개인 계정을 연결한다. 계정 발급·초대 메일·비밀번호 변경은 이 기능에 포함하지 않는다.
- 기업 책임자·관리자만 계정을 연결·중지하거나 교육을 배포·철회한다. 검토자·조회자는 배포 목록만 조회한다. 계정 이메일은 책임자·관리자만 조회한다.
- 모든 지정 대상자가 이용 중이어야 하며 각자의 계정 연결이 필요하다. 한 기업 내 동일 계정을 여러 근로자에게 연결하지 않는다.
- 교육은 저장된 초안의 특정 수정 번호를 배포한다. 원문·현장·제목·대상자 식별자를 별도 보관하며 기본 24시간, 최대 168시간 동안 열람을 허용한다.
- 초안 수정, 명단 이용 중지, 계정 연결 중지, 계정 이메일 변경·정지·삭제, 배포자 권한 상실, 만료·철회는 다음 열람 요청부터 차단한다. 이미 화면에 표시된 내용의 회수는 보장하지 않는다. 자동 조회·주기적 재조회는 하지 않는다.
- 현재 범위는 한국어 교육 자료 열람이다. 번역·음성·서명·이수 기록 기능은 포함하지 않는다. 기존 단일 현장 교육과 별개이며 공유 SaaS의 기존 교육 진입 차단은 유지한다.

## 구현과 적용

`20260930030000_tenant_education_release.sql`은 계정 연결·교육 배포·각 변경 이력 테이블을 추가한다. 이전 세 가지 기업/교육 마이그레이션 적용 후 실행한다. 실행 전 대상 프로젝트와 `auth.users`의 `email`, `email_confirmed_at`, `deleted_at`, `banned_until` 열을 확인한다. 기존 고객 기록이나 계정은 자동으로 연결하지 않는다.

테이블은 FORCE RLS와 읽기 전용 클라이언트 권한을 적용한다. 쓰기는 실제 호출자의 기업 관리자 자격을 확인하는 전용 함수로 제한하며, 변경과 이력 기록은 같은 트랜잭션에서 수행한다. 근로자는 기업 구성원 권한 없이 자신의 지정 교육만 좁은 조회 함수로 읽는다. 모든 사용자 요청은 검증된 개인 토큰을 사용하며 서비스 키로 대체하지 않는다.

요청은 기존 `/api/saas/access`의 `worker-accounts`, `education-releases`, `worker-education` 분기로 처리하므로 서버리스 함수는 4개를 유지한다. 입력 크기·유효기간·수정 번호·식별자를 검증하고 서버 오류의 내부 내용은 응답에 포함하지 않는다. 로그인 정보는 메모리에만 보관하며 기업·계정 변경 및 화면 종료 시 대기 중 요청을 취소한다.

## 검증 범위와 배포 상태

로컬 PostgreSQL 호환 엔진에서 실제 SQL을 실행해 권한·명단·계정 상태·만료·철회·수정 충돌·이력 실패 시 원자적 롤백을 검증한다. 요청 경계와 화면의 역할별 제어도 테스트한다. 화면 동작 검증에는 실제 저장 없이 임시 예시자료를 사용한다.

2026-10-01에 지정 프로젝트 `dpnmslogvwuzmighsgnt`에 신규 SQL 적용을 완료했다. 실제 DB에서 트랜잭션 내 예시 계정·교육으로 본인 자료 열람, 다른 계정 차단, 철회 후 차단, 배포 이력을 검증하고 전부 롤백했다. 잔여 테스트 기업과 계정은 각각 0건이다. RLS와 클라이언트 쓰기 제한도 별도로 확인했다.

GitHub CI에서 타입 검사·전체 테스트·보안 감사·빌드가 통과했고 Vercel 미리보기의 HTTP 회귀 검사 41건이 통과했다. 실제 개인 계정과 테스트 교육이 없으므로 운영 로그인 → 교육 열람 흐름은 아직 검증하지 않았다. DB의 역할별 검증은 실제 사용자 로그인 검증을 대신하지 않는다.
