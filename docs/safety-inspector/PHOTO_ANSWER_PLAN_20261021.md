# 사진 한 장에서 문제·조치·근거를 바로 읽는 개선

작성일: 2026-10-21. 대상: 기본 사진점검 화면. 기존 기록·해시·삭제·승인·외부 전송 경계 유지.

## AI 결과와 기록의 경계

- API content v2는 기존 6개 배열과 `risk_findings` 배열을 반드시 반환한다. 각 문제는 실제 관찰 배열의 인덱스 문자열과 문제·가능 위험·조치·우선순위를 가진다. 인덱스 대상이 없으면 결과를 거부한다. 최대 3개, 문제 근거가 없으면 빈 배열. 법적 위반·벌금·현장 밖 부재를 확정하지 않는다.
- 저장 계약 1.1의 하위 호환 확장으로 `risk_findings`는 선택 필드다. 기존 수동 JSON·과거 분석·보고서는 유효하며 신규 문제를 소급 생성하지 않는다. 공급자 스키마·서버 입력·정적 CSP validator 모두 같은 구조를 검증한다.
- 키를 브라우저에 노출하지 않는다. ON/OFF와 실행 동의·기존 20회 한도·중복 요청 방지 유지. 화면 탭 전환·사례 조회는 외부 AI 호출이 없다. 알려진 실패 후 다음 사용자 클릭에서만 새 시도, 자동 재시도 없음.
- 새 보고서에 문제별 해석과 당시 연결한 감독사례를 저장해 해시에 포함한다. 과거 보고서의 법령·사례는 바꾸지 않는다.
- 법령 원문 검토일은 기존 2026-10-20을 유지한다. 2026-10-21에 제168조·규칙 제43조를 재대조했지만 전체 법령을 재검증했다고 날짜를 바꾸지 않는다. 과거·미래 적용과 실제 부과액은 별도 확인 대상이다.

## 검증 기준

- 유효 관찰 연결/없는 인덱스 거부, 공급자 7개 필수 배열, 구형 계약 허용, 개별 금액 비생성, 관련 사례 필터·복제 격리.
- production 번들·운영 CSP에서 촬영/붙여넣기/OFF/미연결/실패 재시도/보고서 재시도/사진 없는 조회.
- 핵심 문제·위험·조치 노출, 법령 1개 주제 표시, 감독사례 전환과 키보드, 입력 접힘, 모바일 저장 바·320/390/768/1440px 넘침, 보고서 사례·사진·인쇄.
- 운영 배포 후 합성 자료 1건으로 실제 공급자 1회 요청과 저장·보고서·해시 확인, 임시 자료 전체 삭제 및 기존 합성 검증 기록 불변 확인. 실행 결과는 PR와 검증 기록에 별도 기록한다.
