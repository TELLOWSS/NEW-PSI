# 실제 사진점검: 선택한 위험에서 조치 등록까지 연결

## 발견한 문제

결과의 위험 선택과 조치 작성 진입이 분리되어 있었다. 한 사진에 개구부와 전선 위험이 있으면 두 번째 전선 위험을 보고 있어도 사진 전체의 첫 제안 또는 우선 제안이 작성 화면에 들어갈 수 있었다. 현재 선택한 위험과 작성하려는 조치가 어긋나지 않도록 본프로그램을 변경한다.

## 구현

위험 선택 번호를 실제 간편 워크스페이스에서 관리해 핵심·법령·사례 탭과 조치 진입이 같은 선택을 사용한다. 단순 검토 저장으로 서버 문서 객체가 바뀌어도 선택을 유지한다. 다른 사진·새 결과·AI 수용 여부 변경 때는 첫 위험으로 초기화한다. 공개 참고 컴포넌트의 기존 자체 선택 동작은 유지한다.

핵심 답변 아래 `사진 검토 저장 · 이 위험 조치 작성`을 추가한다. 기존 사진 조치 진입도 구체적인 위험이 있는 경우 현재 선택을 사용한다. 버튼 설명에는 사진 전체의 검토 선택과 의견을 함께 저장함을 명시한다. 사진별 검토를 위험 한 건만의 승인으로 표현하지 않는다.

기존 저장·confirm-photo와 응답 유실 복구가 성공한 저장 문서에서 선택 번호와 조치 문구를 다시 찾는다. 동일 문구 그룹이 있더라도 현재 사진이 출처에 포함되어야 한다. 선택 번호 누락·범위 오류·이전 형식·변경된 분석에서 임의 첫 조치로 대체하지 않는다. AI 미수용 또는 별도 전문가 의견이 저장된 경우 전문가 문구를 우선하며, 원래 AI 위험 문구는 작성 출처에서 제외한다.

작성 화면은 선택한 위험 번호·문제 또는 전문가 의견 우선 상태를 표시한다. 제안을 직접 바꾸면 원래 선택 출처 표시는 숨긴다. 처음에는 이 사진 하나만 선택하고 담당·기한과 적용 범위 확인은 비워 둔다. 사용자 확인 전 등록은 하지 않는다. 기존 30건 제한·중복 검사·저장 충돌 처리·닫기 시 미저장 입력 보호·미조치 상태 등록을 유지한다. 선택 번호·출처 안내는 현재 화면 메모리만 사용하며 문서 스키마·기존 고정 보고서는 변경하지 않는다.

## 검증

순수 테스트: 두 번째/낮은 우선순위 위험의 정확한 문구, 사진 범위, 문서 불변성, AI 미수용과 수용 후 별도 의견의 전문가 우선, 잘못된 번호/미검토/이전 형식에서 임의 대체 금지.

실제 본기능 컴포넌트를 합성 API와 연결해 선택 위험 버튼·기존 진입 버튼·전문가 의견·미수용·검토 저장 실패·검토만 저장 후 선택 유지·작성 닫기 취소 7개 시나리오를 검증한다. 선택 조치·출처 사진·빈 담당/기한·명시 적용 확인·미조치 등록과 고정 보고서의 등록 조치까지 추적한다. 사진 업로드/AI 분석 횟수가 추가되지 않아야 한다. 320/390/844 가로/1440 폭을 확인한다. 실제 고객 기록을 쓰거나 유료 AI를 호출하는 검증이 아니며 실기기 검증과 구분한다. CI/운영 배포 근거는 PR에 남긴다.
