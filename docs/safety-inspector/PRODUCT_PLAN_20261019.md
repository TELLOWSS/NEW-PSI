# NEW-PSI SAFETY INSPECTOR — 완성작 제품·구현 계획 v1.2

작성 2026-10-19 / 기준 인계자료 v1.1 / 실제 저장소 TELLOWSS/NEW-PSI

## 제품의 완성 모습

현장사진을 기록하는 것으로 끝나지 않는다. 안전관리자의 설명과 사진의 관찰을 대조해 '확인한 사실'을 만들고, 공식 원문에 근거한 현재 의무와 미래 준비사항을 구분하여 개선을 배정하고, 현장 재점검으로 조치를 확인한 뒤 그 판단 근거를 재현 가능한 보고서에 남긴다.

NEW-PSI의 위험성평가·6대 예방지표에 연결되는 신규 모듈이다. SMART TBM은 별도 프로그램이며 승인된 비식별 교육자료만 별도 계약으로 내보낸다. 게임 저장소 psi-zero-day와는 다른 제품이다.

완성작의 핵심은 **관찰 → 검토 → 근거 → 조치 → 재점검 → 증빙**의 단절 없는 흐름이다. 보기 좋은 화면과 함께, 무엇을 알고 무엇을 아직 모르는지가 명확해야 한다.

## 제공 자료의 해석

- 마스터 기획서·비용 설계·JSON 계약·인수시험: 제품 요구사항의 기준선.
- 자기규율 기록지: 위험작업·위험요인·잠정 위험등급·예방조치·실천약속의 다섯 문항, 공종·교육일·작성자. 다국어/필기는 별도 정답셋 평가가 필요하다.
- SMART TBM 활용 자료: 자료·사진/동영상·작업내용·위험·담당 검토·출력의 업무 연결을 참고한다. UI·데이터 통합의 근거로 사용하지 않는다.
- 특허청 안내 자료: 기존 출원·청구범위 제출 관련 행정자료이며 신규 모듈의 권리 확보나 특허 등록을 입증하지 않는다. 개인정보 포함 원본은 공개 저장소에 넣지 않는다.

## 최종 화면 설계

화이트·네이비를 기본으로 청록색은 진행/검토, 긴급 위험에만 적색을 쓴다. 메인 메시지는 '현장을 읽고, 개선까지 연결하다.' 모바일은 단일열과 가로 스크롤 단계 선택, 태블릿·PC는 기록 목록과 작업실의 두 영역으로 구성한다. 빈 화면을 가상 수치로 채우지 않는다.

| 화면 | 완성작의 주요 경험 | 첫 구현 |
|---|---|---|
| 점검 대시보드 | 긴급·검토대기·지연 조치·법령 준비 신호 | 불러온 최근 점검과 실제 미결 조치 집계 |
| 사진·설명 | 촬영·위치·공종·시점·설명, 원본과 주석 분리 | 원본 업로드·서버 해시·설명 수정 이력 |
| 관찰·사실 검토 | 사진·진술·AI 추론·미확인을 대조, 질문별 답변/수정 | 수동 JSON 대조·검토 수용/반려·사유 |
| 법령·사례 | 현행/공포예정/입법추진/과거, 제재 구분 | 상태별 안내와 공식 홈페이지 링크. 검증 완료 표시는 없음 |
| 개선·재점검 | 담당·기한·수락·전후 사진·재점검·반려·재개 | 배정·개선사진·완료 검토 요청·관리자 확인 |

## 데이터와 인증 설계

첫 단계의 실제 사용자는 전용 설치 관리자다. 현행 공유 세션에는 개인 식별자가 없으므로 모든 감사 주체는 `dedicated-admin`이며 개인 전자서명으로 표현하지 않는다. 여러 현장을 서로 다른 사용자에게 분리 제공하는 기능은 첫 단계에 포함하지 않는다. 이를 위해 shared-saas 모드에서는 API를 아예 거절한다.

신규 테이블 `psi_inspector_inspections`, `psi_inspector_evidence`, `psi_inspector_events`, `psi_inspector_reports`와 비공개 Storage `psi-inspector-evidence`를 사용한다. public 스키마 테이블 모두 RLS+FORCE RLS, anon/authenticated 권한 없음, 서비스 역할은 서버 인증 이후에만 사용한다. Storage의 기존 광범위 정책이 새 버킷을 열지 못하도록 restrictive 정책을 적용한다.

기업형 출시 전에는 `tenant_id + site_id` 복합키, 사이트 membership, 담당 협력사 범위, 역할별 정책으로 별도 마이그레이션하고 양방향 격리 시험을 한다. 전용 설치 데이터를 임의 tenant에 자동 이관하지 않는다.

사진의 SHA-256은 서버에서 원본 바이트로 계산한다. 사진ID는 재시도 키로 쓰고 다른 원본으로 덮어쓰지 않는다. 원본은 3MB/장·20장/점검이며 기존 사진이 점검 문서에서 사라지지 않도록 검증한다. 고해상도 다중사진·동영상·정식 주석·비식별 편집은 M7의 직접 업로드 세션으로 확장한다.

모든 점검 변경은 예상 revision을 검사한다. DB 트리거가 revision과 당시 document를 같은 트랜잭션으로 보존한다. 감사 append 실패 시 업무 변경도 롤백한다. 사진·보고서·감사로그에는 클라이언트 UPDATE/DELETE 권한이 없다.

보고서는 점검 버전·증거 메타데이터·미해결·법령 검증 상태·생성시각을 JSON 스냅샷으로 고정한다. SHA-256은 객체 키를 정렬한 안정적 JSON 직렬화 바이트로 계산하므로 JSONB 저장 후 키 순서가 달라져도 재검증할 수 있다. 배열 순서는 증거 순서로 보존한다.

## AI·OCR 비용 원칙

- 신규 모듈의 유료 AI 및 유료 자동 대체는 꺼짐. 실행 API도 거절한다.
- ChatGPT 사용자는 자신의 대화창에서 직접 사진을 첨부한다. 프롬프트/결과 JSON만 복사하며 쿠키·계정·토큰을 수집하지 않는다.
- 표준 계약의 추가 필드·스키마·점검ID·사진ID·해시를 브라우저와 서버 모두 검사한다. 가져온 값은 관찰 제안이며 법적 근거/완료 승인으로 자동 승격되지 않는다.
- Tesseract.js 6.0.1은 문자인식 전용 PoC. worker·WASM·언어팩은 lockfile의 npm 패키지에서 배포 시 복사하고 실행 중 같은 출처에서만 읽는다. 이미지 바이트는 외부 AI로 전송하지 않는다.
- 한국어·영어·베트남어·중국어 간체의 네 언어가 초기 대상. 원문/정정문/검수 상태를 따로 기록한다. 11개 언어 완성·손글씨 정확도를 주장하지 않는다.
- 로컬 인식 실패 시 수기 정정·수동 브리지로 진행한다. 기존 PSI OCR 경로를 이번 변경으로 교체하지 않는다. COST-11 동등성 비교가 끝난 뒤 전환한다.
- SIWC는 이번 배포의 구현 대상이 아니다. 공식 적격성·지원 환경·승인과 현행 조건을 확인한 뒤 별도 로컬 실증으로 시작한다.

## M2~M4 법령지능의 완성 기준

법령의 키는 `법령ID + 조문 + 공포번호 + 조문 시행일 + 부칙 버전`이다. 점검시점·사건시점·미래 검토시점을 나누고 의무와 제재의 발효일을 따로 평가한다. 적용요건은 사업장 규모·공사금액·업무·채용 등 해당 규정의 요건에 한해서만 사용한다.

| 분류 | 저장·검증 | 출력 규칙 |
|---|---|---|
| 현재 시행 | 조문·부칙·효력일·대상요건·검증시각 | 확인된 범위의 현재 의무 |
| 공포·시행예정 | 공식 공포·확정 시행일·분리 시행 조항 | 미래 준비사항, 현재 위반과 분리 |
| 입법추진 | 예고·심의 단계·수정/철회 | 미확정 정보, 처벌 확정 없음 |
| 과거 | 사건시점 유효 조문·연혁 | 당시와 현재의 차이 표시 |
| 형사벌칙 | 구성요건·벌칙 조문 | 법정형, 실제 처벌 예측 없음 |
| 과태료 | 법정 상한·시행령 별표·차수·가감 사유 | 상한·기준 분리, 단순 합산 금지 |
| 감독사례 | 공식 URL·발표일·당시법령·진행단계 | 송치예정·입건·기소·판결·확정 구분 |

법제처 공동활용 승인/이용조건/호출한도 확인 → source adapter → 원문 스냅샷 해시 → 조문·부칙 추출 → 검증 큐 → 적용요건 확인 → 사용자 적용 검토 → 보고서 고정 순서다. 수집 실패·충돌·오래된 자료는 상태를 표시하고 최신 검증 완료를 차단한다. 원문이 없는 조문·금액·사례를 LLM 기억으로 생성하지 않는다.

## 검증·배포 방침

1. 순수 계약 시험: 깨진/초과 JSON, 추가 승인/금액 키, ID·해시 불일치, 분석 변경의 재검토, 위조 완료, 잘못된 날짜.
2. 서버 시험: 익명·shared-saas 차단, quota·입력크기, 사진 원본 서명·서버 해시·권한, CAS, 원문 오류 비노출.
3. 실제 PostgreSQL(PGlite): 역할별 거부, storage 기존 허용정책과 새 restrictive 정책 조합, 변경 불가, 감사 실패 롤백.
4. UI: 실제 브라우저에서 사진 등록→JSON 가져오기→검토→개선·재점검→보고서, 네 언어 중 인쇄체 OCR 실측. 네트워크 모의 검증은 실DB 검증과 분리 기록.
5. 기존 `verify:fast`, 전체 테스트, production build, 패키지 보안 검사.
6. GitHub PR·Vercel preview·실사 DB 검증 결과를 진행현황에 기록한다. 운영 main과 도메인 전환은 담당자 승인 및 회귀 통과 후 수행한다.

M0에서 남은 환경변수 목록 권한·AI 공급자 청구·공식 법령 API 승인 상태는 별도 확인 대상이다. 기존 데이터·기존 AI 기능·SMART TBM·게임을 무단 변경하지 않는다.
