# 받은 회신 모아보기 (2026-10-24)

## 해결할 현장 문제

공유 요청은 만들 수 있지만, 조치와 링크를 하나씩 열어야 답변을 발견할 수 있다. 여러 사진·여러 담당자가 있는 점검에서는 일정 협의가 필요한 회신과 접수된 개선사진이 묻힌다. 점검자는 초보 사용자여도 안전 판단 전문가이므로, 메뉴를 찾는 시간을 줄이고 정확한 조치에서 대조·재점검으로 이어가야 한다.

## 구현

- 저장 점검에서 사진을 열고 있지 않을 때 `받은 회신 모아보기`를 바로 표시한다. 조치 모아보기 안에도 `받은 회신` 보기를 추가한다.
- 기존 인증된 `share-list` API를 명시적 진입/새로 확인 시에만 호출한다. 메타데이터만 읽고 사진 다운로드·Supabase Realtime·자동 반복 조회·유료 AI 요청은 추가하지 않는다. 새 DB 테이블·마이그레이션도 없다.
- 조치 어려움 → 미반영 개선사진 → 예정 회신 → 회신 대기 → 종료된 링크 → 반영 기록 순으로 안내한다. 텍스트 회신은 마지막 접수 내용을 기준으로 하며, 개선사진 접수는 완료를 뜻하지 않는다.
- 한 번에 요청 카드 6개. `지금 확인`·`회신 대기`·`전체 요청`으로 좁힌다. 긴 요청과 회신은 3줄 미리보기와 해당 조치/전체 내용 보기로 확인한다. 확인 시각을 한국시간으로 표시한다.
- 회신 선택은 조치 UUID와 공유 UUID를 함께 사용한다. 현재 검색·분류·정렬과 관계없이 정확한 조치 페이지로 이동하고 해당 공유 기록을 새로 읽어 펼친 뒤 키보드 초점을 이동한다.
- 공유 당시 제목·담당·기한·원본 사진 번호를 유지한다. 변경된 현재 조치의 문구로 옛 회신을 바꿔 표시하지 않는다. 만료/차단 후 접수 기록이 남더라도 적용 가능 여부와 최종 승인은 해당 조치에서 별도로 판단한다.
- 작성 중인 조치·담당 변경·개선사진 입력이 있으면 이동 버튼을 막고 입력을 보존한다. 조회 실패나 저장본 버전 변화는 `회신 없음`으로 바꾸지 않고 다시 확인하도록 안내한다.
- 모아보기 DOM에는 capability URL·토큰·사진을 표시하지 않으며 세션/로컬 저장소에 회신을 추가 저장하지 않는다. 기존 공유 만료·삭제·공개 범위·점검자 반영 절차를 유지한다.

## 검증 기준

- 순수 분류 테스트: 우선순위, 마지막 텍스트 회신, 만료/차단 후 사진 대조, 잘못된 만료, 현재 점검 범위, 중복 제거, 누락 조치, 정렬 안정성·불변성, 토큰 제외.
- 실제 빌드 UI + 합성 API: 7개 조치/8개 공유로 다른 페이지의 정확한 공유 기록을 열고 초점 이동 확인. 분류·페이지, 빈 목록, 조회 실패, 저장 전 변경 보존, 버전 변경 시 재조회 확인.
- 320/390/844/1440px 가로 넘침과 모바일 한글 시각 확인. 기존 공유·QR·수신·비교·반영 흐름 회귀 검증.
- 실제 운영 자료의 API 조회는 읽기 전용으로 구분하고, 합성 UI 응답으로 수행한 검증을 실제 발송/저장 결과로 표시하지 않는다.
