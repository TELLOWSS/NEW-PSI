# NEW-PSI 29차 — F10 목표 기한 변경 사유·임시 안전조치 유지 이력 (2026-11-01)

## 현장 문제와 범위
즉시 조치가 어려운 지적사항은 자재 입고, 장비·공정 조정 등으로 완료 목표 기한이 바뀔 수 있다. 기록이 나중에 바뀌더라도 **왜 미뤘는지**, **이전 날짜가 언제였는지**, **그 사이 임시 접근통제는 실제로 확인했는지**를 구분할 수 있어야 한다. 반면 점검자의 기록만으로 안전 확보나 작업 재개를 승인하지 않는다.

기존 F10의 `Followup.history`에는 매번 상태·담당자·목표 기한·임시 안전조치·메모·기기 시각이 이미 저장된다. 29차는 이 배열을 활용하여 종전 기록을 그대로 남긴다. **기존 v17 백업/복원 규격 및 DB 버전 변경 없음**.

## 구현
1. 목표 기한을 이전 기록과 다르게 선택하면 **기한 변경 사유(5~500자)를 반드시 입력**해야 한다. 변경 전후 날짜는 별도의 이력 비교 화면에서 보여준다.
2. 임시 안전조치의 텍스트를 변경·해제·공란 처리하면 **임시조치 변경·해제 사유(5~500자)를 반드시 입력**해야 한다. 이전 통제 내용과 새 내용을 한 줄로 비교한다.
3. 최초 기록에는 변경 전 날짜나 통제 내용이 없으므로 변경 사유를 강제하지 않는다. 이전 이력을 기반으로 한 추가 기록에서만 적용한다.
4. 점검자는 임시조치의 확인 수준을 `현장 유지 여부 미확인`, `기록만 확인 · 현장 상태 미확인`, `점검자가 현장 유지 상태 직접 확인했다고 기록`, `재확인 필요 · 유지 상태 확정 불가` 중 직접 선택한다. **모두 점검자의 진술·기록일 뿐, 시스템의 사진·좌표·센서 실측이나 안전 적합성 인증이 아님**.
5. 사유·확인수준·진행 내용을 기존 `Followup.history[].note` 안에 명시적 표지와 함께 구조화하여 저장한다. 이를 읽는 전용 `localFollowupChangeTrace.mjs`는 옛 이력도 비교하되, 없던 변경 사유는 만들어내지 않고 **사유 확인 불가(이전 기록)**라고 표시한다.
6. 기한 변경 수·임시조치 변경 수·최신 확인 수준, 변경 전후 기한·통제 내용·기록일·사유를 접고 펼칠 수 있는 현장 기록 UI로 표시한다.
7. 다른 탭에서 먼저 변경한 후속 조치를 오래된 화면 상태로 덮어쓰지 않도록 **현재 IndexedDB 후속 기록 전체와 표시된 예상 기록을 대조**한 뒤 저장한다. 충돌 시 기록 유지·새로고침 안내.
8. `목표 기한` 변경은 **재점검의 독립 `다음 확인 예정일`을 자동 수정하지 않는다**. 차이가 생기면 점검자가 다음 현장 확인일을 따로 검토해야 한다.

## 한계 및 주의
- 정보의 진위/점검자 신원/현장 통제 유지/법규 적합성/근로자 통보·수신 여부는 자동 확인하지 못한다. 기기 시각은 서버 공인 타임스탬프가 아니다.
- 현재 v17 백업의 후속조치 변경 이력은 **별도 암호학적 위변조 방지 서명 대상이 아니다**. 형식 검증과 사진·일부 기록의 SHA 검증이 이 메모의 신뢰성 전체를 담보하지 않는다. 사용자가 다시 점검하고 제출 전에 검토해야 한다.
- F10 보완은 29차 기능 단위의 완료이며 전체 F10의 독립승인, 실기기 통보·인수인계 인증 등은 남아 있다.
- 새 서버 호출·유료 AI 사용·GPS·QR·자동 메시지 발송·기존 서명/스키마 변경 없음.
