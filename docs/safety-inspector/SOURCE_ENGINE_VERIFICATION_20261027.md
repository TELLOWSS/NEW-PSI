## 실패와 조치

- 새 테스트의 잘못된 함수명 및 고정 버전 기대값을 수정하고 영향 테스트를 다시 통과했다.
- 최초 전체 실행에서 Windows 체크아웃 CRLF와 원본 LF를 그대로 비교하던 기존 2개 검사가 실패했다. 생성 validator와 SQL의 로컬 줄바꿈을 LF로 맞춰 재검증했다. 해당 파일의 Git 내용 변경은 없으며 테스트를 완화하거나 삭제하지 않았다.
- 기존 Vitest include는 `.test.ts`만 수집하므로 신규 UI 테스트도 React.createElement를 사용하는 `.test.ts`로 작성해 전체 CI에 실제 포함했다.
- npm audit의 기존 fast-uri moderate 1건은 남아 있다. 현재 저장소의 high 이상 게이트는 통과했으며 의존성 버전 변경은 이 작업에 포함하지 않았다.

## 사용량·미완료 경계

자료 검토파일은 23,630 bytes, gzip 2,574 bytes다. 모든 16개 주제와 관련 사례·동향을 한꺼번에 포함한 참조는 검토 메타데이터가 없을 때 32,791 bytes, 있을 때 49,787 bytes로 16,996 bytes 증가한다. 이는 사진·분석을 제외한 합성 최대 주제 조합의 비교이며 평균 보고서 크기를 뜻하지 않는다. 새 DB 행·버킷·cron·함수·공식자료 조회 API는 추가하지 않았고, 관리자 후보 검사에서 원문 fetch·DB 쓰기·유료 호출 0을 확인했다.

원문 확인 이력이 있는 2개 자료 중 moel-18869는 원문의 과태료 부과 표현과 기존 카드의 예정 표현이 달라 pending으로 남겼다. 내용 차이를 검토 완료로 승격하지 않았다. moel-20117은 원문 대조 기록이 있으며 나머지 23개는 기존 검토자료 이관 상태다. 미확인 시행일·개정 이력은 채우지 않았다.

실제 Android·카카오톡 외부 전달·공식 API 계약·자료 재배포 허용·실제 Vercel 플랜의 상업 운영 적합성은 이번 합성 검증으로 확인되지 않는다. 운영 배포는 필수 원격 CI, 동일 SHA preview, 안전·보안 검토 및 기존 릴리즈 게이트 확인 뒤에만 진행한다. 이전 수동점검 기본 모드 구현 초안은 이 브랜치에 포함하지 않았다.
