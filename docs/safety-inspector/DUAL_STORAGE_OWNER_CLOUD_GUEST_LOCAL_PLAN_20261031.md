# NEW-PSI · 이중 저장 운영체계 전환 기획서
**프로젝트:** NEW-PSI (SMART TBM 별개) · **기준:** 2026-10-31 · **형태:** 실행 설계 v1.0
**목표:** 운영자 클라우드의 편의는 유지하고, 누구나 체험하는 현장 카메라/기기 점검 자료는 각 이용자 기기에만 보관하여 클라우드 저장·AI 비용이 참가자 수에 직접 비례하여 증가하는 구조를 차단한다.

## 1. 현재 소스에서 검증한 사실
- `/inspector`: 서버 인증(기존 관리자 세션)을 거쳐 Inspector 데이터베이스/비공개 사진 저장소 사용. 현재는 독립 SaaS 계정이나 현장별 권한 분리와 동일하지 않음.
- `/camera`: 로그인 없는 브라우저 IndexedDB `psi-field-camera`에 사진 저장. 스마트폰 갤러리에 자동 저장되지 않음. 공유는 사용자의 명시적 행동에 한함.
- `/field-local/`: 사전 오프라인 준비 가능한 직접 점검. IndexedDB `psi-inspector-local-records`에 사진·점검·후속조치·조치후 사진·v1~v13 복원을 보관. AI 유료 요청 및 서버 업로드 없음.
- `/product`: 서버에 쓰지 않는 고정 샘플. 입력은 메모리에만 있어 새로고침하면 초기화.
- 문제: 제품 홈, 체험 후 CTA, 카메라 후속 이동이 실제 사용자를 클라우드 관리자 화면으로 유도할 수 있음. 저장 위치 설명이 사용자 입장에서 일관적이지 않음.
- 기획에서 '체험'과 '현장 업무 실제 기록'을 구분해야 함. 단순 카메라는 전문 점검의 모든 클라우드 AI/보고서 기능을 제공하지 않음.

## 2. 확정할 제품 정책: Owner Cloud / Guest Local / Sample Memory
| 구분 | 운영자 클라우드 | 일반 사용자 기기 점검 | 고정 샘플 |
|---|---|---|---|
| 기본 진입 | `/inspector` | `/field-local/` (직접 점검), `/camera` (간편 촬영) | `/product#experience` |
| 인증 | **서버가 검사하는 관리자 인증** 필수 | 관리자 로그인 요구하지 않음 | 로그인 없음 |
| 기록 | DB 및 비공개 사진 스토리지 | IndexedDB + 선택적 다운로드 | 브라우저 메모리 |
| 재접속 | 인증된 권한 안에서 다른 기기 | 같은 브라우저/기기에서만 | 새로고침하면 소멸 |
| 유료 AI | 운영자 승인과 비용 한도 내에서 명시적으로 호출 | 비활성 / 서버 자동 호출 금지 | 실제 분석 호출 없음 |
| 공유 | 현재 권한·로그인·API 정책 적용 | 사용자 명시적 공유창/내려받기 | 예시 텍스트/문서 |
| 비용 | 업로드·보관·DB·API 과금 관리 | 주로 정적 배포·네트워크 트래픽, 사용자의 기기 저장 | 정적 배포 트래픽 |
| 한계 | 단일 관리자 계정을 여러 사람에게 공유해서는 안 됨 | 기기 변경 시 자동 동기화 불가, 공용 기기 프로필 간 분리 불가 | 실제 현장 증빙으로 사용 불가 |

**중요:** 클라이언트의 저장 모드 선택은 보안 통제가 아니다. 모든 서버 쓰기/AI 작업은 서버측 관리자 인증과 권한/쿼터 통제에서만 허용해야 하며, 로컬 화면의 링크 교체로 권한이 부여되지 않는다.

## 3. 사용자 여정
### 체험자 (무료 로컬 우선)
1. 제품 홈에서 '내 기기에 기록하며 체험' 선택.
2. `/field-local/`에서 사전 오프라인 준비(선택, 온라인 필요) → 현장명·동·층·공종 직접 입력 → 전체/근접 사진 → 위험·조치 기록 → 미조치/조치중/검토요청 상태·담당·기한·임시 안전조치 → 조치후 사진.
3. 동일 브라우저에서 다시 접속하여 이어보기. 필요시 다건 JSON 백업을 사용자가 파일로 내려받고 별도 보관·복원.
4. 클라우드 자동 업로드/자동 분석/자동 공유/자동 동기화/무단 전환 없음.

### 관리자
1. '관리자 클라우드 운영' → `/inspector` → 서버 인증.
2. 기존 DB·사진 스토리지·검토·분석·보고서 유지.
3. 비용/보관 정책과 승인 이력 관리. 체험자의 로컬 자료가 자동 유입되지 않음.

### 예시 관람
`/product#experience` → 가상 그림·정해진 위험/조치 단계 → 실제 AI·업무 기록은 생성하지 않음.

## 4. 용량과 비용 모델 (가정치이며 실제 청구 아님)
중앙 저장 증가량 = 사용자 수 × 일일 사진 수 × 월 사용일 × 사진당 저장 크기 × (원본/파생본·백업 계수).
- 예시: 300명 × 20장/일 × 20일 × 0.5MB = **60GB/월** (계수 1.0, DB·백업·전송·AI 제외).
- 1,000명이면 같은 조건에서 **200GB/월**. 일반적으로 사용량은 인원·빈도에 대략 비례해 증가하며 반드시 수학적 의미의 지수증가는 아님.
- 로컬 모드라 하더라도 웹 앱 최초 다운로드/업데이트용 Vercel 트래픽, 공유한 파일의 상대 앱 트래픽, 브라우저 저장 제한은 남음.
- 운영자 클라우드는 저장/전송/DB/AI 비용을 **각각** 관측하며 무료 플랜 임계값은 실제 서비스 대시보드에서 확인할 것. 수치상 무제한/무료 보장은 금지.

## 5. 보안·개인정보·무결성
1. **서버 권한 경계:** 관리자 URL만 바꾼 것으로 API가 보호되지 않는다. 클라우드 업로드·분석·조회·삭제의 인증·권한·남용 제한을 서버에서 확인.
2. **브라우저 저장 경계:** 동일 도메인(Origin)·같은 기기/브라우저 프로필을 사용하는 사람이 로컬 기록을 열 수 있다. 기기별 개인정보 보호(잠금, 공유기기 미사용) 안내.
3. **불안정한 보관:** 브라우저 초기화·시크릿 모드 종료·용량 부족·OS 정리·기기 분실로 로컬 기록이 유실될 수 있다. StorageManager.persist() 승인만으로 이를 막지 못함.
4. **백업:** 현 v1~v13 단건/최대 10건 50MB 묶음 JSON은 **암호화되지 않음**. 외부 전달 금지, 가능하면 개인 정보 최소화. 장기적으로 암호화된 휴대용 백업과 복원 검사 추가.
5. **정확성:** 사용자 입력 현장정보는 증빙된 GPS가 아님. 임시 조치는 완료 상태나 안전 확인을 의미하지 않음. 모델 판단/법령 참고는 현장 검증 필요.
6. **분리 강화:** 장기적으로 guest 전용 Origin/별도 도메인 및 임시 데이터 클리어 제공, 필요시 기기 PIN/암호화. 프런트엔드 모드만으로 완전한 격리라고 표현하지 않음.

## 7. 출시 차단 조건
- 익명 이용자가 서버 인증 없이 관리자 자료를 읽거나 DB/AI API를 사용할 수 있으면 출시 금지.
- 로컬 화면에서 촬영 즉시 중앙 업로드/AI 비용이 발생하면 출시 금지.
- 실패한 기기 저장을 성공으로 표시하거나, 백업 없는 기기 변경을 '언제 어디서나 복구'라고 약속하면 출시 금지.
- 기존 관리자 워크플로, 사내 PSI OCR/위험성평가/6지표, 별도 SMART TBM 기능을 회귀시키면 출시 금지.
- 신규 코드의 전체 CI와 모바일 합성 검사 통과 후 GitHub main에 병합하고 Vercel 공식 도메인/커밋을 대조한다. 실기기 현장 검증은 별도 표시.

## 8. 운영 의사결정
**당장 우선:** 체험/기기 점검 안내·진입 경로부터 분리해 이용자가 의도치 않게 클라우드에 자료를 올리는 경로를 최소화한다. 전용 관리자 서버는 현행 유지한다. 이 작업을 완료한 후 F07 변경 감사 및 F06 증빙 추적을 계속한다.
