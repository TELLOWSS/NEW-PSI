# 무엇이 잘못됐는지 모를 때의 사진 단서 탐색

## 사용자 의도

사용자는 이상해 보여 사진은 찍었지만 위험 이름·문제 원인·적용 조문을 모를 수 있다. 먼저 정답을 설명해야 결과를 받는 흐름을 줄인다. 기본 흐름을 ‘촬영/선택 → 설명 없이 명시적으로 사진 AI 실행 → 위치/사진 근거/가능 사고 경로/우선 조치 → 전문가 확인/조치/보고서’로 둔다. 위치·작업 상황 힌트는 선택적으로 추가한다.

## 구현

- 입력에 사진만으로 시작할 수 있음을 표시하고 힌트는 접힌 선택 항목으로 둔다. 촬영/선택 후 텍스트 입력을 자동으로 포커스해 모바일 키보드를 열지 않는다. 적어 둔 힌트는 접기만으로 지우지 않으며 저장 사진을 열면 기존 힌트를 보존한다.
- 실제 이미지와 기존 7개 배열 응답을 사용하는 API/수동 프롬프트를 사진 우선으로 보강한다. 보이는 사람·시설·작업 관계를 살피고 힌트는 보조 자료로 취급한다. 근거 없는 위험이나 사진 밖 시설 부재를 만들지 않는다. 새 모델/공급자/추가 분석 호출을 도입하지 않는다.
- 위험 후보 최대 3개를 사진 위치 → 관찰 근거/관찰 판독 확신 → 왜 문제가 될 수 있는지 → 먼저 검토할 조치로 표시하고 사진 확대·대조 경로를 둔다. 관찰 판독 확신을 사고 확률이나 안전 점수로 표시하지 않는다. 미수용 AI는 대조용이라고 표시한다.
- 단서를 좁히지 못하면 안전 확정으로 처리하지 않는다. 첫 추가 확인 질문/이유 또는 판독 한계를 제시하고 안전한 위치에서 보완할 자료를 안내한다. 질문·재촬영은 다음 사진/보고서의 필수 단계가 아니다. 일반 조치나 금액을 문제를 찾았다는 답처럼 우선 표시하지 않는다.
- 선택한 위험과 그 관찰 근거로 법령 주제를 연결한다. 이전 위험의 주제를 다음 위험에 넘기거나 무관한 힌트만으로 초기 주제를 고르지 않는다. 직접 연결할 수 없으면 수록 주제를 사용자가 선택하게 하며, 법적 의무·금액 적용은 기존 조건부 대조 자료로 유지한다.
- API OFF/미연결/실패와 사진 저장을 사진 판독과 구분한다. 설명 없는 저장에서 AI가 판독한 것처럼 표시하지 않는다. 연결된 API를 켜는 동작도 분석을 자동 실행하지 않으며 기존 안내·동의·명시적 실행을 거친다.

## 호환·비용·저장

기존 JSON/schema와 provider 응답의 7개 배열을 유지한다. 새 prompt는 응답을 간결하게 요청하나 출력 한도/중단·거절/엄격한 검증을 유지한다. 기존 분석·보고서에 새 해석을 소급하지 않는다. 신규 DB/schema migration·저장소·의존성·환경변수 변경은 없다. 사진 최적화/해시/비공개 보관/삭제 검증 범위를 유지한다.

요청 fingerprint·requestId 규칙은 변경하지 않는다. 배포 중 알 수 없는 전송 결과의 재시도가 새 유료 작업으로 분리되는 위험을 만들지 않으며 자동 재분석/유료 재시도를 하지 않는다. 유료 공급자 호출은 기존 사용자 실행과 안내에 따른다.

## 검증·제공 한계

빈 설명+실제 이미지 바이트를 두 공급자 형식에 한 번만 전달하는 서버 fixture, 선택 위험의 법령 연결/연결 없음/잘못된 관찰 참조, 수동 JSON 호환을 검증한다. 브라우저는 무설명 위험 발견/불명확/근거 없는 일반론/낮은 판독 확신/무관한 힌트/API OFF·미연결·실패, 확대·선택 질문·조치/보고서·저장 이어하기·모바일/다크를 확인한다. provider 응답은 fixture이며 실제 현장사진 정확도나 모든 위험 탐지 보장으로 주장하지 않는다. 실제 API 사용료를 수반하는 별도 모델 정확도 평가는 자동 실행하지 않는다. CI/main/배포 및 운영 읽기 검증은 연결 PR에 구분해 기록한다.
