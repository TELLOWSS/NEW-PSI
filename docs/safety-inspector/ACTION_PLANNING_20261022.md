# 간편 사진점검 고도화: 검토에서 현장 조치 전달까지

작성일: 2026-10-22. 안전 전문가이지만 앱을 처음 쓰는 사용자가 여러 장을 검토한 뒤 실제 요청할 조치·담당·기한을 간편 화면에서 정리하는 개선이다.

## 확인한 문제와 설계

| 상황 | 기존 문제 | 구현 |
|---|---|---|
| 여러 사진에 같은 문구의 조치 제안 | 사진별로 반복해서 읽고 전달문 작성 | 검토한 사진의 동일 조치 문구를 모아 표시. 사진별 번호·설명·전문가 의견은 보존 |
| 간편 모드에서 담당·기한 지정 | 상세 관리로 이동해야 함 | ‘다음 사진’ 이후 선택 기능인 ‘조치 모아보기’에서 직접 편집·저장 |
| 같은 문구, 다른 위치 | 자동 통합하면 조치 적용 범위 오인 | 적용 사진은 기본 미선택. 사용자가 사진별 체크와 현장 범위 확인을 해야 저장 |
| AI 해석을 전문가가 수용하지 않음 | 잘못된 제안을 다시 지시할 위험 | 거절한 AI 조치는 제외하고 저장한 전문가 의견만 초안 후보로 제공 |
| AI OFF 또는 제안 없음 | 조치 등록 방법 찾기 어려움 | ‘직접 조치 작성’으로 사진 선택·내용·담당·기한 입력 |
| 조치 저장 중 응답 끊김 | 저장 여부 혼란·중복 등록 | 고정 조치 UUID와 문서 revision 사용. 실패 후 서버에서 동일 내용을 읽어 확인한 경우에만 저장 성공 복구 |
| 많은 조치와 긴 설명 | 모바일 스크롤 증가 | 제안 한 개씩 선택, 등록 조치 세 개씩 페이지 이동. 긴 사진 설명·의견은 전체 보기로 확인 |
| 현장 전달 | 사진별 제안과 실제 등록 조치가 혼재 | 등록 조치 요청문에 담당·기한·상태·적용 사진 포함. 보고서는 작성 당시 등록 조치와 사진별 참고 제안을 구분 |

## 사용 흐름

사진 촬영·붙여넣기 → 선택 설명 → 분석·전문가 검토 → 다음 사진. 필요할 때 ‘조치 모아보기’를 열어 제안 또는 직접 작성을 선택한다. 조치 문구·적용 사진·담당·완료기한·현장 범위를 확인해 저장하고 요청문을 복사한다. 조치 정리는 선택이며 바로 보고서를 만들어도 된다.

확인 질문 응답을 추가로 강제하지 않는다. 제안을 정리하거나 조치를 저장하는 동작은 AI 공급자를 호출하지 않는다. 보고서 작성은 조치 이행 완료가 아니다. 등록 상태는 미조치이며, 개선사진·완료 검토 요청·현장 재점검은 기존 상세 관리에서 이어간다.

## 데이터와 안전 경계

- 기존 `actions` 문서 필드와 인증·revision·검증 API를 사용한다. DB migration, 새 유료 서비스, 사진 재업로드, 별도 조치 테이블을 추가하지 않는다. 조치 최대 30건, 사진 최대 20장 경계는 유지한다.
- 같은 문구는 NFC·공백만 정리해 비교한다. 의미가 비슷하다는 이유로 병합하지 않는다. 전문가 의견과 AI 제안도 별도 후보다. 우선순위는 제안 표시이며 위험도 확정이나 작업중지 명령이 아니다.
- 적용 사진의 전체 UUID를 기존 조치 기록에 남긴다. 긴 설명은 24자 길잡이만 포함하고 원래 사진 설명과 검토 의견은 원 문서에 보존한다. 이 연결 메모는 편집 가능한 기록이지 신규 불변 관계 테이블이 아니다.
- 저장 응답 실패 복구는 UUID·제목·담당·기한·기록·미조치 상태를 읽어 대조한다. 확인할 수 없으면 오류를 유지한다. 다른 revision을 덮어쓰거나 자동으로 두 번째 조치를 추가하지 않는다.
- 조치 변경 시 작성자료 완료 상태를 해제한다. 기존 보고서 snapshot은 변경하지 않으며 새 보고서만 새 조치를 포함한다. 보고서 복사는 해당 snapshot 자료만 사용한다.
- 조치 작성 중 화면 안에서 등록 목록을 보거나 패널을 접어도 입력은 유지한다. 제안 변경·상세 관리 이동·새 점검 시작 또는 브라우저 이탈 시 저장 전 입력 소실을 알린다. 브라우저 종료 후 미저장 조치 복원은 제공하지 않는다.
- 기존 보관 용량·삭제 검증 흐름을 유지한다. 사진·분석·키를 브라우저 영구 저장소나 새 저장소에 복제하지 않는다. 외부 전달은 사용자 미리보기·기기 공유창·복사/다운로드를 제공하며 자동 메시지 전송은 없다.

## 검증 범위

자동 시뮬레이션은 실제 초보자 대상 사용성 연구나 안전판정 정확도 평가와 구분한다. 단위 시험은 동일 문구·다른 사진 범위·거절 및 미검토 AI 제외·20장 ID 보존·중복·보고서 고정을 확인한다. 브라우저는 동일 제안 두 장 중 한 장만 적용, 필수 확인 누락 차단, 입력 보존, 저장 실패 재시도, 성공 후 응답 유실 복구, AI OFF 직접 작성, 모바일 320/390/768/1440px 및 기존 촬영·검토·삭제 회귀를 검증한다. API fixture 시험은 실제 운영 DB 쓰기 검증으로 표시하지 않는다.

운영 검증·테스트 수와 배포 결과는 구현 상태 문서 및 연결 PR에 기록한다.

## 추가 요청: 카카오톡 등 상대에게 바로 보내기

사진 결과의 ‘카톡 등으로 보내기’, 등록 목록의 ‘미결 조치 보내기’, 보고서의 ‘보고서 사진·요약 보내기’를 제공한다. 미리보기에서 보낼 문구를 편집하고 사진을 선택한다. 저장 전 검토 선택과 저장한 검토를 구분한다. 보관 사진은 기존 무결성 검사로 불러온 사본을 사용하며 카카오 공개 이미지 서버나 새 Storage에 올리지 않는다. 비공개 서명 URL은 공유 문구에 넣지 않는다.

기기 기본 Web Share 공유창을 사용한다. 설치된 카카오톡·문자·메일 등 공유 대상 중 사용자가 앱과 상대를 선택하며 실제 전송 여부는 선택한 앱에서 확인한다. 카카오 SDK 전용 메시지 카드/알림톡/친구목록 자동 전송을 구현한 것으로 표시하지 않는다. 카카오 개발자 앱·키·도메인 등록 없이 동작 가능한 기기 공유와, 별도 설정이 필요한 Kakao SDK 연동을 구분했다.

사진은 미리 준비하고 공유 버튼 클릭에서 직접 `navigator.share`를 호출해 사용자 활성화를 유지한다. 파일 공유 지원이 없으면 사진을 임의로 누락해 전송하지 않고 안내한다. 사진 체크를 해제하면 문구만 공유할 수 있다. 지원되지 않는 PC/브라우저·공유 실패에는 문구 복사와 사진별 다운로드를 제공한다. 일부 앱은 사진과 문구를 동시에 받지 않으므로 사용자가 대화창에서 확인하고 복사·첨부로 보완하도록 안내한다. 취소나 앱 부재는 완료로 기록하지 않으며 native API 성공도 상대 수신 확인으로 간주하지 않는다.

공유 사본은 상대방 기기로 전달되므로 이 점검을 삭제해도 회수되지 않는다. 수신자·대화 내역을 서버에 저장하거나 연락처 권한을 요청하지 않는다. 자동 시험은 native share를 모의 처리하며 실제 카카오톡 사용자에게 메시지를 발송하지 않는다. 실제 Android/iOS 카카오톡 버전별 전송·수신 검수는 별도다.

기술 근거: [W3C Web Share](https://www.w3.org/TR/web-share/), [카카오톡 공유 이해하기](https://developers.kakao.com/docs/ko/kakaotalk-share/common). 2026-10-22 확인.
