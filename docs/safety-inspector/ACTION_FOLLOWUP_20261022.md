# 사진점검 후속 고도화 — 개선사진, 전후 비교, 현장 재점검

기준일: 2026-10-22. 이전 기획서와 main 구현을 대조한 뒤, 전문가가 간편 모드에서 조치의 이행 확인까지 마무리하는 흐름을 우선 구현한다.

## 미완료 항목 판정과 이번 범위

| 항목 | 이번 구현 | 남는 경계 |
|---|---|---|
| 간편 모드의 개선·재점검 | 등록 조치에서 촬영·파일·PC 붙여넣기·기존 사진 선택, 개선 내용, 완료 검토 요청, 별도 재점검 확인 | 현장 확인 자체는 사람이 수행. 자동 안전 승인 아님 |
| 조치 전후 비교 | 새 조치에 적용 사진 ID를 구조화하고 원래 사진과 개선사진을 병렬 비교·확대 | 사진마다 정확한 위험 부위 주석, 자동 정합·차이 검출은 별도 |
| 구형 조치 호환 | 연결 필드 없는 미조치/검토 요청 기록은 실제 원래 사진을 직접 지정해 처음 연결 | 이미 확인된 구형 기록을 추정 수정하지 않음 |
| 후속 보고서 | 개선 전후 근거 사진을 선택 자료와 합쳐 새 보고서에 보존, 요약에도 연결 사진 표시 | 기존 보고서 snapshot·해시 불변. 정식 최종 발행 승인 별도 |
| 카톡 등 공유 | 저장된 조치의 선택한 전후 사진 2장과 상태·담당·기한을 공유 미리보기로 전달 | 실제 앱/상대 선택은 기기 공유창. 실기기 수신 검수는 별도 |
| 실패·중복 처리 | 같은 업로드 ID로 재시도, 저장·재점검 응답 유실은 서버의 같은 조치 내용으로 대조 | 동시 편집 충돌은 덮어쓰지 않고 오류 유지 |
| 용량·삭제 | 최적화 사본만 기존 비공개 저장소에 보관, 20장/3MB 경계와 기존 전체 삭제 검증 재사용 | 별도 사진 복제 저장소·유료 AI 호출 없음. 외부로 공유한 사본 회수 불가 |

## 사용자 흐름

사진·설명 → 결과 확인 → 다음 사진 → 조치 모아보기 → 등록 조치 → 개선사진·전후 비교·재점검. 원래 사진과 개선 후 사진을 대조하고 실제 개선 내용 5자 이상·보관/민감정보 확인을 거쳐 ‘완료 검토 요청’으로 저장한다. 이 단계는 완료가 아니다. 현장 확인 내용 5자 이상과 별도 재점검 확인을 기록한 뒤 서버가 확인 시각을 부여한다. 새 보고서를 만들거나 전후 사진·조치를 공유한다.

새 조치의 원래 적용 범위는 변경하지 않는다. 여러 원래 사진을 묶은 조치는 비교할 원래 사진을 선택할 수 있으며, 공유에는 그중 선택한 대표 원래 사진과 개선사진 2장이 첨부된다. 보고서는 전체 연결 근거를 보존하고 대표 1장 전후 비교를 먼저 보여준다. 필요한 자료를 펼칠 때만 사진을 불러와 모바일의 긴 스크롤과 불필요한 다운로드를 줄인다.

## 데이터와 검증 경계

- `InspectorAction.sourcePhotoIds?`를 기존 JSON 문서의 선택 필드로 추가한다. 새 테이블·DB migration·계정·환경변수·SDK 변경이 없다. 필드가 없던 문서와 고정 보고서는 계속 읽는다.
- 연결은 같은 점검의 원본 사진에만 허용하고 중복/빈 배열/외부 ID를 거절한다. 한 번 연결한 범위는 일반 저장으로 바꾸거나 제거할 수 없다. 확인된 조치 전체는 기존 불변 규칙을 유지한다.
- 같은 사진 ID 또는 SHA-256이 같은 바이트를 다른 ID로 등록한 개선사진을 차단한다. 사진의 진위·촬영 위치/시각을 암호학적으로 증명하는 기능은 아니다. 현장 대조가 필수다.
- 사진 선택 시 기기에서 최적화하고 원본은 바꾸지 않는다. 업로드한 사본도 기존 증빙·해시 확인·용량·삭제 대상에 포함한다. 전후 비교용 공개 URL이나 별도 클라우드 이미지를 만들지 않는다.
- 개선사진 등록과 재점검은 기존 인증·revision·검증 API를 사용한다. 일반 `save`로 `verified`와 서버 확인시각을 위조할 수 없다. 재점검 성공 시 이전 작성자료 완료 상태를 해제한다.
- 개선 요청 저장과 별도 재점검 확인은 다른 단계다. 같은 전용 관리자 권한이므로 독립된 제삼자 승인·개인 전자서명·수신자의 조치 수락을 의미하지 않는다.
- 업로드만 성공하고 문서 연결 저장에 실패한 대기 사진은 보고서에 임의로 넣지 않는다. 보관/삭제 검증에는 그대로 포함하고 같은 ID로 연결 저장을 재시도한다. 새로고침 후에도 보관된 연결 대기 사본을 선택해 사진·실제 위치 확인 후 재업로드 없이 연결할 수 있다.
- 완료 사진이 AI 분석 대상이 아니어도 새 보고서에는 조치 연결 근거를 포함한다. 보고서 요약·공유는 해당 snapshot 자료만 사용하고 현재 데이터나 새 법령을 과거 보고서에 넣지 않는다.
- 저장 전 입력은 페이지 안에서 패널을 접었다 열어도 유지한다. 조치 목록 페이지 이동·상세 관리 버튼/새 점검·브라우저 이탈 시 미저장 입력 소실을 알린다. 오프라인 영구 보관·종료 후 미저장 사진 복원은 구현하지 않는다.

## 검증 계획

단위/서버 시험: 기존 문서 호환, 다른 점검·중복 ID, 같은 원본 재사용 차단, 적용 범위 불변, 일반 저장 승인 위조 차단, 서버 재점검 시각과 완료 자료 해제, 새 보고서의 개선 증거 누락 방지, JSONB 키 순서가 바뀐 응답 복구.

브라우저 시뮬레이션: 파일·카메라·붙여넣기, 저장 실패 재시도, 저장/재점검 후 응답 유실, 구형 조치 연결, 새로고침 이어하기와 연결 대기 사본 재사용, 전후 확대·공유 미리보기, 모바일 네 해상도와 다크 모드, 이전 보고서 불변, 추가 유료 AI 호출 없음. 실제 현장 판정 정확도나 실제 초보자 모집 연구로 취급하지 않는다.

운영 API는 별도 합성 자료만 생성해 두 사진·조치·재점검·새 보고서 및 실제 삭제 검증을 확인하고 정리한다. 기존 checkpoint는 읽기 전용 해시 대조만 하며 실제 업무 기록은 변경하지 않는다. 결과와 배포 ID는 연결 PR에 기록한다.

## 후속 미완료 목록 (과거 문서와 구분)

- 법령 API 자격과 실시간 개정·시행일 동기화, 전체 감독·판례 수집 및 검증 큐.
- 실제 현장 사진 정답셋·전문가 검수, Android/iOS 실기기와 카카오톡 앱별 실제 수신 시험.
- 개인 계정/전자서명·기업/현장별 권한, 수신자의 조치 수락·재발/재개 상태와 감사 절차.
- 위험 부위 주석, 다국어 사진 분석/전달물 전체 11개 언어, 오프라인·50장 이상 대용량.
- 최종 승인된 정식 발행·월간/임원 DOCX/PDF, PSI 지표/별도 SMART TBM의 승인된 연계 계약.

공식 기술 자료 확인: Supabase 표준 업로드 및 2026-10-12 TLS 공지. 이번 기능은 기존 SDK/HTTPS/비공개 Storage 경로를 유지하며 덮어쓰기·TLS 설정 변경이 없다.
