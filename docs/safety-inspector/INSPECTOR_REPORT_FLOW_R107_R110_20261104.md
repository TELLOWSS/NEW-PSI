# NEW-PSI 인스펙터 사용성 진단 및 보고서 동선 재설계 · R107–R110
> 2026-11-04 · 코드 검토 기반 기획/구현/합성 QA · NEW-PSI 전용. SMART TBM과 PSI: ZERO DAY는 제외.

## 1. 실제 코드 검토 결과와 검토 한계

**확인한 현재 동선 — 관리자 클라우드 간편 점검**
`SafetyInspector.tsx` → `InspectorQuickWorkspace.tsx` → 사진 촬영/파일 선택 → 개인정보 제거·보관 안내의 명시적 동의 → 사진 저장/직접 점검 또는 사용자가 승인한 AI 분석 → `InspectorAnswer` / `InspectorExpertReview` → `resultJourney`(조치 또는 보고) → `createReport` 서버 스냅샷 → `InspectorReport` → 사진 로딩 상태 확인 → 인쇄/PDF·공유.

- 간편 화면의 주동작과 보조 동작이 상단 진입 카드, 입력 패널, 결과 탭, AI·법령 패널, 검토 패널, 조치 플래너, 하단 고정 액션 등 여러 영역에 분산돼 있다. 운영 코드만 봐도 초보자가 보고서 버튼을 찾기 어려울 가능성이 있다. *실사용자 관찰/클릭 계측 결과는 아니다.*
- `lib/inspector/resultJourney.ts`는 AI 없는 직접 점검에서 **조치 작성**을 1차 버튼, **보고서 기록**을 2차 버튼으로 안내한다. 실제 현장 조치가 아직 필요한지 판단할 때와 *우선 발견 내용을 기록·전달할 때*는 서로 다르므로, 직접 점검에서는 후자가 1차 경로여야 한다.
- `InspectorReport.tsx`는 사진, AI 원문/가설, 법령·조건별 금액, 개선·재점검, 이력을 기본적으로 한 화면에 길게 연속 렌더링한다. 현장소장에게 즉시 전달할 **핵심 요약**과 사무실에서 대조할 **전체 증빙**의 읽기 목적이 혼재되어 있다.
- `InspectorQuickWorkspace.createReport`에는 저장 전 조치 초안, 바뀐 설명, 미검토 AI 사진, 사진 미보관, 버전 재확인 등의 중요 차단 규칙이 이미 있다. 이번 작업에서 *절대 우회하지 않는다.*
- **기기 오프라인 점검은 다른 경로**: `InspectorLocalDraft.tsx`의 사진→관찰→기기 저장과 F10 재점검 경과보고서(CSV·HTML)는 관리자 클라우드 점검 보고서와 동일한 산출물이 아니다. 사용자에게 경로/산출물 차이를 설명해야 하며, 서버 기록을 자동 동기화하거나 법정 교육/안전 승인으로 과장해서는 안 된다.

**확인 범위:** GitHub `main`의 소스·기존 합성 시나리오·CI. 삼성 인터넷/iPhone Safari 실제 기기, 실제 근로자·현장소장 사용성 면담, 보고서 수신 확인, OCR/AI 의미 정확성은 이번 소스 분석의 증거가 아니다.

## 2. 제품 목표

**사진 → 사람이 확인한 사실 → 미결 상태 그대로 기록·공유 → 필요시 조치/재점검**.

원칙: *보고서를 만드는 데 조치 완료를 요구하지 않는다*. 당장 조치할 수 없을 때 미조치/기한/담당 상태를 사실 그대로 남긴다. 그러나 사진·분석 검토, 설명 변경, 미저장 조치, 저장 버전/권한 오류를 묵살하지 않는다.

### 정보 구조
1. **발견**: 첫 화면의 촬영/사진 선택을 그대로 유지. 자동 AI는 기본 OFF, 사진 보관/외부 전송 동의는 명시적으로 유지.
2. **확인**: 첫 결과에 **지금 할 일 한 가지**를 제시. 직접 점검은 사진과 설명을 먼저 보고서에 기록하는 버튼을 주동작으로 전환. AI 결과는 인간 검토 저장을 먼저 요구하고, 미검토 사진도 우회 금지.
3. **보고**: 보고서 기본 화면은 현장소장이 한눈에 읽는 **핵심 요약**; 근거·사진별 상세 검토는 **상세 근거 전체**를 눌러 열기. 출력/인쇄 PDF는 요약 화면 상태에 좌우되지 않는 전체 스냅샷으로 유지.
4. **후속**: 조치 요청/담당 지정/임시 통제/개선사진/재점검은 필요할 때 이어가기. 보고서 생성과 작업재개·개선 완료·법령위반 확정을 연결하지 않는다.
5. **기기 직접점검**: 3단계 사진→관찰·조치→저장 및 기존 복구 이력 유지. F10 경과보고서는 *조치/재점검이 기록된 경우*의 추가 선택 경로임을 분명히 표시. AI/서버/요금 전환 없음.

## 3. 이번 릴리스 실제 구현 범위

- **R107 / UX-AUDIT**: 본 기획서와 현행 차단 규칙 문서화. 관리자 간편점검·로컬 F10 보고서의 역할 구분.
- **R108 / NAVI–CORE**: `resultJourney` 직접 점검 시 **보고서로 기록하기**를 주 버튼으로 배치, **조치 작성(선택)**을 보조 버튼으로 전환. AI가 생성한 분석이 있으면 먼저 확인/검토/저장을 요구. 3단계 상태 안내(사진·현장 확인 / 조치 / 보고)를 기본 화면에 간결히 표시.
- **R109 / LUMI–SAFI**: 클라우드 보고서 기본 `핵심 요약` 읽기모드, `상세 근거 전체` 전환. 핵심 보고에는 현재 기록 사진 수, 현장·공종, AI 검토/미검토, 미결/미확인·조치 상태를 노출하고 위법·제재·개선 완료를 자동 선언하지 않음. 출력/인쇄는 기존 *전체 보고서 증빙* 그대로.
- **R110 / PROOF**: 단위 테스트 + 실제 브라우저 합성 사진 업로드/동의/직접 점검→보고서, AI 저장 전 보고서 차단, 미저장 조치가 보고서에서 탈락하지 않도록 범위 선택, 핵심/상세 전환 후 스냅샷 동일성, 인쇄 사진 로드 차단, 모바일 320/390, 오프라인 무과금 정책 회귀.

## 4. 인수 기준 / 실패 시 중단 조건
- 동의 없는 사진 보관·유료 API 호출 없음.
- 직접점검은 보고서로 이어지는 명확한 주 버튼이 있으며, 사용자가 선택한 경우 조치 등록은 별개 가능. **조치 미등록=조치 완료**로 표시하면 실패.
- AI 사진 검토 미저장/현장 대조 미확인, 미저장 조치, 바뀐 설명을 자동 보고서에 포함하거나 묵살하면 실패.
- 요약/상세 전환은 조회 표현만 변경. 사진/보고서 snapshot, 서명·승인/법정 판정 상태를 바꾸지 않으며, 인쇄·PDF에는 상세 기록 전체가 보존된다.
- 사용성 버튼은 터치 타깃 44px 이상, 320/390px 모바일 화면에서 가로 스크롤/겹침이 없어야 함.
- 릴리스 CI·기존 Inspector/회사 전체 브라우저 시나리오 실패가 있으면 PR 병합 금지. 병합 뒤 `main` CI 재검증과 Vercel Production SHA/alias 교차 확인.

## 5. 남은 별도 과제
- 삼성 인터넷/iPhone Safari 실기기, 카메라·권한 거절, 스크린리더/통역자 인터뷰, 실제 현장 10명 이상 경로 완주·소요시간 측정: **미수행**, 합성 Chromium 결과로 대체 불가.

- 법령·금액·감찰사례를 실시간 검증하는 기능은 이번 UI 개선에 포함하지 않으며 참고자료 한계를 그대로 표기.
