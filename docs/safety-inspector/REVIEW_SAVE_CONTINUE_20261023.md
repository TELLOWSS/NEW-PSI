# 현재 사진 검토 저장·안전한 중단·같은 사진 이어보기

## 우선순위와 기획

안전 전문가는 현장 사진을 검토하다가 전화·현장 대응으로 작업을 중단할 수 있다. 종전에는 전문가 의견을 적어도 ‘다음 사진’ 또는 ‘보고서 저장’을 누르기 전까지 서버에 저장되지 않았고, 보관한 사진을 읽기만 해도 이동 경고가 표시됐다. 저장과 진행을 분리해 현재 사진의 판단을 확실하게 보관하는 것을 이번 우선 과제로 선택했다.

1. 전문가 판단 보완 영역에 ‘검토 저장 전 / 검토 저장됨’을 표시한다. 라디오의 기본 ‘참고해 활용’ 선택만으로 저장되었다고 표시하지 않는다.
2. ‘검토만 저장’은 기존 confirm-photo API로 현재 사진의 선택·의견만 명시적으로 저장한다. 현재 사진에 머물며 다음 사진 이동·보고서 생성·조치 완료 확정·AI 재분석을 하지 않는다. 이미 같은 내용이 저장돼 있으면 중복 저장하지 않는다. 짧은 의견과 미수용 이유의 기존 서버 검증을 유지한다.
3. 서버 저장본과 다른 사진·설명·제목·검토 의견이 있을 때 이동/새로고침 경고를 유지한다. 저장한 사진과 검토를 읽기만 하는 경우에는 불필요한 경고를 제거한다. 조치 작성·개선사진의 기존 별도 변경 보호는 유지한다.
4. ‘검토만 저장’ 성공 후 이 탭에는 점검 ID와 사진 ID 두 개만 보관한다. 다시 접속하여 ‘이전 점검 이어하기’를 누르면 해당 사진의 최신 저장본을 읽고 파일 SHA-256을 확인한 후 표시한다. 사진/의견/분석 내용/서명 URL은 브라우저 저장소에 보관하지 않는다. 이 탭의 위치 저장이 막혀도 서버 저장 성공을 실패로 바꾸지 않으며 저장 기록에서 여는 방법을 안내한다.
5. 다음 사진·조치 작성 등으로 현재 사진을 떠나거나 새 점검·보고서를 완성하면 위치를 정리한다. 삭제 잠금은 사진 복원 전에 검사하고, 대상 사진이 없어졌다면 다른 사진을 대신 열지 않는다. 기록 목록에서 사용자가 명시적으로 선택한 ‘검토 이어보기/조치 이어보기’ 의도는 이 탭 위치보다 우선한다.

## 응답 유실·충돌

검토 저장 요청이 실패하면 쓰기를 자동 재시도하지 않고 detail을 한 번 읽는다. 같은 점검/사진, 더 최신 버전, 동일 사진 해시·분석·사진 설명·점검 공통정보(제목·사건일·공종·위치·API 설정 등), 일치하는 검토 선택/의견 및 활성 보관 상태가 모두 확인되는 경우에만 저장 성공으로 복구한다. JSON 객체 키 순서 차이는 허용한다. 변경된 분석·설명·검토나 삭제 잠금은 복구하지 않고 현재 입력을 유지한다. 서버가 실제로 저장하지 않았다면 사용자가 수정·재시도할 수 있다.

## 데이터·비용 경계

새 DB/schema/RLS·Storage 버킷·외부 API 키·유료 호출·자동 업로드가 없다. 기존 저장 사진과 기존 검토 API를 재사용한다. 의견을 서버에 저장하는 동작은 사용자의 명시적 실행 때만 발생한다. 미저장 원본 사진/입력 전체를 자동 복구하는 오프라인 저장 기능은 아니다. 고정 보고서와 삭제 검증 엔진은 수정하지 않는다.

## 검증

순수 판정 6개 테스트: 기본 선택과 저장 상태 구분, 키 순서 차이의 응답 복구, 다른 분석/사진/삭제 상태 거절, ID 두 개만 있는 제한된 위치, 실제 변경에 따른 이탈 보호, 수동 사진의 설명 보호.

브라우저 신규 10개: 현재 사진 저장·읽기 전용 이동·재수정 경고, 저장 전 실패/수동 재시도, 저장 응답 유실, 다른 기기의 수정 거절, 삭제 중 복구 거절, 위치 저장 차단, AI 미수용 의견, 짧은 의견 거절, 이어볼 사진 없음, 검토 저장 후 보고서 완성 시 위치·안내 정리와 중복 검토 저장 방지. 기존 촬영·삭제·조치·카드·법령 연결·보고서 및 기록 이어보기 시나리오도 회귀 검증한다. 합성 서버 응답에 실제 문서 검증을 적용하며 실제 유료 분석이나 업무 데이터 수정 없이 수행한다. 최종 CI·운영 배포 및 검증 근거는 연결 PR에 기록한다.
