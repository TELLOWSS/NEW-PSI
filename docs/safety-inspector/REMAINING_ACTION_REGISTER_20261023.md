# 미완료 재점검과 저장본 조치대장

## 점검 결과와 우선순위

사용자가 현장에서 사진을 모아 전문가 판단을 저장하고 담당자에게 조치를 넘기는 흐름을 기준으로 현재 코드와 기존 기획서를 대조했다. 오래된 구현 상태 문서의 미완료 항목에 이미 완성된 기능이 섞여 있어 최신 분류를 별도로 만든다.

| 요청·기획 항목 | 현재 구현 | 남은 범위 |
| --- | --- | --- |
| 직접 촬영·가로/세로·선택·PC 붙여넣기 | 공유 카메라, 실제 프레임 전체 보존, 기본 가로, 저장 위치/용량 안내 | 실제 휴대폰·렌즈별 검수, 광각 렌즈 보장은 아님 |
| 사진 최적화·원본 보존·증빙 | 브라우저 JPEG 최적화, 업로드 해시/용량/크기 영수증 | 운영자 공급자 백업 삭제까지 보장하지 않음 |
| 사진만으로 위험 단서·선택 힌트 | 분석·불확실성·문제별 조치, 선택 위험별 자료 연결 | 실제 현장 정답셋 20건 이상 전문가 정확도 평가 |
| 검토·중단·이어보기 | 명시적 검토만 저장, 실제 저장 상태, ID만 저장하는 탭 이어보기 | 전체 미저장 초안의 오프라인 복구 |
| 현장 확인·개선 전후·완료 확인 | 선택 질문, 전문가 미수용 의견, 담당/기한, 개선 증빙, 별도 재점검 | 개인 승인 계정·협력사별 권한·전자서명·재개 업무 절차 |
| 보고서·전달 | 고정된 사진 포함 검토용 보고서, 인계문, OS 공유/파일, 현장 카드 | 정식 최종 발행 승인·월간/임원 출력·DOCX |
| 조치대장 CSV | 이번 구현: 저장본 전체 등록 조치 내려받기 | 여러 점검 통합·기간별 대장은 별도 |
| 삭제·무료 보관 | 서버 파일 부재·DB 관련 행·서명 URL 만료 검증, 실패/재시도·요약 용량 | 공급자 백업 삭제 시점, 무료 요금제 총량 보장은 아님 |
| 법령·금액·사례·동향 | 날짜 고정 공식 자료, 선택 위험별 연결, 조건부 상한/종류, 무관한 자료 배제 | 법제처 자격 기반 실시간 원문/시행일 adapter, 전체 제재·감독·판례 수집 및 검증 큐 |
| 기업 도입·다국어·연동 | 공개 제품 체험, 기존 관리자 운영 | 현장별 RLS·11개 언어·SMART TBM 승인 이벤트 계약·실제 비용 계측 |

계정/권한이나 외부 API 자격이 필요한 항목을 완료로 바꾸지 않는다. 실제 기기·현장 정확도는 합성 브라우저 시뮬레이션과 구분한다. 이번에는 현장에서 저장한 조치를 기존 엑셀 대장으로 옮기는 반복 작업을 없애는 CSV를 우선한다.

## 구현 흐름

사진 검토 후 모은 사진 화면의 ‘보고서·현장 인계’에서 ‘조치대장 CSV 내려받기 · N건’을 누른다. 저장된 점검의 등록 조치 전체가 대상이며 화면 검색/필터나 보고서 사진 선택으로 일부를 누락하지 않는다. 조치가 없거나 처리 중이면 버튼은 비활성화한다. 입력 중인 제목·조치가 있어도 서버 저장본을 내보낸다는 안내를 표시한다. 임의의 AI 제안을 등록 조치로 만들지 않는다.

파일명은 점검 ID 앞 8자리와 저장 버전을 사용하며 현장명·담당자를 파일명에 넣지 않는다. CSV는 점검 ID/버전/명칭·현장·위치·공종·사건시각, 조치 번호/ID/명칭·담당·기한·상태·전후 사진 번호·현장 확인시각·기록·검토용 구분을 담는다. 실제 파일과 URL을 포함하지 않는다. 번호는 점검 전체 사진 순서다. 구형 적용 사진 미지정/유실된 연결은 확인 필요로 표시하며 다른 사진을 대신 지정하지 않는다.

미조치·완료 검토 요청·현장 재점검 확인을 구분한다. 검토 요청을 완료로 바꾸지 않고 재점검 시각은 verified 상태에만 포함한다. 구형 확인시각이 없으면 없음으로 표시한다. 시각은 저장 ISO 값을 그대로 표기하고 임의의 현지 시각으로 추정하지 않는다. 내보내기가 서버 상태·검토·조치·고정 보고서를 수정하지 않는다.

## 파일·오류·저장 경계

한글 UTF-8 BOM과 CRLF, 모든 셀 인용 및 큰따옴표 이스케이프를 사용한다. 쉼표·줄바꿈·전체 저장 문장을 보존한다. 수식 시작 문자와 공백/제어문자 뒤의 수식도 문자로 취급하도록 작은따옴표를 붙인다. 추가 외부 라이브러리가 없다.

클릭 시 로컬 Blob으로 만들고 다운로드 링크를 제거한 뒤 Blob URL을 30초 후 해제한다. 생성/클릭 예외는 실패 안내를 내며 서버 저장 성공으로 혼동하지 않는다. ‘파일을 준비했습니다’는 기기 파일 저장 완료를 검증했다는 뜻이 아니다. 인계문 txt도 같은 오류 처리 경로를 이용한다. 다운로드한 사본은 사용자가 기기에서 관리·삭제하며 Supabase 점검 삭제로 외부 사본이 삭제되지 않는다. 신규 DB·Storage 사본·유료 분석·자동 업로드·환경변수를 추가하지 않는다.

## 검증 계획

순수 테스트는 전체 30개 조치 보존·원본 불변·미검토 AI 배제, 한글/쉼표/따옴표/줄바꿈 CSV 재해석, 수식 시작/공백·제어문자 방어, 상태 3종·구형 연결·확인시각, 빈 대장 헤더를 검증한다.

실제 production 번들·운영 CSP의 브라우저 시뮬레이션은 조치 0건 비활성화, 저장 후 파일명·BOM·내용·쓰기/AI 추가 호출 없음, AI OFF 수동 조치, 다운로드 실패와 재시도, 개선 전후 상태 3종의 새 다운로드, 320/390px 및 가로 844px/다크 화면을 확인한다. 기존 검토 저장·보고서·조치 응답 유실·법령 연결 회귀도 확인한다. 실제 업무 자료를 수정하거나 유료 분석·외부 전송을 실행하지 않는다. 최종 CI와 운영 결과는 PR에 기록한다.
