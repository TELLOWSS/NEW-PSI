# 앱 초보 안전전문가의 사진점검 시뮬레이션과 개선

작성일: 2026-10-22. 대상: NEW-PSI 기본 사진점검 화면. 안전 지식은 충분하지만 앱은 처음 쓰는 현장 관리자를 기준으로 설계했다.

## 사용 목표와 조사 방법

사진·짧은 현장 설명 → AI 제안과 근거 검토 → 필요할 때 전문가 판단 보완 → 다음 사진 → 모은 자료로 보고서 완성. 확인 질문은 선택 보조 자료이며 사진마다 문답을 끝내도록 요구하지 않는다.

현장 시나리오는 시스템비계·개구부·난간 판독, 실제 방호가 촬영 범위 밖에 있는 경우, 연속 두 장, 작업 중 새로고침, API OFF, 분석·보고서 오류로 구성했다. 브라우저 자동 시뮬레이션과 저장 API·소스 검토를 사용했다. 실제 초보자 모집 연구나 현장 안전판정 정확도 평가 수치는 산출하지 않았다.

첨부된 자기규율 기록지의 작업·위험·판단·조치·실천 구분과 SMART TBM 화면의 기록→검토→현장 활용 원리를 참고했다. 사진점검에 근로자 교육 문답을 추가하지 않으며 PSI 점수와 별도 SMART TBM으로 자동 전송하지 않는다. 첨부 원문은 변경·저장소 수록 대상이 아니다.

## 전문가 의견의 의미

- AI 원문은 덮어쓰지 않는다. 전문가 의견·수용 여부는 `reviews`에 별도 기록한다. 서버가 확인 시각과 전용 관리자 출처를 부여한다.
- ‘AI 해석과 다름’은 AI 제안의 수용 거절이며, 현장이 안전하다는 승인이나 개선 완료가 아니다. 실제 조치·재점검 상태를 자동 완료 처리하지 않는다.
- 거절한 AI 위험·조치는 현장 전달문에 넣지 않는다. 당초 설명은 참고로 표시하고 전문가 의견을 먼저 보여 준다. 상세 보고서의 AI 원문은 대조용임을 명시한다.
- 사람이 거절한 AI 결과가 보고서 법령·금액을 찾는 신호가 되지 않게 한다. 법령은 수록 공식 자료의 조건부 참고이며 실제 위반·부과액을 확정하지 않는다.
- 의견 보완·재열람·보고서 작성은 새 AI 분석을 호출하지 않는다. 사진 설명 자체가 바뀌면 기존 분석과 검토를 무효화하는 경계는 유지한다.

## 이어하기와 보관

- 브라우저에는 마지막 점검 ID만 sessionStorage에 저장한다. 사진·API 키·분석 원문을 브라우저 영구 저장소에 복제하지 않는다. 저장소 사용이 차단되어도 기본 점검은 동작한다.
- 이어하기는 서버 인증 후 기존 `detail`을 조회한다. 사진을 열 때 기존 비공개 서명 URL을 요청하고 바이트 SHA-256을 대조한다. 한 번에 선택한 사진 한 장만 화면용 Blob으로 유지하고 이동·종료 시 객체 URL을 해제한다.
- 재열람·의견 확인에는 새 업로드·AI 전송 동의를 요구하지 않는다. 새 사진 업로드와 명시적인 외부 AI 재분석에는 각각 기존 동의 경계를 적용한다.
- 저장 전 기기 사진·아직 저장하지 않은 설명과 검토 메모까지 복구한다고 주장하지 않는다. 활성 사진 편집 중 이탈 경고를 제공한다.
- 삭제 상태의 점검은 재개하지 않으며 저장 기록에서 삭제 결과를 확인하게 한다. 과거 보고서 스냅샷을 현재 의견·법령으로 바꾸지 않는다.

## 보고서와 검증 기준

1. 확인 후 다음 사진으로 이동해도 보관 장수·검토 상태·보고서 완료 동작이 보인다. 사진 두 장 처리에 점검 생성은 한 번, 업로드·분석은 각 사진 한 번이다.
2. 전문가 의견은 사진에 귀속되고 새 보고서의 스냅샷·해시에 포함된다. 이전 보고서는 수정하지 않는다. 제목 변경은 사진 분석을 다시 호출하지 않는다.
3. 검토 대기 AI 사진이 있으면 보고서 완성 전에 해당 사진을 열어 확인하도록 안내한다. 선택 확인 질문을 전부 답하도록 요구하지 않는다. AI OFF 사진은 설명 자료임을 표시한다.
4. 새로고침→이어하기→이전 사진 확대→의견 보완→보고서 완료에 중복 업로드·유료 재분석이 없다. 저장 사진의 무결성 실패는 그대로 중단한다. 명시적인 재분석이 실패한 경우 설명이 바뀌지 않았을 때만 저장된 분석 결과를 다시 열 수 있다.
5. 서버에서 잘못된 검토 구분, 이유 없는 거절, null·상한 초과 의견과 위조된 확인 출처를 거부한다. 낡은 저장 버전은 기존 충돌 검사를 적용한다.
6. 전문가가 거절한 AI 조치가 조치요청문·보고서 전달 요약에 포함되지 않는다. 보고서에서 제외한 사진은 복사 요약에서도 제외한다.
7. 운영 CSP의 production 번들, 320/390/768/1440px, 확대 화면 키보드·포커스 복귀, 카메라·붙여넣기, API OFF·미연결·분석 재시도·보고서 재시도를 검증한다.

## 운영 반영 범위

DB 스키마·권한·API 공급자·모델·키·유료 호출 한도 변경 없이 기존 JSON 문서와 인증된 API를 활용한다. 서버 확인 요청에 검토 구분·의견만 추가한다. 실제 운영 검증에는 명확히 표시한 합성 시험자료만 사용하고 시험 기록·사진·보고서는 전체 삭제 절차로 정리한다. 실제 근로자 사진과 첨부 PDF를 시험 데이터로 업로드하지 않는다.

검증 결과와 최종 main·운영 배포 식별자는 관련 PR에 기록한다. 판독 모델의 현장 정확도, 실시간 법령 동기화·개별 과태료 실제 부과액 계산, 별도 SMART TBM 연동은 이 사용성 개선의 완료 주장에 포함하지 않는다.

## 추가 요청 반영: 삭제 확실성·구체적인 법령·최근 감독동향·모바일

### 삭제의 완료 조건과 중단 복구

기존 코드는 Storage API 제거, 경로 재조회, 파일 읽기 실패를 확인하지만 새 서명 URL 한 건의 차단만으로 이전 URL 전부의 만료를 대신할 수 없었다. 또한 삭제가 중단되면 원인과 남은 양을 간편 화면에서 확인하기 어려웠다.

- 첫 삭제에서 DB의 기존 삭제 펜스를 세워 신규 업로드·분석·보고서를 차단한다. 파일은 Storage API로 지우고 남은 경로를 조회한다. 메타데이터만 SQL로 지우지 않는다.
- 기존 120초 사진 링크를 고려해 최초 삭제는 125초 검증 대기를 둔다. 파일이 이미 없어도 이전 링크 대기와 DB 정리 확인 전에 ‘완료’로 표시하지 않는다. 사진 링크 생성 직후에도 삭제 상태를 다시 검사해 경합 중 링크를 반환하지 않는다.
- ‘보관 용량 · 이 점검 삭제’를 간편·상세 화면에 공통 제공한다. 사진만/전체 범위, 남은 사진 개수·용량, 점검/사진정보/보고서/이력 행 수, 진행 중 작업과 재시도 시각을 표시한다. 전체 삭제는 사진·분석·설명·이력·보고서를 함께 제거한다. 사진만 삭제하면 기록은 유지하고 편집을 잠근다.
- 명시적으로 시작한 삭제는 관리 패널을 열어 둔 동안 링크 만료 후 한 번 자동 마무리한다. 반복 오류는 무한 자동 재시도하지 않는다. 새로고침·재접속 후에는 저장 점검을 다시 열어 상태를 확인하고 ‘남은 삭제 마무리’를 누른다.
- 완료 RPC 응답만 믿지 않고 Storage 목록과 5개 관련 테이블(점검·사진정보·보고서·이력·작업)의 정확한 개수를 다시 조회한다. 조회 실패를 0건으로 처리하지 않는다. 삭제 완료 후에도 UUID를 이용한 읽기 전용 상태 조회·검증서 저장이 가능하다.
- 진행 중 업로드·분석을 시간 초과만으로 강제 완료시키지 않는다. 끝나지 않는 작업은 상태를 공개하고 관리자 확인 대상으로 남긴다. 실제 저장소·네트워크 장애 때 삭제 성공을 보장하는 표현을 쓰지 않는다.
- 최소 삭제 영수증·API 호출 제한 집계는 남는다. 외부 AI·기기 원본·다운로드 PDF·클립보드·제공자 백업/로그의 삭제까지 입증하는 기능은 아니다. 타 점검을 한꺼번에 삭제하는 기능은 추가하지 않는다.

### 무료 사용량에 대한 설명

2026-10-22 공식 가격표를 확인했다. Free 참고 한도는 파일 1GB·DB 500MB·전송 5GB와 캐시 전송 5GB다. 이 앱은 이미 적용된 프로젝트 파일 900MB 신규 업로드 제한을 유지한다. 현재 프로젝트 파일/DB 조회값을 표시하되 조직 전체 잔여량·월 전송량으로 표시하지 않는다. 무료 잔여 사진 장수를 확정하지 않는다. 삭제해도 소비한 월 전송량은 복구되지 않으며 DB 물리 표시 용량도 즉시 감소한다고 약속하지 않는다. 유료 플랜·용량 증설·새 외부 서비스는 추가하지 않는다.

### 법령을 ‘판단에 쓸 기준’으로 읽게 하기

‘법령·금액’ 탭은 선택 위험 주제 한 개만 표시한다. 연결된 사진/설명 → 적용 기준 → 현장 대조 항목 순으로 정리한다. 예를 들어 비계는 제56조의 적용 대상·높이·폭 40cm·발판재료 사이 틈 3cm·고정과 예외를 함께 표시하고, 사진으로 측정했다는 표현을 쓰지 않는다. 개구부는 제43조 방호와 제13조 난간 구조를 구분한다. 보호구·교육·MSDS는 의무 주체·종류별 금액 조건을 분리한다.

조문 전문 요지·예외·완료 증빙은 필요한 경우 펼친다. 형사벌금·행정 과태료의 법정상한과 실제 사건의 부과액은 구분하며, 개별 과태료 1·2·3차 금액을 검증 없이 생성하지 않는다. 법령 조문 데이터의 검토일은 2026-10-20을 유지하고 사례·동향 검토일 2026-10-22와 섞지 않는다.

### 감독 사례와 동향의 구분

공식 사례는 3건에서 5건으로 확대했다. 2026-10-01 한화에어로스페이스 특별감독과 2026-09-20 반도체 27개소 점검을 추가해 화재·전기·MSDS·표지·교육을 보강했다. 제조업 사례에는 업종을 표시하고, 선택 주제에 해당하는 공개 적발 사항과 ‘내 현장에 적용할 점’을 별도로 제시한다. 예: 접지 탈락 사례의 제302조는 현재 충전부 방호 카드 제301조와 다른 의무임을 표시한다. 전체 감독 과태료를 사진 한 장·위반 한 건의 예상 금액으로 전용하지 않는다.

동향은 2026-10-20 발표한 3분기 누적 재해조사 대상 사망사고 잠정 통계·11월 화재폭발 점검 예고와 2026-01-22 연간 감독계획을 수록했다. 감독 결과/감독 방침/잠정 통계/예정된 점검을 명시적으로 구분한다. 해당 주제와 연결할 사례가 없으면 없다고 표시한다. 자료는 확인 날짜가 있는 선별 수록본이며 실시간 자동 갱신·전체 사례 검색이라고 주장하지 않는다. 새 보고서에 자료와 날짜를 스냅샷으로 고정하고 과거 보고서에 새 동향을 삽입하지 않는다.

### 모바일 화면과 추가 검증

탭은 ‘핵심 조치 / 법령·금액 / 사례·동향’ 3개를 유지한다. 사례와 동향은 탭 안에서 전환해 긴 목록을 한꺼번에 보여주지 않는다. 상단 메뉴 아래에 탭을 유지하고 탭 전환 때 본문으로 스크롤한다. 위험 선택·관련 주제 변경은 AI를 재호출하지 않는다. 320px 화면, 16px 입력, 44px 이상 터치 영역, 라디오 잘림, 고정 하단 메뉴와 보고서 버튼 겹침, 키보드·확대·인쇄를 검증한다.

삭제 검증은 단위 테스트로 부분 실패·진행 중 작업·잔여 행·파일 목록 실패·이전 링크 대기를 검증하고, 브라우저로 대기 후 자동 마무리/새로고침 후 재시도/사진만 삭제를 시뮬레이션한다. 배포 후 별도 합성 사진 1장과 수동 검증 결과로 실제 UI→인증 API→Supabase→보고서→전체 삭제를 확인한다. 유료 AI를 재호출하지 않고, 기존 승인된 합성 체크포인트가 변하지 않았는지도 대조한다.
