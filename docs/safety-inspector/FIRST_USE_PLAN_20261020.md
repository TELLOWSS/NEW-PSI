# 사진점검 첫 사용 경험 개선 기획서

작성: 2026-10-20 / 기준 main 5368b57 / 대상: 현장 전문가이지만 PSI는 처음 쓰는 점검자

## 목표와 완료의 의미

사진을 찍거나 선택하고 짧은 현장 힌트를 입력한 뒤, 읽기 쉬운 분석을 확인하고 사진·개선 권고가 포함된 검토용 보고서를 바로 얻는다. 질문별 조사·법령 조회·상세 감사 기능은 보조로 둔다. 보고서 작성은 개선 완료나 법령 검증·최종 승인을 의미하지 않는다.

## 변경 전 시뮬레이션

Chromium 가상 카메라와 격리 API fixture로 첫 점검 → 촬영/선택 → 사진 설명 → 분석 진입을 실행했다. 실제 사용자 연구나 실기기 시험으로 간주하지 않는다. 운영 사업자료 생성·삭제와 유료 공급자 호출은 하지 않았다.

| 관찰 | 처음 쓰는 사람에게 생기는 문제 | 변경 |
| --- | --- | --- |
| 사진별 설명을 저장했지만 다음 행동 계산은 공통 설명만 검사 | 이미 적은 설명을 다시 요구하는 안내 | 설명을 필수가 아닌 힌트로 취급하고 실제 사진·분석·검토 상태로 안내 |
| 분석 진입 즉시 사진 복사·프롬프트·API·JSON 입력이 함께 노출 | 어느 방법을 따라야 하는지 선택 불가 | 앱에서 바로 분석 / ChatGPT 직접 분석을 분리 |
| API OFF, 준비 상태, 동의, 저장 조건을 별도로 파악해야 함 | 비활성 버튼의 원인을 알기 어려움 | 이유를 바로 표시하고 명시적인 ‘API 켜고 이 사진 분석’ 지원 |
| 촬영 후 설명 입력란이 긴 페이지 아래에 있음 | 사진 등록 후 다음 행동을 찾기 어려움 | 단계 제목으로 이동, 새 사진은 부연설명으로 초점 이동 |
| 검토 이후 자료 완료 → 보고서 탭 → 보고서 작성 | 이미 확인한 자료를 여러 번 완료 | 간편모드는 ‘확인한 사진으로 보고서 만들기’ 한 동작으로 순차 처리 |
| 화면의 AI 개선 권고가 기존 보고서 사진별 본문에 없음 | 결과물이 분석 화면보다 정보가 적음 | 보고서·복사 요약에 개선 권고와 우선순위 포함 |
| 미검토 사진을 제외하고 보고서를 만들 수 있음 | 누락 범위를 놓칠 수 있음 | 확인/미확인 장수를 표시하고 제외 시 명시 확인 |

원본 baseline: `artifacts/audit/inspector-novice/baseline.json`, `before-390/768/1440.png` (로컬 검증 산출물, 저장소 제외).

## 사용자 흐름

1. **사진 추가**: 사진 보관·비식별 확인 후 카메라/사진 선택/PC 붙여넣기. 촬영 사진은 로컬 미리보기에서 사용 여부를 결정한다. 자동 JPEG 최적화, 기기 원본 보존 안내는 유지한다.
2. **분석 확인**: 부연설명은 선택 입력. 앱 분석은 외부 전송 동의와 명시 버튼을 눌러야 시작한다. API OFF 기본값을 유지하고 자동 분석하지 않는다. 서버가 준비되지 않으면 이유와 ChatGPT 경로를 제공한다.
3. **다음 사진 또는 보고서**: 결과는 관찰·추론·개선 권고를 구분한다. 전문가가 사진을 확인한다. 질문별 추가 확인은 접힌 보조 항목이며 미응답은 미확인으로 남긴다. 확인한 사진만 대상으로 보고서 자료 완료와 보고서 생성을 순서대로 수행한다.
4. **결과 활용**: 보고서에 사진·점검자 설명·관찰·개선 권고·미확인 사항을 포함한다. 보고용 요약 복사와 인쇄·PDF 저장을 제공한다. 확정되지 않은 법 위반·처분액을 생성하지 않는다.

## 화면 원칙

- 간편모드는 한 번에 현재 할 일과 다음 행동을 먼저 보여준다. 분석 전 반복 사진은 작게 보여주고, 설명을 함께 저장하는 현재 동작과 중복되는 하단 저장 바는 숨긴다. 상세모드의 기존 도구는 유지한다.
- API 연결·과금 상세, 저장 증빙·삭제·감사자료는 필요할 때 펼친다. API OFF 스위치는 계속 접근 가능하다.
- ChatGPT 경로는 사진 전달 → 표준 질문 전달 → 답변 가져오기 세 부분으로 안내한다. 사진 복사 후 프롬프트 복사 시 클립보드가 바뀐다는 점을 각 단계에서 알린다.
- 답변 입력은 원본 번호·사진 해시·엄격한 표준 검사를 유지한다. 다른 사진의 결과나 임의 산문을 자동 보정하지 않는다.
- 390/768/1440px, 키보드 초점, 화면 낭독기 상태 안내, 다크 테마, 인쇄를 확인한다.

## 구현 경계

기존 private Storage, 20장/3MiB 제한, 서버 API OFF 게이트, 호출 횟수 제한, 승인·스냅샷 계약과 기존 고정 보고서 데이터는 유지한다. DB 스키마·요금제·키 설정을 바꾸지 않는다. 보고서 화면에서 새로 표시하는 개선 권고는 이미 스냅샷 안에 저장된 값만 사용한다. 원래 보고서의 바이트·해시를 다시 쓰지 않는다.

API 분석 실패·저장 충돌은 구체적인 다음 행동과 함께 표시하고 자동 재시도하지 않는다. 자료 완료 후 보고서 생성이 실패하면 완료된 자료에서 보고서 생성만 재시도한다. 미검토 자료를 자동으로 승인하지 않는다.

## 검증 기록

아래는 자동 시뮬레이션 결과다. 운영 배포 읽기 검증은 배포 완료 보고에서 별도로 구분한다. 합성 데이터 테스트와 실기기·실사용자 시험은 구분한다.

### 구현·검증 결과

- 120개 파일 / 1,049개 Vitest 통과. 선택 설명, 완료 사진 범위, 반려·미응답 처리, 요약의 원본 불변성, 코드 블록 복사와 사진 해시 검증, 한국시간 날짜 전환을 포함한다. 보안·타입·빌드 검사 통과, production 의존성 취약점 0건.
- 실제 Chromium 153, **빌드된 운영 파일 + 현재 production CSP/Permissions-Policy**에서 6개 시나리오 통과: API 바로 분석 / API 미연결 후 ChatGPT / 분석 실패 후 명시 재시도 / 보고서 생성 재시도 / 미확인 사진 제외 취소 / 용량 조회 실패와 API 연결 상태 분리.
- API 자동 실행 0회, API 미연결 수동 경로의 API 실행 0회. 실패한 API 분석은 자동 재시도하지 않는다. 보고서 생성 재시도에서도 자료 완료 요청은 총 1회다. 미확인 사진 제외 취소 시 완료·보고서 요청은 0회다.
- 실제 가상 영상 장치의 촬영·즉시 미리보기·재촬영·선택 후 최적화, PNG 클립보드/사진 붙여넣기, 기존 상세모드·WASM OCR·production 메뉴 진입 회귀 통과.
- 390/768/1440px 가로 넘침 없음. 입력 가능 시점 이후 사진 설명으로 초점이 이동한다. 결과가 도착하면 분석 제목으로 이동한다. 오류 안내로 키보드 초점이 이동한다.
- 사진·개선 권고·미확인 상태가 있는 PDF를 텍스트와 렌더로 확인했다. 복사 UI는 인쇄에서 제외한다. 다크 테마에서도 흰 종이 배경을 유지하고 인쇄 전환 애니메이션을 끈다. 날짜는 한국시간으로 표시한다.
- 결과물: `artifacts/audit/inspector-novice/simulation.json`, 화면 PNG, `first-report.pdf` (재생성 가능한 로컬 QA 산출물, 저장소 제외). 실행: `PSI_QA_BUILT=1 PSI_CHROMIUM_PATH=... node scripts/verify-inspector-first-use.mjs`.

검증 경계: 위 6개 흐름의 API·데이터 저장은 격리 fixture다. 유료 공급자 실호출·실제 휴대폰 하드웨어·실사용자 사용성 연구의 통과로 해석하지 않는다. 운영 배포 후에는 기존 합성 점검의 사진·보고서와 관리자 인증을 읽기 전용으로 재확인하며, 새 업무 기록·유료 분석 요청·삭제를 수행하지 않는다.
