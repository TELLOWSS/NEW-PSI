# 사진점검 중단 안내·초보자 복구 흐름

## 사용자 경험

일반 화면은 설정 변경 대신 현재 상태와 다음 행동을 안내한다. 운영 정보·무료 등록·작동 시험은 접힌 운영자 관리 안에 배치한다.

- 일시적 장애: 사진 분석 다시 시도. 새 업로드 없이 현재 사진을 사용하며 자동 재시도하지 않는다.
- 공급자 한도: 즉시 재분석 버튼을 제안하지 않고 직접 점검·연결 재확인·관리자 전달 안내를 제공한다. 재개 시각을 확인할 근거가 없으면 날짜나 시간을 임의로 약속하지 않는다.
- 인증·권한·모델·무료 확인 문제: 운영자 확인 대상으로 안내한다. 사용자가 키·청구 설정을 바꾸도록 요구하지 않는다.
- 응답 유실·중복 요청·맥락 변경: 저장 결과부터 확인한다. 같은 사진의 해시·설명·삭제 상태를 확인한 뒤 결과를 불러온다. 일치하는 기록에 결과가 없을 때에만 직접 점검 경로도 연다. 새 AI 요청을 자동 생성하지 않는다.
- 사진 확인 문제: 직접 점검으로 이어갈 수 있다.

## 입력과 저장

사진 업로드 및 설명 저장이 완료된 상태와 이 화면에만 남아 있는 입력을 구분한다. 직접 점검 선택 시 사진·설명은 저장하고 apiEnabled=false를 명시적으로 사용해 React 상태 갱신 시점과 무관하게 외부 분석이 발생하지 않게 한다. 상세 화면에서는 수정 내용을 먼저 저장한 후 같은 점검의 간편 화면으로 이어간다. 보고서·조치 검토 조건은 완화하지 않는다.

중단 안내가 표시되는 동안 하단 고정 업무 버튼을 숨겨 복구 버튼을 가리지 않는다. 모바일 버튼 높이는 최소 44px이며 좁은 화면에서 한 열로 배열한다.

## 관리자 전달

안내 복사는 자동 발송이 아니다. 날짜·허용된 문제 코드·분석/연결 상태만 넣는다. 사진·현장 설명·근로자 정보·점검 ID·URL·키·서명값·공급자 원문은 넣지 않는다. 클립보드를 사용할 수 없으면 복사할 안내문을 화면에 표시한다.

## 검증

`scripts/verify-inspector-friendly-recovery.mjs`는 실제 UI와 합성 API를 사용해 다음을 확인한다.

1. 무료 확인 차단 → 직접 점검 → 사진·설명 포함 보고서. 추가 추론 0회.
2. 연결 없음 → 사진·설명 저장. 추가 추론 0회.
3. 확인된 일시 장애 → 수동 재시도. 기존 사진 업로드 1회 유지.
4. 한도 소진 → 재개 시각 확인 불가 안내, 즉시 재분석 유도 없음.
5. 설정 문제 → 운영자에게 책임을 안내, 사용자 키 설정 요구 없음.
6. 응답 유실 → 저장 결과 확인. 새 추론 요청 없이 직접 점검 가능.
7. 클립보드 거부 → 안내문 직접 복사 경로.
8. 상세 화면 차단 → 저장 후 같은 점검의 간편 화면 복귀.

각 시나리오는 320/390/844/1440 너비의 가로 넘침과 브라우저 오류를 검사한다. 고객 사진·운영 업무 기록·실제 공급자 호출을 사용하지 않는다. 화면 캡처·검사 결과는 `artifacts/audit/inspector-friendly-recovery`에 생성한다.

이 브랜치는 기존 운영 main 6978bed를 기준으로 만든 UI 변경이다. 별도 브랜치의 Google OIDC 연결 준비 코드를 포함하지 않는다. Google 권한·청구·운영 설정은 변경하지 않는다. 사용자 승인에 따라 GitHub·Vercel 운영 반영을 진행한다. 운영 배포 결과는 해당 PR에 기록한다.

최종 로컬 검증: 151개 테스트 파일·1,324개 테스트, 타입 검사·빌드 통과. 필수 빠른 검사와 high 등급 의존성 감사 게이트도 통과했다(기존 fast-uri의 moderate 항목 1개는 남아 있음). 8가지 합성 브라우저 시나리오와 네 화면 너비 검사 통과.

## 추가 편의성 보완

- 사진 선택·사용 허용·연결 확인·분석 차단·직접 점검 상태별로 지금 해야 할 한 가지를 분석 버튼 아래에 안내한다. 버튼에 aria-describedby를 연결한다.
- 연결 확인 중에는 관리자 설정 문제로 단정하지 않는다. 직접 점검을 선택하면 연결 확인 응답이 아직 없어도 사진·설명을 저장할 수 있다.
- 점검 작업영역에는 원시 HTML·JSON 파싱·서버 URL·키 관련 진단을 노출하지 않고 입력 보존과 다음 확인 행동을 안내한다. 현장 입력 검증·설명 충돌 등 유효한 한국어 안내는 유지한다.
- 브라우저 검증 스크립트는 개발 화면·로컬 운영 빌드·배포된 운영 화면을 지원한다. 운영 화면 검증도 합성 응답·사진을 사용하며 실제 업무 기록 쓰기와 공급자 호출을 발생시키지 않는다.

추가 검증: 152개 파일·1,336개 테스트, 타입·필수 검사·빌드 통과. 연결 대기 중 직접 점검을 포함한 브라우저 9종 및 네 화면 너비 검사 통과.
