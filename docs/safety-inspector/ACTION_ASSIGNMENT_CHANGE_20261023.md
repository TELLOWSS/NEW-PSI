# 등록 조치의 담당·기한 변경

## 현장 흐름과 우선순위

신규 조치에는 최근 담당자와 오늘/내일/3일 뒤 기한 단축 입력이 이미 있다. 그러나 등록한 조치의 담당자가 바뀌거나 공정에 따라 기한을 조정할 때 간편 화면에서 수정할 수 없었다. 같은 조치를 다시 등록하면 미결 건수·담당자별 요청문·대장이 중복되어 후속 관리가 흐트러진다. 기존 번호를 유지한 담당·기한 변경을 우선한다.

사진 검토 → 조치 등록 → 등록 조치의 ‘담당·기한 변경’ → 담당/기한/변경 이유 입력 → 현장 여건 대조 확인 → 명시 저장 → 새 요청문/조치대장/보고서 전달 순서다. 입력 폼은 버튼을 눌러 열며 기본 목록을 길게 늘리지 않는다. 현재 점검의 담당자 단축 선택과 한국시간 달력일 기한을 재사용한다. 값 변경 시 확인 체크를 다시 받는다. 실제 바뀐 담당 또는 날짜와 5~200자 이유가 있어야 저장한다.

## 저장과 보존

기존 조치 ID·내용·적용 사진·개선사진·미조치/완료 검토 요청 상태는 유지한다. 담당자와 기한만 바꾸고 조치 기록에 이전 값/새 값/이유를 덧붙인다. 다른 조치를 제거하거나 완료 승인으로 바꾸지 않는다. 재점검 확인(verified)된 조치는 기존 서버의 불변 검증과 UI로 수정하지 않는다. 구형 sourcePhotoIds가 없는 조치도 원래 범위를 추정하지 않는다.

기존 note 2,000자 한도를 넘으면 이전 기록을 줄이거나 지우지 않고 변경을 거절한다. 후속 개선/재점검 동작은 기존대로 현재 조치 note를 대체할 수 있으며, 변경 시점의 전체 문서는 기존 immutable revision 감사 스냅샷에 보존된다. 공유 관리자의 기록이며 개인 전자서명은 아니다. 서버 감사 이력을 포함한 전체 점검 삭제 범위는 기존 정책을 따른다.

변경 후 materialCompletion을 해제해 새 보고서 작성자료 완료를 다시 받는다. 기존 고정 보고서·기기 다운로드·외부 전달 사본은 소급 수정하지 않는다. 새 저장본에서 요청문·CSV·새 보고서를 작성한다.

## 실패·충돌·입력 보호

명시 클릭만 기존 save API를 호출하며 현재 revision과 편집 시작 당시의 전체 조치를 대조한다. 다른 사용자가 담당/기한/내용/상태를 바꾸었거나 이미 확인을 마쳤다면 덮어쓰지 않는다. 서버의 revision 조건부 UPDATE와 assertSafeEdit 검증을 유지한다.

응답 유실 시 detail을 한 번 읽고 같은 점검, 더 최신 revision, 활성 보관 상태와 전체 예상 문서의 정확한 일치로만 성공을 복구한다. 객체 키 순서는 무시하지만 배열 순서·다른 조치·현장 설명 등은 모두 대조한다. 삭제 중/다른 기기의 추가 수정이면 입력을 유지하고 오류를 안내한다. 자동 쓰기 재시도가 없다.

입력 중 새 점검/상세 이동/새로고침/페이지·검색 전환/보고서 작성을 기존 dirty 보호에 포함한다. 취소도 변경이 있을 때만 폐기 확인을 받는다. 같은 조치의 개선 입력이 미저장 상태라면 담당·기한 폼을 잠그고, 담당·기한 변경 중에는 개선 입력을 잠근다. 변경 저장 후 개선 폼은 새 note를 기준으로 다시 열어 기존 값 때문에 거짓 dirty 또는 재점검 차단이 생기지 않게 한다. 손대지 않은 변경 폼은 후속 저장본의 변경된 기준을 따라간다.

## 데이터·비용 경계

기존 관리자 인증/서버 save·detail만 사용한다. 신규 테이블·schema·RLS·권한·키·환경변수·사진 사본·AI 호출·의존성을 추가하지 않는다. Supabase 변경 로그와 UPDATE 공식 문서를 확인했으며 신규 Supabase 기능으로 이전하거나 TLS/auth 구성을 바꾸지 않는다. 실제 업무 자료 수정 없이 fixture 저장 경로에 실제 문서 검증을 적용해 시험하고 운영의 기존 기록은 읽기 전용으로 대조한다.

## 검증

순수 판정: 원본 불변·ID/상태/범위 유지, 미조치/검토 요청 및 구형 범위, 완료/동시 수정 거절, 입력·날짜 검증, note 한도·다른 조치 보존, 전체 문서/삭제 상태 기반 응답 복구.

브라우저: 정상 변경·새 요청문/CSV/보고서·기존 보고서 불변, 저장 전 실패/재시도, 저장 후 응답 유실, 다른 기기 수정·삭제 중 거절, 취소 확인과 입력 유지, 변경 중 보고서/새로고침 보호, 완료 검토 요청 상태에서 변경 후 재점검 정상 진행·완료 후 수정 버튼 제거. 320/390px 및 가로844px·다크 화면을 확인한다. 실제 휴대폰·현장 정확도와 유료 공급자 호출은 별도다. 최종 검증과 main/Vercel 운영 결과는 PR에 기록한다.
