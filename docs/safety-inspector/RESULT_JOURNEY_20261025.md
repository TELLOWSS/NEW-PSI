# 점검 결과 다음 행동 안내

## 목적

결과를 받은 사용자가 검토 저장·조치 작성·다음 사진·보고서 중 지금 해야 할 일을 알 수 있도록, 현재 저장 상태에서 우선 행동 하나를 계산한다. 결과의 핵심 답변과 전문가 판단 다음에 안내를 표시하고 하단 주 버튼도 같은 행동을 수행한다.

## 안내 우선순위

1. 설명이 바뀌면 현재 입력을 유지하며 설명 확인으로 이동한다.
2. 저장된 분석을 아직 열지 않았다면 원래 결과부터 연다. 다시 분석하지 않는다.
3. 현재 전문가 의견이 저장되지 않았다면 현장 대조 후 검토 저장을 안내한다. 거절 의견이 비었거나 작성한 의견이 5자 미만이면 입력칸으로 이동한다.
4. 작성 중인 조치·개선 입력이 있으면 그 입력으로 돌아간다.
5. 다른 사진의 미검토 분석이 있으면 저장된 우선순위에 따라 다음 사진을 연다. 직접 점검 사진에서도 이동할 수 있지만 그 사진에 AI 검토 기록을 만들지 않는다.
6. 직접 점검 사진에 연결된 조치가 없으면 조치 작성과 검토용 보고서 기록을 선택할 수 있다.
7. 나머지는 검토용 보고서를 우선하고 필요하면 해당 사진에 조치를 추가한다. 미결 조치는 보고서를 만들었다고 완료로 바꾸지 않는다.

## 보존 사항

- 다음 검토 순서는 기존 `pendingReviewQueue`의 저장된 제안 우선순위를 따른다. 접힌 진행 상태에서 순서와 단서를 볼 수 있다.
- 상태 선택기는 읽기 전용이다. 검토·조치·보고서 저장은 기존의 명시적 사용자 작업과 검증 경로를 사용한다.
- 설명 충돌, 저장된 분석 원본 확인, 5자 의견 조건, 미저장 조치 보호, 보고서 검토 조건을 완화하지 않는다.
- 의견 보완 버튼은 기존 입력칸을 열고 포커스하며 작성 내용을 지우지 않는다. 다른 사진으로 이동하면 보완 요청 상태를 초기화한다.
- 하단 다음 촬영 버튼은 현재 AI 검토가 저장되기 전에 실행되지 않는다. 직접 점검 사진에는 AI 검토 저장을 요구하지 않는다.
- 새 AI 요청·자동 승인·조치 완료·청구 설정·DB 스키마 변경은 추가하지 않는다.

## 검증

- `tests/inspectorResultJourney.test.ts`: 설명 변경, 저장된 결과 미열람, 짧은/거절 의견, 수정한 검토, 미저장 조치, 대기 사진, 직접 점검, 사진별 조치 범위, 미결 상태, 사진 부재 등 13개 검사.
- `scripts/verify-inspector-result-journey.mjs`: 분석→명시적 검토 저장→보고서, 짧은 의견 보완·포커스, 전문가 해석 거절 유지, 설명 변경 시 저장·보고서 차단.
- `scripts/verify-inspector-result-queue.mjs`: 직접 점검 사진→우선 검토 사진 및 AI 검토 저장→우선 검토 사진. 직접 점검의 임의 검토 기록·추가 AI 호출 없이 이동.
- 기존 중단 복구 9종도 회귀 검증한다. 각 브라우저 시나리오는 320/390/844/1440 너비와 브라우저 오류를 확인한다.
- 로컬 테스트는 CI와 같은 UTC 환경에서 실행한다. 호스트 시간대에 의존하는 기존 `safetyCase.test.ts`의 날짜 기대값 2개는 다른 호스트 시간대에서 실패하므로 제품 코드를 바꾸지 않고 검증 시간대를 CI에 맞춘다. 사용자 화면의 한국시간 표시는 유지한다.

실제 계정 비밀번호를 사용하지 않고 합성 응답과 사진으로 검증한다. 운영 화면 검증에서도 실제 점검 API·인증 API와 범위 밖 배경 요청을 격리하여 업무 기록을 쓰거나 실제 AI 추론을 호출하지 않는다.

로컬 최종 검증: 153개 파일·1,349개 테스트, 필수 검사·타입·빌드 통과. 새 결과 안내 4종과 다음 검토 이동 2종을 개발·운영 빌드에서 확인했다. 기존 중단 복구 9종의 개발 회귀 검증도 통과했다. 운영 배포와 공개 화면의 합성 검증 결과는 PR에 기록한다.
