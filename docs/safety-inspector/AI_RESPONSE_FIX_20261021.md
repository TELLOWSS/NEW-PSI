# 사진 AI 표준 형식 오류 수정 — 2026-10-21

## 확인한 오류와 코드상의 원인

첨부 `image(20261020-213033).png`에서 최적화(1.80MB→0.42MB) 후 ‘409 - 분석결과가 표준 형식과 다릅니다. 표준 프롬프트로 다시 요청해 주세요.’를 확인했다. 첨부 파일을 찾지 못한 문제는 작업 환경 재연결 후 해결됐으며, 사진 속 오류는 앱의 별도 분석 응답 검증 오류다.

기존 Gemini 요청은 `responseMimeType: application/json`, OpenAI 요청은 `json_object`만 지정했다. JSON 문법을 요청했지만 필수 배열·하위 키·열거형과 추가 키 금지를 공급자에 전달하지 않았다. 모델이 등록번호·해시·처리모드까지 다시 작성해야 했으며 표준 스키마가 조금만 달라도 가져오기가 거절됐다. 실제로 실패했던 공급자 원문은 저장하지 않았으므로 특정 잘못된 필드를 원인으로 단정하지 않는다.

기존 분석 지문은 같은 사진·설명으로 한 번 요청하면 실패해도 재요청을 막았다. 브라우저 모의응답만으로 성공을 확인한 기존 검증 범위로는 이 문제를 충분히 확인하지 못했다.

## 수정한 계약

- Gemini `generationConfig.responseJsonSchema`, OpenAI Responses `text.format: json_schema / strict: true`에 같은 구조화 스키마를 전달한다.
- 모델은 관찰·가설·확인 질문·조치·법령 검색어·한계의 6개 배열만 생성한다. 모든 객체는 추가 키 금지, 필수 키 및 문자열 열거형을 지정한다.
- 점검번호·사진번호·이미지 해시·버전·API 출처는 서버가 검증된 요청과 실제 이미지에 연결한다. 누락 값을 추측하거나 모델이 보낸 잘못된 신원 정보를 덮어써서 수용하지 않는다. 모델 계약에서 해당 필드 자체를 제외한다.
- 기존 수동 ChatGPT 전체 계약과 엄격한 ID·해시 대조는 유지한다. 외부 API의 추가 법적 판단·금액·위조 출처, 잘못된 항목·열거형·배열은 계속 거절한다.
- 항목 수를 짧은 현장 결과에 맞게 제한하고 각 문장을 간결하게 지시한다. 기존 4,096 출력 토큰과 점검당 20회 한도는 올리지 않는다.
- Gemini 완료 사유·분석 거절·빈 응답·thinking 파트, OpenAI 중단·refusal을 구분한다. 미완료 JSON이 우연히 문법상 유효하더라도 정상 분석으로 적용하지 않는다.

## 실패·재시도와 사용자 흐름

공급자 오류는 사용자용 메시지·오류 코드·수동 재시도 가능 여부로 반환한다. 공급자 원문·사진·설명·키를 로그에 남기지 않고 `inspector_ai_failure`와 코드/공급자만 기록한다. API 자체 응답을 다시 표준 프롬프트로 복사하라고 요구하지 않는다.

간편 화면에서 분석에 실패해도 업로드된 사진과 설명을 유지하고, 사진을 AI로 판독한 결과가 아님을 표시한 설명 기반 법령·조치 조회를 먼저 제공한다. 사용자가 같은 사진으로 직접 재분석할 수 있으며 사진을 다시 올리게 하지 않는다.

중복 클릭은 같은 진행 중 요청에 합쳐진다. 서버가 재시도 가능한 실패를 확실히 반환한 뒤 사용자가 다시 누를 때만 새 요청 ID를 사용한다. 네트워크 단절 등 결과를 모르는 경우에는 같은 ID를 유지해 중복 과금 요청을 방지한다. 자동 유료 재시도는 없다. 재실행 사용료 가능성을 오류 안내에 표시한다. 기존 예약·총 20회 제한은 그대로 사용하고 DB schema·권한·API 키 설정은 변경하지 않는다.

배포 전 실패했던 옛 지문과 충돌하지 않도록 응답 계약 버전을 분석 지문에 포함한다. 기존 사진·설명·보고서를 변경하지 않는다.

## 검증 기준

- 실제 실패 유형의 비표준 JSON, 잘못된 열거형·추가 권한 필드·누락·상한 초과 배열을 입력해 거절을 확인한다.
- 두 공급자의 실제 REST 요청 모양과 구조화 스키마, 선택 사진의 설명, 서버 신원 연결, 한 번만 호출되는 오류 경로를 검증한다.
- 토큰 중단·빈 응답·거절·thinking 분리, 수동 재시도 ID 갱신·동시 클릭 합침·불확실한 결과의 ID 보존을 검증한다.
- 간편 화면에서 409 오류 후 설명 기반 대안 표시→같은 사진 수동 재분석→확인·보고서를 검증한다. 기존 상세 작업실 경로도 재확인한다.
- 운영에서는 합성 도식 1장으로 실제 공급자 분석을 한 번 실행하고 응답 저장·서버 ID/해시·법령 포함 보고서 스냅샷을 확인한다. 실제 현장사진·작업자 자료를 시험 입력으로 사용하지 않는다. 임시 시험 기록·사진·보고서는 전체 삭제 절차로 정리하고 기존 승인 시험자료는 변경하지 않는다. 운영 검증 결과는 배포 확인 후 별도로 기록한다.
