# PSI 사진점검 초보자 UX 2차 구현 — 현장 조치 연계
작성 2026-10-25 · 기존 PR #71 다음 단계

## 적용한 실제 흐름

1. **회신 수신자**: 관리자 계정이나 새 앱 없이 요청을 확인한다. '개선사진 제출 / 조치 예정 / 조치 어려움'에 따라 제목·입력 안내·예시·전송 버튼을 다르게 표시하며 필수 입력이 무엇인지 알려준다. 설명 없이 비활성화된 제출 버튼을 남겨두지 않는다. 성공한 회신은 승인이나 전송 확인 이상의 의미로 표시하지 않는다. 기존 share API 계약, 재전송 UUID, 보관 동의, 3회/사진 1장 한도를 유지한다.
2. **안전관리자 재점검**: 미조치 → 개선사진 제출에 따른 검토 요청 → 실제 현장 대조 확인을 별도 단계로 표시한다. 현장 원위치, 개선 고정/통제, 잔여 위험을 직접 살펴보는 안내를 제공하지만 자동 승인/체크 표시/시스템 검증으로 처리하지 않는다. 이전 사진과 개선 사진의 실제 서버 저장·해시·승인 계약은 변경하지 않는다.
3. **보고서**: 전체 보고서 최상단에 읽는 순서와 실제 이미지 로딩 상태를 보여준다. 보고서에 포함될 사진이 모두 무결성 확인·디코딩을 마치기 전 PDF/인쇄 버튼을 비활성화한다. 누락·접근 문제로 일부 사진이 실패한 때는 누락을 명시하고 사용자가 별도 확인한 경우에만 인쇄한다. 기존 보고서 스냅샷/해시·작성 권한은 그대로 유지한다.

## 절대 변경하지 않는 경계
- AI 분석/외부 전송은 사용자의 명시적 동의 및 실행 전까지 발생하지 않는다.
- 사진은 원본 대신 최적화 사본을 다루고 기존 보관/삭제·토큰 만료·접수 기록을 유지한다.
- 외부 수신자의 본인 입력 이름은 신원 확인·개인 전자서명이 아니다.
- 사진 업로드·공유 성공이 개선 완료나 위법 확정을 의미하지 않는다.
- 최종 현장 재점검은 관리자 직접 확인이며 SMART TBM과 NEW-PSI는 별개다.

## 자동 검증 범위
- 단위: 회신 분류별 안내·사진 필수 조건·필수 입력 문구, 재점검 상태 3단계, 출력 시 전체 사진 로딩/실패/성공 판단.
- 기존: 점검 검토·조치 저장·공유/회신 API·보고서 스냅샷·사진 해시·로그인·비용 보호 회귀 테스트.
- 실제 안드로이드 카메라·카카오톡 앱·다국적 근로자 이해도와 실제 현장사진 모델 정확도는 자동화 합성 테스트와 구분하며 별도 실사용 검수 대상으로 남는다.
