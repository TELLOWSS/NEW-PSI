# 수동 위험 선택 유지 및 회귀 검사 보완

기준 후보: `92aa0e0`(PR #118), 선행 출처 엔진 PR #117 위의 변경. 이전 전체 안정성 검증에서 직접 고른 `electric` 기준이 보고서에 유지되지 않는 점과 조치·회신 브라우저 검사의 오래된 전제를 확인했다. 이번 변경은 그 범위만 보완한다.

## 저장과 표시

- 기존 점검 JSON 문서에 선택 필드 `photoRiskTopics?: Record<photoId, topicId>`를 추가했다. 새 DB 테이블·마이그레이션·API·자동 수집은 없다. 현재 점검의 저장된 사진과 기존 법령카드 ID만 허용하며 최대 20개다. AI 분석 JSON으로 이 값을 입력하지 않는다.
- 기존 수동 결과 화면의 기준 선택 컨트롤을 재사용한다. 수동 점검에서는 점검자 진술임을 표시하고, 다음 사진·조치 작성·보고서로 진행할 때 기존 save 요청으로 저장한다. 선택 변경도 기존 이탈·로그아웃 경고 대상으로 다룬다. 중복 버튼은 추가하지 않았다.
- AI 결과를 살펴볼 때의 일회성 법령 비교는 기존 동작을 유지한다. 사진의 AI 분석·점검자 설명·전문가 검토를 선택값으로 덮어쓰거나 삭제하지 않는다.
- 새 보고서 법령 참조는 명시적 점검자 선택을 먼저 연결하고 기존 설명·AI 자료의 독립 근거도 유지한다. 예를 들어 감전을 선택하고 설명에 개구부가 있다면 두 근거를 보존한다. 선택을 AI 판정이나 위반 확정으로 표시하지 않는다. 금액·법령카드 본문도 변경하지 않았다.
- 보고서 사진별 표시와 공유 요약에 ‘점검자 선택 위험 · AI 판정 아님’을 남긴다. 저장된 사진을 다시 열 때 선택값을 복원한다. 미선택 구버전 기록에는 새 필드를 보충하지 않으며 과거 보고서 JSON·해시를 다시 만들지 않는다.

새 단위검사는 잘못된 사진/주제/금액 객체 거부, 선택된 법령의 서버 보고서 반영, 구버전 필드 미주입, AI 분석·검토 보존, 공유 진술 구분 및 동결 스냅샷을 검증한다. 보안·인증·삭제의 기존 검사와 조건은 삭제하지 않았다. 원격 CI에 담당·기한/개선사진/삭제 17개와 회신 5개 흐름을 추가했다.

브라우저 검사 실패 원인도 수정했다. AI 검토 저장 전에 ‘다음 사진’을 누르던 fixture를 현재 순서로 맞췄고, 변경 이유 라벨과 회신 진입 이름을 갱신했다. 예정 회신도 확인 대상으로 포함하므로 회신 기대 건수를 2→3으로 바꿨다. 개선사진 재시도는 전역/국소 경고가 함께 존재하므로 해당 조치의 경고를 확인하고, 실패 후 바뀌는 ‘같은 개선사진·내용으로 다시 시도’ 버튼을 누르도록 했다. 각각 다른 실패의 원인을 확인한 뒤 수정했으며 동일 오류를 반복 실행해 통과를 유도하지 않았다.

합성 증거: `artifacts-selection-*.log`, `artifacts/audit/inspector-mobile-ux/`, `artifacts/audit/inspector-quick/`, `artifacts/audit/inspector-selection-followup/`, `artifacts/audit/inspector-selection-followup-recovery/`, `artifacts/audit/reply-inbox/`. 실현장 사진·근로자·실제 회신 토큰·유료 AI를 사용하지 않았다.

## 남은 운영 경계

실제 Android/iOS, 카카오톡 송수신, 외부 AI 실제 응답, 운영 Supabase RLS·Storage·삭제·복원은 이번 합성 검사로 확인하지 않는다. 기존 fast-uri moderate 1건도 남아 있다.

커밋 이후 원격 GitHub CI와 동일 SHA Preview READY를 대조한다. 운영 main 병합·배포는 기존 게이트를 유지한다. 특히 `utils/releaseGate.ts`는 저장자료에 영향을 주는 변경에 실제 복원 검증 근거를 요구한다. 로컬·PGlite·합성 브라우저 결과로 이를 대체하지 않는다. Vercel 실제 플랜·운영 용도의 적합성과 선행 #117의 통합 역시 별도 확인 사항이다.

이전 기록을 새 서버로 읽는 호환성은 검증했지만, 새 선택 필드를 저장한 기록을 이전 서버로 되돌릴 때는 이전 버전의 엄격한 문서 검증이 거부할 수 있다. 운영 데이터에 Preview로 쓰지 않았으며, 반영 전 전환·복원 시나리오에서 이 경계도 확인해야 한다.
