# NEW-PSI 사진점검: 발견에서 개선 증빙까지

## 판매 아이디어와 고객

건설 현장의 안전담당자·공종 책임자를 위한 **전용 설치형 사진점검 도구**를 첫 상품으로 제안한다. 구매 동기는 사진 판독 자체보다 사진·전문가 의견·요청 조치·담당·기한·개선 전후 사진·현장 재점검을 한 기록으로 연결하는 데 둔다. 사진을 여러 채팅방과 문서로 옮기는 작업을 줄일 수 있는지는 현장 파일럿에서 측정한다. 시간 절감률·사고 감소율·정확도·고객 수를 임의로 광고하지 않는다.

PSI의 기존 수기 위험성평가 OCR·5문항·6지표 정체성을 유지하고, 사진점검은 명확한 제품 진입점을 가진 모듈로 소개한다. 별도 SMART TBM과 점수 자동 승인·전달을 약속하지 않는다.

## 상품 제안

| 범위 | 제안 내용 | 제공 경계 |
|---|---|---|
| 소규모 현장 체험 | 담당자 한 명이 현장 자료로 결과·조치·보고서 흐름 검수 | 예시 체험은 공개, 실제 업무는 기존 관리자 인증 |
| 현장 전용 도입 | 전용 설치, 현장 교육, 보관·삭제·AI 운영 조건 협의 | 설치·지원 계약과 가격은 별도 확정 필요 |
| 여러 현장 확장 | 기업·현장별 권한, 협력사 수락, 전자서명 등 요구 정리 | 현재 제공 기능으로 광고하지 않고 추가 구축 대상으로 명시 |

첫 판매 방식은 설치·교육·초기 운영 지원의 범위와 가격을 협의하는 파일럿 제안이다. 공개 다중 고객 SaaS·자동 결제·계약 접수 시스템으로 취급하지 않는다. 가격 숫자나 가공의 연락처·후기를 만들어 넣지 않는다. 검토안 파일은 사용자가 원하는 상대에게 직접 전달한다.

## 구현한 고객 흐름

1. `/product`: 로그인 없이 제품 가치·실제 가능한 결과를 확인한다. 기존 `/`와 `/?mode=photo-inspector` 진입은 유지한다.
2. 개구부·비계·전선 도해를 선택해 위험·조치, 개선 전후, 보고서 구성 예시를 바꾼다. 실제 판독·저장·조치 완료 기록이 아니며 AI 호출이 없다.
3. 법령·금액·감독사례를 펼치면 업무 화면과 동일한 날짜 고정 법령 자료를 읽는다. 관련 주제 검색이며 AI 사진 분석으로 표시하지 않는다.
4. 소규모 체험·현장 전용·여러 현장 구성을 선택한다. 사진 수·일수·사본 크기 가정으로 사진만의 용량을 계산한다. 무료 한도·청구액·압축 보장으로 표시하지 않는다.
5. 선택한 구성·실제 제공 기능·용량 가정·추가 구축·협의 사항을 포함한 도입 검토안을 Markdown 파일 저장·복사·기기 공유로 전달한다. 상담 접수·결제·계약 성공을 표시하지 않는다.
6. ‘내 사진으로 점검’은 기존 인증을 거쳐 간편 사진점검으로 이동한다. 인증 우회·공개 사진 접근을 추가하지 않는다.

기존 관리자 잠금 화면과 자료가 없는 간편 점검 화면에서도 제품 체험으로 이동할 수 있다. 사진·작성 중인 기록이 있으면 간편 화면의 제품 링크를 숨겨 불필요한 이탈을 줄인다.

## 화면·그래픽

- 종이색 바탕·짙은 녹색·국소적인 연녹색 강조. 큰 메시지와 실제 산출물 미리보기를 첫 화면에 함께 배치한다.
- 제품 본문에는 별도 이미지 다운로드가 없는 자체 SVG 현장 도해. 실사 사진·인식 박스·정확도 점수로 가장하지 않는다.
- 모바일 단일 열, 320px부터 대응, 주요 조작 44px 이상, 16px 선택 입력, 접을 수 있는 법령·용량·질문, 키보드 초점·본문 바로가기·동작 줄이기 지원.
- 제품 체험은 밝은 고정 팔레트를 사용해 기기 다크 설정에서도 대비를 유지한다. 업무 화면의 기존 다크 모드는 유지한다.

## 성능 구현

- `index.tsx`에서 업무 App과 Provider를 별도 동적 진입 모듈로 분리한다. 제품 체험에서 차트·Supabase/AI SDK·업무 서비스·인증 요청을 시작하지 않는다.
- 제품 페이지에서는 기존 다국어 웹폰트를 요청하지 않고 기기 글꼴을 사용한다. 다른 업무 경로에서는 기존 글꼴을 유지한다.
- 법령 상세·사례·업무 화면 CSS는 사용자가 해당 영역을 펼쳤을 때 불러온다. 제품 초기 화면은 로컬 SVG·React·자체 CSS로 구성한다.
- 사진점검 상세 작업실과 간편 보고서를 필요 시 불러오도록 분리한다. 실제 기능을 제거하거나 보관 자료를 변경하지 않는다.
- 추가 SDK·분석 추적기·광고·신규 환경변수·DB schema 변경 없음.
- 초기 JavaScript 브라우저 요청 합계 350,000바이트, 같은 파일의 gzip 추정 합계 125,000바이트 이하를 회귀 예산으로 둔다. 이는 서버 실전송 압축률·실기기 응답시간·업무 처리량 보장이 아니다.

공유 크롤러용 `/product/index.html`은 제품 제목·설명·canonical·Open Graph를 정적으로 포함한다. 공유 미리보기 PNG는 실제 제품 화면을 렌더한 자체 도해 캡처(1200×630)이며 본문 초기 화면에서는 요청하지 않는다. 실제 카카오톡 수신·캐시 갱신은 실기기 검수와 구분한다.

## 파일럿에서 측정할 항목

- 처음 사용하는 전문가가 도움 없이 첫 사진 결과와 보고서까지 도달하는지.
- 입력·수정·재점검·전달에 든 실제 시간, 중복 입력 횟수, 중간 이탈 원인.
- 사진별 인식 오류와 전문가 수정·거절 이유. 법령 적용 조건 누락 여부.
- 실제 사진 크기·AI 호출 수·실패율·Storage·DB·전송량, 삭제 후 잔여량.
- Android/iOS 촬영·붙여넣기·카카오톡 등 실제 송수신·다운로드.
- 설치·교육·지원의 투입 시간과 구매자의 지불 의사. 측정 전 숫자로 판매 효과를 약속하지 않는다.

## 검증 방법

`scripts/verify-inspector-product.mjs`는 production 번들·CSP에서 네 화면 폭, 장면/전후/보고서 전환, 법령/사례, 구성/용량, 검토안 복사와 다운로드 내용 일치, 사용자 활성화가 유지된 공유 호출 fixture, 공유 미지원, 인증 경계, 초기 JS 예산을 확인한다. 공개 체험의 API 호출·업무자료 변경·유료 AI 요청은 0건이어야 한다. 기존 간편·상세 관리 회귀와 전체 CI를 추가 확인한다. 운영 반영 커밋·실측 결과는 연결 PR에 기록한다.

자동 결제, 다중 고객 권한 격리, 실시간 법령 개정 동기화, 법적 최종 판정, 실제 카카오톡 수신, 성과 수치·무제한 무료 보장을 이 릴리스의 완료 항목으로 주장하지 않는다.

## 로컬 실측

변경 전 공통 초기 진입(당시 `/product`도 기본 관리자 진입으로 처리) JavaScript 요청 합계 1,878,318바이트, 개별 gzip 추정 합계 517,382바이트. 새 제품 체험의 동일 브라우저·로컬 production 번들 측정은 226,498바이트, gzip 추정 72,512바이트다. 원문 바이트 약 87.9% 감소이며, 동일 기능 화면의 응답시간·모바일 실기기 처리량 비교가 아니다. 업무 App과 차트·데이터 서비스 초기 요청 제외에 따른 제품 진입 최적화다.
