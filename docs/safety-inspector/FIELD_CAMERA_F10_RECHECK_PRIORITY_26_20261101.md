# NEW-PSI 26차 · F10 기한별 재점검 대장 및 상태 불일치 표시 (2026-11-01)

## 사용자 업무와 개발 경계
건설현장에서는 위험을 확인한 당일에 모든 보수·교체·설치가 끝나지 않는다. 자재 미입고, 장비 투입, 공정 협의 등으로 일정이 바뀌며 **임시 안전조치의 기록, 담당·기한, 재점검 결과와 다음 확인일**을 구분해야 한다. 기존 F10(25차 main 기준)은 점검 전체·조치별 재점검 기록, 기기 시각, 사진 SHA-256 스냅샷 및 v17 백업/복원을 보유한다. 그러나 여러 기록을 대상으로 재점검 예정일·상태 불일치를 한눈에 확인하는 뷰는 없었다.

이번 작업은 F10의 기존 저장 스키마·동기화 경계를 변경하지 않는다. 새로운 GPS, QR, 네이티브 앱, 유료 AI, 백엔드 알림, 승인 시스템을 도입하지 않는다.

## 구현
- `lib/inspector/localRecheckQueue.mjs`: 기존 브라우저 점검 기록을 **읽기 전용**으로 한 개의 조치 대상당 하나의 우선순위 항목으로 집계.
- 최신 재점검 이력의 `nextCheckDate`가 있으면 그것을 기준으로 판단한다. 최신 이력이 없을 때만 기존 후속조치 `dueDate`를 사용한다. 재점검에서 다음 확인일을 명시적으로 미정 처리했다면 구 기한을 되살려 확정된 일정인 것처럼 표시하지 않는다.
- 일자 비교는 접속 기기의 **로컬 달력일** 기준. 기한 초과·오늘 확인·3일 이내·이후 예정·일정 미정·확인 완료 기록의 6종과, 최신 `delayed/temporary_checked/needs_more` 이력에 `verified`가 함께 존재하는 **상태 불일치**를 최우선으로 분리한다.
- 한 점검에 전체 조치와 20개 개별 조치가 있으면 대상은 별도로 계산한다. 집계 숫자는 **대상 수**이지 사진 수나 점검 기록 수가 아니다.
- 기존 기기 직접 점검 화면에 7종 상태 버튼, 우선순위 상세 목록, 원본 점검 목록과 연결된 필터, 수동 새로고침 추가.
- 책임자·임시조치 기록 유무를 명시한다. 기록이 없으면 '미기록'일 뿐 실제 조치 미실시 여부를 확정하지 않는다. 조치 완료 기록을 자동 변경하거나 작업 재개를 승인하지 않는다.
- 급박한 현장 위험은 정해진 기한과 관계없이 접근통제·작업중지 필요성을 우선 검토하도록 안내.

## 검증
- Vitest: 오늘·연말·기한초과·3일·이후예정·미정, 구 이력과 최신 이력 구별, 완료 상태/미완료 최신 재점검 충돌, 조치별 독립 집계, 구형 레코드 누락, 입력 무변형을 검증.
- 기존 `scripts/verify-inspector-local-offline.mjs` 실제 Chromium 오프라인 시뮬레이션을 확장: 기존 조치 상태와 재점검 결과를 실제로 저장 → '이후 예정 1 / 상태 불일치 1' 표시 → 필터 작동 → v17 JSON 백업·복원 후 현황 보존.
- 기존 단말 크기별 Inspector QA와 전제품 브라우저 QA는 별도 GitHub Actions로 실행.
- 합성 사진/점검만 사용. 실제 근로자 자료·현장 사진·과금 AI·서버 통보 없음. 자동 Chromium 테스트는 실제 갤럭시·삼성 인터넷, 장갑·햇빛·저사양 환경 실증을 대체하지 않는다.
