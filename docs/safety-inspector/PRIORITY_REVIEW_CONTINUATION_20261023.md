# 실제 사진점검: 위험 단서 우선 연속 검토

대상은 관리자 인증 뒤 사용하는 실제 `InspectorQuickWorkspace`이며 공개 샘플이 아니다. 여러 장의 저장 사진을 점검할 때 현재 사진을 닫고 목록에서 다음 대상을 찾는 왕복을 줄인다.

## 동작

저장된 AI 분석이 있고 전문가 검토 기록이 없는 사진만 대기열에 넣는다. 최신 형식은 사진별 구체적 위험 단서 중 가장 높은 우선순위(우선 통제→빠른 개선→일상 관리) 순, 동률은 원래 사진 번호 순이다. 명시적으로 단서가 비어 있으면 일반 조치 문구로 위험을 만들어내지 않는다. 단서 필드가 없는 이전 분석만 기존 조치 우선순위를 사용한다. AI 미실행 사진·AI 없는 개선 증빙·이미 검토한 사진·분리된 분석 키는 제외한다. AI 미수용 기록을 AI 위험 신호로 재사용하지 않는다. 순서는 검토 안내이며 안전·위법·완료 판정이 아니다.

현재 사진 결과에 다음 사진 번호·대표 단서·우선순위를 보여주고 전체 남은 순서는 접어 둔다. `검토 저장 · 다음 대기`는 현재 사진의 명시 검토만 기존 confirm-photo API로 저장한다. 일반 문서 저장·분석 재실행·업로드·보고서 생성·조치 상태 변경을 하지 않는다. 기존 lost-response 검토 읽기 복구를 사용한다. 저장 실패/미수용 의견 5자 미만이면 이동하지 않는다. 변경한 사진 설명이나 작성 중인 조치가 있으면 비활성화한다.

저장 성공 후 같은 점검의 다음 사진을 서명 URL로 읽고 등록 SHA-256과 대조한 다음에만 사진·분석·검토 상태를 함께 바꾼다. 읽기/무결성 오류면 저장된 현재 검토와 화면을 유지한다. 다음 사진은 검토 전으로 열린다. 이미지 object URL은 기존 effect로 정리한다. 탭 이어보기에는 점검/사진 UUID만 기록하며 이미지·분석·의견 사본을 남기지 않는다. 다음 사진 읽기 실패 시 현재 사진 위치를 보존한다. 위치 저장이 안 되면 안내한다.

모은 사진의 다음 할 일, 기록에서 검토 재개, 인계 화면의 남은 사진, 하단 고정 버튼도 동일 대기열을 사용한다. 원래 사진 번호와 보고서 순서·고정 보고서는 바꾸지 않는다. 즉시 다음 촬영·현재 사진 검토만 저장·보고서 작성 기능도 유지한다. 모바일 320/390/가로 844/데스크톱 1440 폭과 긴 문구 줄바꿈, 44px 버튼을 검증한다.

## 검증과 범위

순수 대기열 테스트: 우선순위/동률/불변성, 현재·기검토·미실행·분리 분석 제외, 명시 빈 단서와 이전 형식 구분, 최고 단서 선택. 실제 본기능 컴포넌트를 합성 API 응답과 연결한 브라우저 검증: 연속 두 장 이동, AI 미수용 저장, 짧은 의견 거부, 저장 실패, 저장 후 응답 유실 읽기 복구, 다음 사진 무결성 실패, 설명 변경 비활성화. 새 사진의 실제 픽셀과 분석 교체, 대기 수, 위치 UUID, 기존 조치·분석·보고서 불변성을 확인한다. 실제 고객 사진·기존 점검을 변경하지 않으며 유료 AI 호출은 하지 않는다. 전체 CI/운영 배포 증거는 PR에 기록한다. 실기기/실서비스 쓰기 검증과 합성 통합 검증은 구분한다.
