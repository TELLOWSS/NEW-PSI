# NEW-PSI 25차 — F06 현장 카메라 공유·ZIP 저장 직전 SHA-256 검증 (2026-11-01)

## 기획 기준
'docs/safety-inspector/FIELD_CAMERA_PLAN_PROGRESS.md' F06은 원본/사본 해시·출처를 다루는 **부분 구현** 상태. 기존 페이지 '/camera'는 '보관 파일 다시 확인' 클릭 시 해시를 대조했으나, 수동 확인을 하지 않고 곧바로 공유 또는 ZIP을 준비할 수 있었다. 사진 화면이 이미 보유한 메모리 사본과 IndexedDB의 최근 저장 값이 서로 달라진 상황을 사전에 탐지하지 못한다는 위험을 개선한다.

## 구현
1. 기존 사진함과 server-side Inspector / OCR / SMART TBM을 변경하지 않고 'lib/inspector/fieldPhotoDelivery.ts' 단일 전달 전 검사 로직 추가.
2. 실제 IndexedDB에서 선택된 ID의 파일·기록을 **다시 읽는다**. 메모리의 목록과 ID, 이름, MIME, 저장 시각, 바이트 수, 기록 SHA-256을 대조한다.
3. 새로 읽은 실제 사진 Blob에서 SHA-256을 계산해 '보관 당시 기록된 SHA-256'과 대조한다. 기록이 없는 사진, 파일이 사라진 사진, 내용/메타정보가 변경된 사진은 공유·ZIP 생성이 차단된다. 해시 계산이나 IndexedDB 읽기에 실패해도 전달하지 않는다.
4. 단건 OS 공유, 여러 장 공유, 다중 사진 ZIP 생성 3개 작업에 같은 게이트를 적용한다. 하나라도 실패하면 전달물을 만들지 않으며, 해당 항목을 불일치 목록에 표시한다.
5. 검증·공유 중 다른 선택/삭제/중복 버튼 조작을 제한한다. ZIP 생성 뒤 선택한 사진이 바뀌면 ZIP을 표시하지 않는다.
6. 기존 '보관 파일 다시 확인'은 유지해 사용자 재검증과 미리보기 보존이 가능하다. SHA 누락 사진은 사용자가 따로 로컬에 내려받을 수 있으나, 새 저장/촬영 후 기록되는 SHA 없이 공유가 안전하다고 주장하지 않는다.
7. 외부 API, GPS, 네이티브 신규 앱, 유료 AI 호출·업로드·개인정보 전송·기존 IndexedDB 스키마 변경 없음.

## 시뮬레이션 및 회귀
- 신규 Vitest: 저장본 일치, 조용한 Blob 변조, 기록 해시/시각 변경, SHA 누락, IndexedDB 삭제, 저장소 접근 거절, SHA 계산 거절, 중복/미목록 선택 차단.
- 신규 Playwright: 390x844 / 1280x800 실제 브라우저에서 합성 1px 사진 저장 → 정상 OS 공유 mock → ZIP 다운로드·실제 ZIP 해제 및 SHA 확인 → IndexedDB 저장본 무단 변경(사용자 확인 버튼 누르지 않음) → 공유 중단·기존 ZIP 링크 무효화·새 ZIP 차단.
- 기존 사진함 연속 촬영, 저장 오류/재시도, 10장 보관, 공유, ZIP, 복원, 삭제, 오프라인 경로 관련 기존 QA를 훼손하지 않는다.
- 테스트에 근로자 실사진/개인정보, 유료 AI 모델 호출은 넣지 않는다.
