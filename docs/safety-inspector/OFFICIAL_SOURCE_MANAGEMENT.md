# PSI Inspector 공식 안전정보 관리

확인일: 2026-10-27. 대상: TELLOWSS/NEW-PSI의 기존 정적 법령·사례·동향. 다른 제품과 데이터를 공유하지 않는다.

## 반영 구조와 책임

- 기존 `lib/inspector/legal.ts`, `inspectionCases.ts`, `safetyTrends.ts`의 카드 ID·본문·금액·조회 함수를 유지한다. 기존 사례·동향을 새로 개발하거나 새 출처로 집계하지 않는다.
- `data/inspector/sourceReviews.json`은 25개 기존 항목의 출처 검토 이력을 관리한다. `legal:카드ID`, `case:사례ID`, `trend:동향ID`에 순번대로 검토 이력을 추가한다. 과거 이력을 덮어쓰거나 삭제하지 않는다.
- 원문 확인일(checkedAt), 내용 검토일(reviewedAt), 공개일(publishedAt), 재검토 기한(reviewDueAt)을 별도로 기록한다. 미확인은 null로 유지한다. 과거 파일의 전역 검토일을 원문 확인일·공개일로 복사하지 않는다.
- 초기에는 실제 공식 HTML 본문을 다시 열어 대조한 `case:moel-18869`, `trend:moel-20117` 두 건만 대조 기록을 기재했다. moel-18869는 원문의 부과 표현과 기존 카드의 예정 표현이 달라 pending으로 남겼고, moel-20117은 reviewed로 기록했다. 검토자는 실제 수행 주체인 Codex로 기록했으며 사람의 관리자 승인이나 법률 판단을 대신하지 않는다. 나머지는 기존 검토자료의 이관 상태(legacy)다.
- 자료 내용 해시는 카드/사례/동향 전체(검토 메타데이터 제외)에 연결된다. 본문·원문 URL·금액 등 내용이 달라지면 이전 검토를 그대로 사용할 수 없고 새 검토 이력이 필요하다. 금액 필드는 검토파일로 수정할 수 없다.
- 코어: 구조·호환성, 세이프: 원문·위험 연결·시행본, 키퍼: 관리자 경계·저장량, 프루프: 별도 CI·브라우저 검증 책임. 명칭은 검토 책임을 구분하며 실제 별도 에이전트를 실행했다고 의미하지 않는다.

## 관리자 통제 갱신 순서

실제 갱신 권한은 기존 관리자 화면의 미리보기와 별도로 **Git 저장소 쓰기 권한·PR 검토·릴리즈 게이트**로 통제한다. 웹 업로드가 운영 데이터나 DB를 직접 변경하지 않는다.

1. Inspector의 **저장 기록·상세 관리 → 관리자·공식 안전정보 검토·갱신**에서 현재 검토파일을 내보낸다. 또는 다음 명령으로 내보낸다.

   ```sh
   npm run sources:manage -- export artifacts/source-review-candidate.json
   ```

2. 공식 원문을 열어 확인한 뒤 파일의 version을 올리고 대상 record의 revisions에 새 이력을 추가한다. revision은 이전 값+1, contentSha256은 검토한 실제 자료 내용 해시다. 기존 이력은 그대로 유지한다. 원문을 열지 못했으면 pending을 사용하고 reviewed로 바꾸지 않는다. 검토자·원문 확인일·검토일·근거 위치·재검토 기한을 실제 사실대로 기록한다. 날짜는 YYYY-MM-DD, 기한 기본 권고는 90일 이내다.

3. 자료 본문 자체를 변경했다면 정적 자료 파일을 먼저 수정하고, 아래 digests 명령의 해당 값으로 새 이력을 작성한다. 원문과 변경 내용을 사람이 대조해야 하며 해시만 맞는다고 사실이 검증되는 것은 아니다. 새로운 카드·사례·동향을 추가할 때도 해당 자료 키의 최초 검토 이력을 등록한다.

   ```sh
   npm run sources:manage -- digests
   npm run sources:manage -- preview artifacts/source-review-candidate.json
   npm run sources:manage -- apply artifacts/source-review-candidate.json
   npm run check:inspector-sources
   npm run verify:ci
   ```

   preview는 읽기 전용, apply는 **로컬 저장소 검토파일만** 변경한다. 웹 미리보기는 실행 중인 자료 내용에 대한 검사이므로 본문이 바뀐 새 코드의 후보는 저장소 CLI에서 검사한다. 내보내기는 기존 파일 덮어쓰기를 거부한다. 후보는 최대 192KiB, 자료 100개, 항목당 검토 이력 30개로 제한한다. 한도 확장은 별도 검토한다.

4. 작은 PR로 제출하고 안전·보안 검토, 필수 CI 및 합성 브라우저 검사와 preview SHA를 대조한다. 승인 없는 main 병합·배포 게이트 우회는 하지 않는다. 운영에서는 기존 `build:verified`와 운영 설정 게이트를 유지한다. 중단 시 이전 승인 커밋으로 복구하며 과거 보고서는 다시 작성하지 않는다.

## 상태와 법령 시행본

- legacy 또는 메타데이터 없는 과거 보고서: **기존 자료·검토 이력 보완 필요**.
- pending 또는 확인일·검토자·근거·기한 누락: **원문·검토 확인 필요**.
- reviewed: **원문 대조 기록 있음·현장 적용 별도 확인**. 이 상태도 법 위반·행정처분·안전 상태의 확정이 아니다.
- reviewed이지만 기한 경과: **검토 기한 경과·원문 재확인 필요**.
- withdrawn: **사용 중단**. 새 조회의 근거에서는 제외한다. 과거 보고서에 저장된 원문은 삭제하거나 재작성하지 않는다.

법령은 각 검토 이력의 legalEditions에 버전, 공포일, 시행 시작·종료일, 원문, 확인 메모를 기록할 수 있다. 사건일에 해당하는 단일 시행본은 **후보**로만 표시한다. 시행일 미확인·범위 밖·중복 버전이면 사건 당시 시행본 확인 필요로 표시한다. 날짜로 과거 금액을 자동 계산하거나 조문을 자동 교체하지 않는다. 초기 데이터에서 확인되지 않은 개정 이력은 비워 둔다.

기존 법정상한은 변경하지 않았다. 법정상한, 행위 주체·의무 위반 요건, 사건 당시 시행본, 반복 위반별 부과기준, 실제 판결·처분액은 서로 구분한다. 사진별 합산이나 자동 확정을 하지 않는다.

## 위험 검색과 확인 필요

수록 카드의 키워드 분류와 특정 단서 우선 연결을 재사용한다. 바닥·슬래브·작업발판의 끝단은 개구부·단부 후보로 찾되 철근·전선 등 부재 끝단과 구분한다. 크레인·굴착기·지게차·철근의 전도라는 단어 하나로 통로 정리정돈 조문을 대체 연결하지 않는다. 별도의 통로·적치 상황이 진술됐을 때만 해당 후보가 추가될 수 있다.

없는 카드 ID나 수록되지 않은 위험에는 근거를 생성하지 않는다. 신규 참조에 unmatchedTopicIds를 남기고 카드가 전혀 없으면 전체 감독 방침도 대체 근거로 붙이지 않는다. 사례가 없다는 이유로 다른 업종·위험의 사례를 보여주지 않는다. 제조업 사례의 기존 업종 구분을 유지한다.

## 보고서·공유 호환성 및 비용

검토 메타데이터는 카드·사례·동향의 선택 필드 sourceReview와 참조의 catalogVersion으로 확장한다. 새 보고서에는 **현재 이력 1개**만 복사하고 전체 이력을 중복 저장하지 않는다. 서버의 기존 스냅샷 해시 계산과 사진 해시·최적화·보관·삭제, 점검 document·조치·공유 토큰 스키마는 변경하지 않는다. 과거 보고서 read-report 응답에는 현재 메타데이터를 보충하지 않으며 기존 JSON·해시·자료 버전을 그대로 반환한다. 공유 문구에도 현재 스냅샷의 검토 상태와 시행본 확인 필요를 포함한다.

신규 DB 테이블·버킷·행·cron·Edge Function·유료 AI·원문 수집 API·조회별 출처 fetch는 없다. 자료 조회·관리자 JSON 검사 모두 로컬 처리다. 기존 보고서 1행의 JSONB에는 필요한 현재 검토 메타데이터만 추가되므로 보고서별 바이트 증가는 발생한다. 저장소 검사/테스트 및 gzip 번들 증가는 검증 결과에 수치로 남긴다. 원본 PDF·이미지는 제품에 포함하지 않는다.

2026-10-27 확인한 [Supabase 무료 요금표](https://supabase.com/pricing)는 DB 500MB, 파일 1GB, egress 5GB(캐시 egress 별도 5GB), API 요청 무제한 표기이나 다른 리소스 제한과 비활동 정지가 적용된다. 실제 운영 사용량과 여유량은 별도 확인 대상이다. Supabase changelog도 확인했으며 이번 변경은 SDK·DB·인증·GraphQL을 수정하지 않는다.

[Vercel Hobby 조건](https://vercel.com/docs/plans/hobby)은 개인·비상업용만 허용한다. 무료 여부만으로 현장 상업 운영 적합성을 승인하지 않는다. 실제 계정의 플랜·용도 확인이 필요하고, 이 작업에서 요금제 변경이나 유료 가입을 실행하지 않는다. 신규 런타임 함수 호출은 없으나 기존 CI/preview 빌드와 정적 전송량은 소비된다. 재배포를 반복하여 한도를 낭비하지 않는다.

## 자동 수집·공식 API는 다음 단계

이번 단계는 검토자가 원문을 확인하고 통제된 파일·PR로 갱신하는 구조다. 자동 갱신은 다음 사항을 확인한 후 별도 제안한다.

| 대상 | 먼저 확인할 사항 | 운영 조건·제약 |
|---|---|---|
| 국가법령정보 공동활용 API | 이용신청·인증, 시행일/연혁 조회 필드, 재배포·캐시 조건 | 호출량·재시도 상한, 사건일별 버전 대조, 공포/시행일 분리 |
| 고용노동부 공개자료 | 공식 API 제공 여부, 다운로드·이용조건, 익명화 범위 | API 미확인 상태에서 크롤러를 확정하지 않음. 첨부 형식·정정·삭제 감시 |
| 공단 예방자료 | 개별 자료의 공공누리·도판 저작권·상업용/변경 제한 | 링크만 제공할지 원문을 저장할지 별도 결정. 대용량 PDF 미러링 금지 |
| 실행·비용 | Vercel/Supabase 실제 플랜·할당량, 스케줄러 실행 제한, 외부 API 비용 | 고정 최대 건수·호출수·바이트·시간, 수동 중단, 검토 대기 격리. 관리자 승인 전 운영 반영 금지 |

자동 수집 결과가 기존 법령카드의 금액이나 사건 적용 결론을 덮어쓰는 경로는 두지 않는다.
