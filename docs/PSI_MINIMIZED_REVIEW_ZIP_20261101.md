# NEW-PSI 14차 — 선택 파일만 담은 내부 검토용 ZIP

## 목표
11차에서 검증된 ZIP 내부 파일을 체크만 하던 기능을 확장해, **선택한 원본 파일만 담은 별도 검토용 ZIP**을 생성한다. 원본 ZIP을 변경하지 않으며 외부 전송은 하지 않는다.

## 실제 처리
1. 관리자 OCR 상세에서 원본 증빙 ZIP을 고르고 별도로 기록한 전체 ZIP SHA-256과 대조한다.
2. ZIP의 해시·문항 소속 기록 ID가 해당 근로자 기록과 일치해야만 파일 목록을 연다.
3. 필요한 파일을 선택하고 **개인정보가 포함될 수 있으며 별도 마스킹·승인이 필요하다**는 체크박스를 확인한다.
4. 버튼을 누르면 이전에 확인한 ZIP을 **생성 직전 다시 검증**한다. SHA, 근로자 기록 ID가 다르면 실패한다.
5. 선택된 파일을 원본과 byte-for-byte 비교해 `selected/<path>`에 담는다. 선택되지 않은 파일, 원본 ZIP의 `record/snapshot.json` 및 `record/timeline.txt`는 **선택하지 않았을 때만** 제외한다.
6. 별도 ZIP은 `REVIEW_MANIFEST.json`, `SHA256SUMS.txt` 및 **선택된 파일의 원본 바이트만** 포함한다. ZIP 전체 SHA-256을 표시해 별도 보관할 수 있게 한다.
7. UI는 결과를 `INTERNAL_REVIEW_SUBSET`으로 표시한다. 전송·결재·실제 제출은 발생하지 않는다.

## 이 기능으로 하지 않는 일
- 선택한 PDF·사진·JSON의 이름, 전화번호, 얼굴, 위치, 기타 민감정보를 자동 마스킹하지 않는다.
- 파일 내용의 개인정보 유무를 AI가 검사하고 안전하다고 인증하지 않는다.
- 선택된 모든 원본 이미지나 JSON도 **개인정보가 남아 있을 수 있다**.
- 12차/13차의 독립 승인·현장별 권한 staging SQL과 이 ZIP 기능은 **운영상 연동되지 않았다**. 검토용 ZIP이 생겼다고 반출 승인이나 서버 기록이 생기지 않는다.
- 새 ZIP의 해시가 기존 ZIP의 최초 수신시각, 원본 진정성, 법적 증거능력을 보증하지 않는다.
- 원본 파일은 그대로 보존해야 한다. 새 ZIP은 검토 편의를 위한 **별도 사본**이다.

## 검증 기준
- 선택한 1개만 새 ZIP에 있는지, 미선택 JSON·타임라인이 제외되는지 검사
- 선택 파일 바이트·SHA-256이 원본 매니페스트와 같은지 확인
- 다른 근로자 기록 ID, 외부 보관 SHA 미대조, 조작된 원본 ZIP, 중복/존재하지 않는 경로 실패
- 기존 기능 전체 테스트·타입 검사·빌드·전사 제품 브라우저 검증 통과
- 배포 SHA와 실기기 재조회는 **별도** 검사
